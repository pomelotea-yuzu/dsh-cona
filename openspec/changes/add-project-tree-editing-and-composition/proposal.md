# R2 项目树编辑与流程拼接

本 change 属于 R2 的第二个产品切片，2026-11-20 编写。DSH 与 QoderCN 于 2026-11-20 完成第三轮复核并确认放行。产品验证项均为 `untested`。 [审阅处理](review-response.md)

## Why

R1 的小树编辑器支持新增节点和编辑节点内容。R2 首切片把它接到窗口顶部的项目概览。用户建立了开发流程以后，需要能调整阶段的归属与展示顺序，并在现有规划中插入可复用的流程块，保留已积累的聊天和成果。 [首切片后续范围](../archive/2026-11-20-add-project-overview-and-resume/proposal.md#what-changes) · [产品需求](../../../docs/product/2026-11-11-project-management-design.md#动态项目树)

## What Changes

- 用户从项目概览进入所选实例的树编辑器，可在同级重排节点（含根级），也能将整棵子树移动到另一个父节点下的指定位置。拖放和可用键盘操作的菜单共用位置选择、预览和确认保存。
- 移动保留节点身份、目标、状态、依赖、聊天关联和成果。完整预览显示新位置，保存通过现有规划提交服务校验基线。并发修改、无效位置、发布结果未知和回执确认后回读未同步分别提示。
- 提供一个适用于代码开发的内置流程预设。用户预览其层级、目标、完成条件和内部依赖，确认后一次性插入所选父节点下的同级位置。每次新插入生成自己的节点 ID，新节点从待办开始，可继续用树编辑器调整。
- 复用 R2 的实例隔离、R1 的 owner 与 WorkRun 准入、持久意图及回执、完整快照和中英 UI。移动和插入由 owner 发起，现有 Agent 工具沿用原有动作、目标和基线准入。owner 实际改变规划后，正在运行的工作继续执行；需要后续规划写入时，在旧运行结束后显式发起工作。

## Capabilities

### New Capabilities

- `project-tree-editing` 覆盖本机已登记实例的树重排、子树移动、内置流程实例化及其提交与回读。

### Modified Capabilities

本切片以新增能力描述树结构操作，沿用现有树入口、数据格式、提交及宿主准入规范。

## Impact

- 领域和应用层增加结构变换与预设展开，Host 提供随包的预设并走现有 owner 提交入口，Client 扩展 `ProjectPanel` 与 `PanelController`。项目 JSON 继续使用 v1 的 `parentId`、`order`、节点及依赖字段，发布结果可由现有读者读取。结构操作与既有节点编辑共用保存判据，回执确认后须有同源有效回读才显示普通已保存。 [技术设计](design.md)
- 产品完成条件是在固定 DSH `0.2.2-rc.2` 中，从顶部项目入口打开树，完成重排、跨父级移动与一次流程插入，随后重连和重启回读；同时核对旧 ID 和关联、活动 WorkRun 边界、冲突保留、插入重试及中英显示。 [验证矩阵](validation-matrix.md)

## 后续范围

Agent 发起的移动和插入留待后续，届时定义涉及原位置、目标位置和新节点的授权。本切片保留 Agent 已有的新增、拆分及状态等工具。多选分组、合并、复制、用户模板存取和规划撤销／重做留在后续提案中细化。文件骨架、从已有项目提炼模板及参数化沿 R5 路线推进。Git 双副本协作与资料位置迁移、目标／时间路线图仍属于 R2 后续范围。 [开发路线图](../../../docs/engineering/2026-11-12-plugin-development-roadmap.md#r2项目树协作与工作接续)

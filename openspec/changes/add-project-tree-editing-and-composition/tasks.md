# R2 项目树编辑与流程拼接实施任务

按 1 → 2 → 3 → 4 执行。依赖已归档的 R1 提交及同步协议、R2 首切片的多实例项目概览。A 为自动测试，F 为真实文件后端，H 为固定 DSH 宿主。每项任务勾选时附上交付及所列层级的证据。矩阵分句按各自要求核对，记录实际命令、版本、前置条件和结果。 [验证矩阵](validation-matrix.md)

## 1. 领域变换与预设

- [x] 1.1 实现以父节点和同级锚点定位的移动变换。用自动测试检查多根夹具的根组及普通子节点组前移、后移、原位和非根跨父级移动，比较受影响的两个同级列表、后代关系、节点 ID、依赖和已有记录。覆盖根组成员变化、后代、缺失节点和错误锚点的拒绝。校正 `domain/validate.ts` 文件头和结构校验前两处根规则注释。对应 T01、T04、T05（A）。
- [x] 1.2 提供版本化的中英「功能开发」预设与描述校验。自动测试覆盖有效预设、重复键、无效父级、父子环、缺失依赖端点、依赖环与两个语言版本的结构一致性。对应 T06、T07、T14（A）。
- [x] 1.3 实现以应用层提供的 ID 实例化模板的变换。自动测试覆盖在指定锚点前插入、向空父节点追加、两批独立 ID、内部依赖映射与 `todo` 初始状态，并用 v1 校验核对候选。对应 T06、T07（A）。

> 1.1–1.3 于 2026-11-22 完成，A 层自动测试证据见 [1.x 实施记录](implementation/2026-11-22-1.x-domain-transforms.md)。验证矩阵中 T01、T04–T07、T14 的 F／H 分句仍保持 `untested`，待后续任务与宿主实测。

## 2. 提交服务与授权

- [x] 2.1 为现有服务接入预设读取、移动和插入。对 `conaOverview` 与原 `conaProject` 树入口验证预设读取与写入的 owner、实例和项目身份核对。对 `treePresets` 验证实例可读性，核对载荷、可用语言、版本精确匹配和未知版本拒绝。自动测试覆盖同项目 ID 的不同实例、无效请求、Agent 上下文直达结构命令，以及原工具准入。对应 T07、T08（A）。
- [x] 2.2 通过真实文件后端验证结构变换的发布与基线校验。核对每次有效变更只推进一次规划修订、原位操作保留原头、非法输入保留文件与修订。覆盖并发规划更新、外部内容指纹变化、源代际变化，以及既有 v1 校验器回读。对应 T01、T04–T07、T09（A／F）。
- [x] 2.3 接入模板生成 ID 的持久意图、回执查询和恢复。用真实文件后端模拟回执丢失、同号换参数、候选持久化后中断、发布结果未知，以及升级后原预设版本不可用。核对重试只生成一批 ID、重启后可回读已提交结果，以及待核对、隔离等状态。对应 T10、T11（A／F）。
- [x] 2.4 在活动 WorkRun 上验证 owner 变更的影响。用自动测试核对原位操作、规划变化后运行继续、旧基线写冲突、以新快照基线写入被绑定拒绝、目标范围保留，以及旧运行结束后由新 WorkRun 按现有准入重新绑定。对应 T08、T12（A）。

> 2.1–2.4 于 2026-11-22 完成，A／F 层证据见 [2.x 实施记录](implementation/2026-11-22-2.x-service-authorization.md)。说明：2.3 的「候选持久化后中断／发布结果未知／待核对／隔离」由既有 `recovery.test.ts`、`quarantine.test.ts` 的通用故障注入覆盖（机制与应用层共用，结构命令复用同一意图／恢复路径），本轮未针对模板 ID 另写重复用例；2.4 的「旧运行结束后新 WorkRun 重新绑定」由既有 `work-lifecycle.test.ts` 覆盖。验证矩阵 T01、T04、T06、T08–T12 的 H 分句仍为 `untested`。

## 3. 树编辑器交互

- [ ] 3.1 扩展树展示、拖放和键盘位置菜单。交付统一的移动草稿、层级与位置预览、原位提示、取消与焦点恢复。确认操作由统一保存入口处理。会改变规划的预览及确认保存后显示活动工作与后续写入的条件句提示。用组件或控制器测试核对同一位置生成等价预览，取消恢复权威树。对应 T01、T02、T04、T05、T12 的界面交付，H 层实测见 4.2、4.4。
- [ ] 3.2 接入预设列表和插入预览，显示内置来源（`builtin`）、准确版本、可用正文语言和本次所用语言，以及层级、目标、完成条件和内部依赖。补齐结构操作、错误、状态及无障碍标签的中英资源。用字典检查及组件或控制器测试核对预览字段、英文回退、切换语言时保留草稿正文和冻结的语言参数。对应 T06、T07、T14（A）。
- [ ] 3.3 接通结构草稿到提交与回读。用控制器测试核对确认时冻结参数和操作号、结果未知时原样重试、确认冲突后以新基线和新操作号显式提交，以及结构保存和既有节点编辑回执已确认但回读失败时的「已提交，待同步」、仅重读和成功回读后的状态。覆盖原因记录的主体、部分成功和单独重试。对应 T09、T10（A）。
- [ ] 3.4 核对各实例的面板状态与草稿。用控制器测试覆盖切项目、切页后返回、已有节点内容草稿时发起结构操作，以及 A 的快照或回执在 B 打开后迟到。核对原草稿可找回，迟到结果与原操作归属一致，B 只接受自身的有效回读。对应 T03、T11（A）。

## 4. 宿主实测与收口

- [ ] 4.1 建立真实宿主验证环境。在 DSH `0.2.2-rc.2` 安装预构建包，记录提交、包版本／哈希、宿主和 profile，准备一对已登记实例和一份改动前的 v1 资料。经顶部概览和原树入口核对实际加载的是验证包和预期实例。
- [ ] 4.2 走完正常树编辑路径。在真实宿主用多根资料验证根组和普通同级组的向前／向后重排、原位、拖放与键盘等价、预览取消和焦点恢复，再跨父级移动带聊天和成果的子树并两次插入同一预设。核对预览的内置来源、准确版本、可用正文语言和本次所用语言。切换简中、英文及第三种语言核对预览正文和已保存内容。分别留下操作及回读证据。对应 T01、T02、T04、T06、T14（H）。
- [ ] 4.3 核对真实宿主的实例隔离与保存异常。在 A 留草稿，跨页并切 B，覆盖两树入口、异常身份及实例请求。验证旧基线拒绝后可重新确认，模板响应丢失后以原请求重试，回执已确认但回读待同步、原因保存部分成功，以及 A 的迟到响应与 B 隔离；重连、重启后核对回执、草稿和磁盘。对应 T03、T08–T11（H）。
- [ ] 4.4 核对真实宿主的活动 WorkRun。在配置实例有可归属活动工作时通过 owner 移动其目标祖先并插入预设，记录原目标、绑定、运行状态和读写结果。检查会改变规划的预览及确认保存后的面板提示，明确后续规划写入须待原运行结束并从当前规划发起新工作。用真实 Agent 验证旧基线和最新快照基线的写拒绝。等待原运行确认结束，从当前快照起新运行，核对新绑定与范围内写入。按 T12 分句记录宿主及真实 Agent 证据。对应 T12（H）。
- [ ] 4.5 执行升级回读与 R1／R2 回归。用改动前的 v1 资料完成结构编辑、重启和接续卡片回读，核对原聊天、历史验证状态以及现有代码观察或未核对原因。复查 R1 规范化、提交恢复和 V15／V32／V37，以及 R2 概览、实例切换及接续投影。对应 T13（F／H）和回归记录。
- [ ] 4.6 收齐交付证据并复跑 OpenSpec 严格校验及 `pnpm check:ci`。在验证矩阵逐项填写 A／F／H 实测结论与脱敏证据，标明待测或受阻分句，记录代码、包、宿主和工具版本。对应 T01–T14 的最终核对。

# R2 项目树编辑与流程拼接设计

## Context

`WorkNode` 已有 `parentId` 和 `order`。v1 支持一个或多个根。`parentId: null` 的节点构成根组，各同级组（含根组）的 `order` 从 0 连续，父子关系无环。显式依赖单独验证端点与环。现有 `update-node` 只改文本和完成条件。R2 的概览能为已登记实例打开各自的树面板；本切片从这条路径进入，继续使用 `ProjectCommandService` 内读取文件、核对基线、写入意图、发布、落回执和回读的流程。

## Goals / Non-Goals

- 支持同级重排、移动整棵子树、预设流程插入，鼠标和键盘可触达同样的位置。
- 让插入结果和既有编辑一样，可以经 v1 文件验证、重启回读，并由支持 v1 的其他读者直接打开。
- 本切片的流程来源是一个随包提供的预设。用户模板存取、项目提炼、跨项目复制、分组合并、撤销／重做及代码骨架各自进入后续提案。既有 `split-node`、节点编辑和新增节点继续走当前入口。Agent 发起的移动和插入留待同时定义来源节点、目标位置和新节点的授权。

## Decisions

### 用父节点和同级锚点表达位置

- 变换输入以 `parentId` 表示目标父节点、以 `beforeNodeId` 表示插到该同级节点之前。`beforeNodeId: null` 表示追加到同级组末尾，也覆盖空父节点。根节点在 `parentId: null` 的目标组内重排。非根节点移动和模板插入均指定一个现有节点作为目标父节点，根节点也可作为该父节点。
- 移动输入另含要移动的 `nodeId`。先从原同级列表取出该节点，再定位目标锚点；按新的列表给受影响的同级组重新编号。根级重排只重新编号根组。预览及回读按同级顺序深度优先渲染，支持逐层缩进以及同标题节点，其身份仍以 ID 确定。 [既有规划校验](../../../packages/project-plugin/src/domain/validate.ts) · [架构中的搭建与拼接](../../../docs/architecture/2026-11-11-project-development-architecture.md#用户搭建与拼接)
- 将节点移到自身或后代之下、把根降为子节点或把非根升为根、指定缺失节点或错误同级组的锚点，以及把节点自身用作锚点，均由 Host 拒绝。回落原位置的有效动作是无变化；Client 显示原位置并禁用保存。若等价命令到达 Host，复用既有无业务变化回执语义，规划指纹、规划修订和公开文件保持原值。
- 跨父级移动仅改移动根的父节点及受影响同级列表的顺序。已有节点 ID、后代之间的关系、目标和完成条件、状态、依赖边、记录索引、关联聊天保持原值。显式依赖可横跨分支，移动不产生新的依赖边。仍以完整文档校验作为发布前的最后检查。

### 内置流程实例化为普通 v1 节点

- Host 随包提供一个「功能开发」预设 `feature-development`，初始版本为 `1`。预设 ID 是稳定的小写连字符字符串，版本是正安全整数，按 ID 与版本精确匹配。子树的根下依次包含「明确目标与验收条件」「实现」「验证」，后两项分别显式依赖前一项。每个版本的正文与结构固定，任一改动均使用新版本。随包检查唯一键、模板单根、有效父级、连续同级顺序和父子／依赖无环。项目规划仍可包含多个根。
- 两个 owner 树入口各提供 `treePresets` 读取方法。概览入口用登记的 `instanceId` 解析实例，原入口使用配置实例。通过 owner 和实例可读性核对后，返回当前安装包支持的预设版本。每个条目含 `id`、`version`、固定来源 `builtin`、可用正文语言 `zh-CN`／`en`、中英预设名称和说明、节点本地键与父键、同级顺序、各语言标题／目标／完成条件、以本地键表达的依赖。Client 用同一载荷预览，按宿主语言选定本次正文，其他宿主语言使用 `en`。 [界面与内容语言](../../../docs/architecture/2026-11-12-plugin-i18n-design.md#界面语言与项目内容分开)
- 插入请求提交 `templateId`、`templateVersion`、`contentLocale`、`parentId` 和 `beforeNodeId`。Host 根据自身随包预设解析内容，全部参数与实例和基线进入请求摘要。新操作只能使用当前安装包提供的 ID／版本和该预设声明的正文语言。未知 ID、当前包无对应版本、语言越界及预设内容无效分别返回 `template-not-found`、`template-version-unavailable`、`template-locale-unsupported`、`template-invalid`。位置错误沿用规划命令的结构校验诊断，父节点为空或不存在用 `parent-not-found`，锚点不存在或不属于目标同级组用 `invalid-anchor`。
- Host 为模板中的每个节点分配新 ID。预设键只在本次实例化中映射父子关系及内部依赖；模板根挂到目标父节点，新节点从 `todo` 开始。一次发布整棵子树，保留既有依赖，模板边只连本次生成的节点。公开结果使用标准 v1 规划数据，会话、授权和历史验证沿用既有存储。 [v1 schema](../../../packages/project-plugin/formats/v1/project-v1.schema.json)
- 持久意图记录本次分配的 ID 与候选头。匹配的重试先按既有意图或回执核对，新操作号的显式插入生成独立子树。已持久化的候选和回执使用原请求摘要、生成 ID 与候选头走恢复流程，即使升级包已移除原预设版本。

### 复用实例准入、保存与读取

- `conaOverview` 的 owner 准入及实例注册核对继续保护预设读取与结构写入。原 `conaProject` owner 树入口接入时复用同一服务。新增命令在可信上下文的准入阶段明确限定为 `remote-owner`，覆盖原始命令的直达调用。既有 Agent 动作、目标和已接受基线核对适用于原有工具。 [owner 入口](../../../packages/project-plugin/src/host/overview-service.ts) · [WorkRun 准入](../../../packages/project-plugin/src/application/work.ts)
- 每个结构草稿捕获项目 ID、实例 ID、源代际、`planVersion`、`planRevision` 及操作参数。快照不可用或正在核对未知写入时，沿用面板现有的写入可用性规则。提交服务在同一实例串行队列内重读完整资料基线并校验，再以现有持久意图、发布和回执顺序处理。实际变更推进一次规划修订和状态修订。接受回读时核对当前实例、连接代际、源代际和修订顺序；展示当前完整快照中的树。若回读已包含其他提交，保留原操作的回执结论，树显示最新有效快照。
- 每个实例同一时间保留一份面板草稿。已有内容或结构草稿时，用户先保存并完成核对，或明确放弃，才能开始另一份草稿。确认保存后冻结请求参数与 `operationId`。响应丢失或提交结果未知时，只允许核对或重发原请求。已确认冲突后，用户在新快照重新选择位置并确认，以新操作号提交。既有回执匹配、隔离及恢复规则继续处理未决写入。 [提交与恢复规范](../../specs/project-command-commit/spec.md) · [面板同步规范](../../specs/project-panel-sync/spec.md)
- 共用面板的规划保存回读判据，覆盖结构操作和现有节点内容编辑。回执确认发布而完整回读失败或落后时，展示「已提交，待同步」，保留带未同步提示的树，仅重试读取而不重提已成功的变更。有效回读须匹配项目、实例和源代际，且规划与状态修订至少覆盖回执，同一规划修订的规划指纹须与回执相符。换源后的回执属于历史，当前资料按有效快照显示。
- 使用原 PanelController 的每实例状态保存浏览选择和草稿。切项目或宿主页面后的迟到响应只归属原实例与原操作，回到原实例后再显示其最新快照及草稿状态。 [概览与接续规范](../../specs/project-overview-resume/spec.md)

### 活动 WorkRun 保持执行，后续写入走新运行

owner 提交实际规划变化时，当前 WorkRun 继续执行并可读取；目标、允许动作、绑定和运行历史保留。旧基线请求遇到当前规划冲突或变源；将最新读取结果用作当前运行的写入基线，仍会因绑定基线不符而被拒绝。`continueScope` 不接受新规划基线。会改变规划的结构预览及已确认的保存结果提供条件句提示：「如果有活动工作，后续规划写入需等原运行结束，再从当前规划显式发起新工作。」这条文案固定随操作显示，只说明条件和后续操作。新工作按既有可信宿主事件创建 WorkRun 和绑定。单纯重排不发送停止指令，原位操作也不触发基线变化。 [WorkRun 准入](../../../packages/project-plugin/src/application/work.ts) · [工具协议](../../../packages/project-plugin/docs/tool-protocol.md)

### 沿用面板的可选变更原因

结构草稿沿用现有可选变更原因。移动和重排以移动节点为记录主体，插入以目标父节点为主体。先确认结构提交及同源有效回读，再按现有 `append-record` 流程保存原因。原因保存独立显示成功、失败或待核对，使用自己的操作号核对或重试，结构命令保持原回执。

### 预览和本地化

拖放和操作菜单统一生成同一种结构草稿。预览列明要移动或插入的节点、目标父节点和位置，可取消并恢复已保存树。模板预览还列出内部依赖和完成条件。键盘可用菜单完成选择、确认、取消，焦点返回可辨认的树节点或触发按钮。用户通过明确的保存操作提交。提交成功后从权威快照显示新结构，并按已保存、冲突或待核对等状态告知结果。

控件、状态、原因和无障碍标签使用现有字典与英文回退。预设名称和说明随 UI 语言显示；预览建立时选定正文语言，切换宿主语言时保留待保存正文及已保存项目原文。原预览保存并完成核对或明确放弃后，可用当前可用语言重新选择模板。第三种宿主语言下的新预览选用 `en`。

## Risks / Trade-offs

- 同级列表重排会改变相关兄弟节点的 `order`。单次候选校验覆盖整份计划；回读测试应核对两侧列表、稳定 ID 和相关记录，并覆盖同级由前往后移动的偏移边界。
- 变更基线冲突时，用户需要对新位置重新确认。树位置可能受到其他编辑影响，因此保留原意图并同时提供新快照供核对。旧基线回执仅表示历史。
- DSH 内拖放、键盘焦点和跨页草稿保持需在固定宿主上复测。探针和回归记录分别注明代码、包、宿主版本及测试层级。 [验证矩阵](validation-matrix.md)

## Migration Plan

项目资料继续使用 v1；已有项目用当前快照进入树编辑器。预设随插件发布。既有文件和本机回执照原有解析、核对及恢复流程读取。验收使用一份改动前的 v1 资料，升级后编辑并发布，再用现有 v1 验证器和旧读者回读结果。接续回归核对历史验证、聊天和已有代码观察；规划基线的保存与比较仍对应 R2 首切片 O08 的未完成部分，主规范要求继续保留。 [O08 验证记录](../archive/2026-11-20-add-project-overview-and-resume/validation-matrix.md) · [接续主规范](../../specs/project-overview-resume/spec.md)

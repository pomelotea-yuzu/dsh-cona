## 正常使用过程

1. 用户在项目概览点「项目分析」，选择一个已映射的仓库和一个相对文件或目录。预览显示本机资料实例、所选范围、范围内可观察的文件和排除项。用户确认后冻结此次输入，建立独立分析 Session 并送入一次分析请求。取消预览返回概览。
2. Agent 在该 Session 中读取范围内文本、规划背景和允许引用的已有验证记录，提交结构化发现。概览显示准备中、分析中、完成、中断或需要核对。用户可以打开实际分析聊天，查看报告或发起新的复盘。切换概览实例只改变浏览对象。
3. 举例，分析 `packages/project-plugin/src/host` 时，报告可以指出已读的会话接入文件、推断某条连接限制及建议补的边界测试。若随后修改、添加或删除该目录下的文件，即使没有新 commit，回看也会指出依据已变。再次确认后一轮生成新报告，可返回上一轮查看当时的材料。

### 分析会话的执行器

随插件的 `cordis.patch.yml` 插入 `@deepseek-ai/dsh-agent-preset` 声明行，以 `config.id: cona-project-analysis` 作为分析会话选择的稳定标识。宿主现有 `agentPresets` 注册表加载该声明。`config.plugins` 声明原生工具执行器 `@deepseek-ai/dsh-tool-executor-native` 和插件的分析作用域接入模块。接入模块注册本轮允许的分析能力，并接到现有 Host 的实例绑定。preset 子插件不装配 PTC、Shell、编辑或代理执行工具；继承来的工具受可见性限制和实际执行守卫控制。注册表缺失、重复 ID、声明加载／解析失败、宿主返回的 preset 不符或有效作用域不可确认时，显示分析执行不可用及具体原因，保留历史回看。固定安装包须验证这些路径。

分析 preset 作用域必须选定 DSH rc.2 的原生工具执行器（`packages/core/tool-executor-native`），并在真实 Agent 的工具定义和调用执行上自证。`packages/core/tools/src/index.ts` 的执行器选择优先用近层作用域。使用启用 PTC 的隔离对照 profile 核实普通 Session 仍使用原先的执行器，分析 Session 走原生执行，保留的 `run_code` 入口无法调度。分析可执行集合限于项目背景、索引、受限文件读取、验证记录读取和本机报告保存。执行守卫同时拦截分析作用域出现的其他工具、局部注册工具、Shell 和代理转发能力。PTC 的程序正文在工具守卫之外运行，文件沙箱的 `read-only` 只限制写入；两者均不能替代执行器选择和范围读工具的约束。

以隔离夹具中的合成文件做正反对照。向分析 Session 发起未允许的执行调用时，分别观察执行器的选择、工具分派结局与正文未进入的证据，以及范围外内容没有返回、范围内外测试文件未变化。记录部署的文件／进程沙箱模式；单有文件未变化或沙箱拒写，无法证明没有代码被执行。分析作用域的原生执行器或守卫无法在固定版可靠建立、恢复或核对时，入口显示执行不可用，保留历史回看。

以上 DSH 接点是对固定提交 `ddac96760b6edf8fa0fe17cbdcf0b512f4c12b2c` 的静态核对。实施第 2 组在隔离 profile 验证真实安装包和实际工具路径，包括失败后是否能阻止首条请求进入模型。保护无法建立时，概览保留历史入口，并显示分析执行不可用。若固定版本无法实现已定边界，执行者记录实测并按 change 工作流处理设计调整。此处不要求跟随宿主升级。

分析能力在专用作用域注册，执行器和守卫均须在首次派发前就绪。后端按实际 Session、已认领的请求、绑定、实例和源代际核对。工具输入中的 Session、实例、身份、源代际或路径绝对位置均不能替代 Host 绑定。通过 scoped tools 检查可见性，并以实际执行守卫阻止未允许调用；允许集合内的工具仍各自做参数和范围校验。分析完成、中断或宿主重启后，原 Session 进入历史状态。概览标记「历史分析」并提供复盘入口。宿主会话页仍能接收输入的环境，由后台步骤准入拒绝继续分析，不进入模型、不给旧绑定恢复读写；本机历史视图保持可查。已有普通 Session 的执行权限沿用其各自规则。

### 启动和恢复的提交顺序

预览只读取映射、范围和规划信息。确认请求以 owner 提供的操作号冻结实例、仓库和所选范围，先在实例队列建立本机分析记录；有可信 Session ID 后持久登记关联，核对实际 preset、执行器和守卫，再发送带 Host 请求标识的首条消息。已确认的映射或规划变化时返回重取预览。Session 创建或发送返回未知时，先用保存的标识、实际会话目录及消息记录核对。同号重试回读已确认结果，未查清的阶段保留待核对，无条件重发会导致重复启动。重启加载分析会话归属和工具保护后才接受分析工作，既有消息与报告仅作为历史。

## 文件范围、枚举和读取凭证

- 每轮一个本机逻辑仓库、一个文件或目录。优先复用登记的逻辑仓库映射及配置实例可用的工作副本根。只有实际上能核对的映射可选。路径使用仓库相对路径，目录成员按路径段判定。根目录选择显式表达。使用 `validateRelativePath` 和 `resolveInScope` 的规则拒绝绝对路径、上跳、逐段符号链接和不合适的文件类型。回看引用时按当前映射重新执行同样的范围核对，并核验历史版本凭证。
- 目录递归采用稳定顺序，跳过 Git 内部资料和非普通文件。工作副本可由 Git 核对时也跳过 Git 忽略的未跟踪路径；已跟踪文件仍按所选范围处理。显式选择被排除对象时显示原因。扫描项数、单文件字节和单轮已返回文本的总量在文件适配器集中设置，测试可注入小上限分别命中每种情况。非文本、超出上限与读取失败项保留原因；范围内的文件若无法取得内容指纹，该次观察为不完整。已确定部分仍可供分析。范围外文件和已明确排除对象不参与内容变化判断。
- 观察范围时生成由相对路径、类型和内容哈希组成的有序条目，并记录整份观察是否完整。枚举、内容指纹和提供给 Agent 阅读是三个不同动作。只有真正交付给 Agent 的文本范围才生成读取凭证，含相对路径、实际行范围及所见内容哈希；截断只计交付片段。受检文件在读取前后出现已观察到的替换或变化时记为依据不一致。读取凭证及报告终稿只留本机，内容观察不缓存整棵代码树。

## 验证记录与历史来源

验证记录是同一资料实例内的项目背景。分析开始时从已校验公开快照获得有界的 `verification` 索引清单；正文只通过已绑定的验证记录读取入口交付。以记录 ID 在同实例同代际重新定位捕获时的索引项，对照当前索引核验 `kind`、`contentHash`、验证主体、`subjectVersion`、已记录状态和范围，再用 `readScopedFile` 读取并核对正文实际字节哈希。以实际交付的正文片段制造凭证，正文没读到时展示覆盖缺口。报告提交只接受本轮已交付凭证；若引用正文或元数据与凭证不一致，返回可核对诊断。其他公开记录仍可通过所选工作副本内的普通文件作为静态资料阅读。报告中的既有验证沿用原状态和受检版本，`subjectVersion` 缺失显示未核对，有值也仍按历史证据展示；首切片只报告已有证据和静态发现。

代码来源凭证包含读取时的相对路径、整份文件字节哈希和实际交付行范围。打开来源前重新核对映射和范围，再比较当前文件字节哈希及该行范围。两者相符可导航到原行；同路径内容修改、行号移动或删后重建且内容有差异时，默认显示「历史来源已变化」，给出原凭证，有现文件才提供显式的「查看当前文件」。路径或映射失效时保留历史凭证并给出原因。验证记录来源同样复查当前索引及正文，以本轮凭证四项（记录 ID、`contentHash`、验证主体、`subjectVersion`）和对应字节／行范围判断是否仍一致，正文或元数据变化时只呈现历史状态，禁止用现有记录替代当轮证据。

## 报告、持久化和生命周期

| 本机对象 | 必需信息与约束 |
|---|---|
| 分析记录 | `analysisId`、实例、实际 Session、发起请求标识、仓库映射身份、文件或目录、来源代际、`planVersion`、开始的代码观察、开始时间与执行状态。复盘可带上轮 `analysisId`。 |
| 读取凭证 | 文件为所见相对路径、整份文件哈希及实际交付行范围；验证记录为绑定的记录 ID、正文哈希、验证主体与受检版本及所交付行范围。覆盖分别记录工作副本和验证记录的已读、未读、不可读与排除项，均由宿主生成。 |
| 报告终稿 | 报告时间、概要、事实／推断／建议条目及其依据。事实必须引用本轮已交付的文件或验证记录凭证，或已捕获的规划背景。外部验证引用带来源与历史状态。没有本轮对应验证证据的项按静态分析标示。首切片不执行测试命令。 |

开始由 owner 确认。保存由持有分析绑定的实际 Agent 提交。数据写入复用本机持久化和实例队列，作为独立私有对象保存，适配旧本机状态缺少分析字段的情况。一个分析最多一个终稿。以实例、`analysisId`、请求 ID 与规范化载荷核对重试，同一请求同一载荷返回同一结果，改变载荷或复用错误目标时给冲突诊断。已持久化报告会在重连回读。正文或终稿发布失败保持未完成状态并可查明实际结局。

发布前在实例队列再次核对绑定、停止状态和源代际。取消请求与宿主实际终态分别记录。已收到取消不接收新的提交，已有持久报告继续可回读。宿主终态时无报告则标中断或未形成报告，重启后按历史回读且不恢复旧分析授权。导航、报告刷新和实例切换不发送新请求。

## 依据状态与复盘

运行状态与依据状态独立展示。依据状态由 Host 在保存和回看时计算：

| 状态 | 条件与处理 |
|---|---|
| 当前 | 来源与映射可核对，`planVersion` 一致，范围观察完整且内容一致，没有已观察到的读取不一致。Git HEAD 可作为来源附注。单独改动范围外文件保持当前。追加本轮未引用的记录时，若 `planVersion` 与既有引用凭证未变，也保持当前。 |
| 依据已变 | 可确认来源代际、映射、规划内容、范围内文件增删改、已引用验证记录正文或元数据的变化，或已观察到交付给 Agent 的内容与报告基线不符。展示变更类别，保留历史报告；若同时有观察缺口，仍解释缺口。 |
| 无法核对 | 无确认变化，但工作副本、范围或内容观察因映射缺失、读错误或扫描截断无法重建或比较。说明缺口，并提供重新选择范围或复盘入口。 |

保存用当轮实际读取的依据。工作副本中途发生变化时仍可提交带旧依据的历史发现，确知变化的报告当场标明；资料源代际失效时旧运行停止写入，已有报告按历史保留。复盘重新预览同一范围或由用户改选，从当前规划及代码建立新 `analysisId` 和 Session。这个入口不会应用建议或变更树。相关提示、状态与空态提供简中、英文和英文回退。

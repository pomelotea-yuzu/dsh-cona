## ADDED Requirements

### Requirement: 从概览确认范围并启动独立分析

项目概览 MUST 显示分析入口，具备本机有效工作副本映射且支持受保护执行的配置实例可发起分析；条件缺失时显示不可用及原因。用户选择已映射的仓库及一个文件、目录或仓库根。Host MUST 在确认时重新核对预览的实例、映射、范围及规划基线，为每轮登记独立分析 ID、实际 DSH Session、源代际与代码观察。确认和重试 MUST 使用同一可核对的启动请求，开始分析的授权只来自本机用户确认及可信宿主绑定。

#### Scenario: A01 首次分析与取消预览

- **WHEN** 用户在已有代码项目的概览选择仓库和范围，并确认或取消预览
- **THEN** 确认创建带指定范围、基线和专用 preset 的新分析 Session，同工作区已有空白 Session 保持原关联；取消返回概览且不创建分析或发送消息

#### Scenario: A02 缺少映射或预览过期

- **WHEN** 当前实例没有有效映射，或确认前实际映射、实例或规划基线改变
- **THEN** 显示确切原因，不使用另一实例的工作副本，也不按旧预览派发分析

#### Scenario: A03 启动重试与关联失败

- **WHEN** 用户重复确认同一启动请求、响应丢失或实际 Session 尚未成功登记
- **THEN** 可查证的同一请求回到原分析，结果未知时显示需要核对，未登记实际 Session 时不派发分析消息

### Requirement: 受保护的只读执行与真实读取凭证

分析 Session MUST 使用固定宿主的专用原生工具执行路径，排除 PTC 程序及通用代码执行。Host MUST 按可信实际 Agent 身份与执行范围，只允许读取已捕获的规划背景、读取同一资料实例已校验的验证记录索引和正文、列举和读取经范围核对的文件，以及保存本轮本机报告。Host MUST 在首条消息前核对会话关联、实际执行器及执行守卫。分析不能继承另一会话的工作授权。范围预览与枚举须说明排除、不可读与截断；只对实际交付给 Agent 的字节和行范围记已读。

#### Scenario: A04 真实身份与其他会话隔离

- **WHEN** 已登记的分析会话和另一个普通工作会话同时存在，或分析工具收到其他会话和过期绑定的调用
- **THEN** 正常分析只可在当前绑定的范围内读取，普通工作按自己的授权运行，错误或失效身份不能使用分析绑定

#### Scenario: A05 拒绝写入和未保护的执行

- **WHEN** 分析尝试调用 PTC 保留执行入口、其他通用代码执行、文件写入、Shell、代理或公开项目写入，或在启动前不能确认原生执行器／范围保护
- **THEN** 未允许的执行在正文开始前被拒绝，范围外内容没有返回、范围内外文件没有改变；缺少保护时入口显示执行不可用且不派发分析请求

#### Scenario: A06 范围越界与部分读取

- **WHEN** 分析试图访问相邻目录、符号链接、仓库内部资料或其他排除对象，或部分文件不可读、超出限额，只能提供部分文本
- **THEN** 拒绝越界和排除项，展示覆盖缺口，只为实际交付给 Agent 的文本范围生成凭证

#### Scenario: A07 终止执行与历史会话

- **WHEN** 分析完成、中断、收到停止请求、原资料源代际失效或 Host 重启，随后尝试向旧会话输入新请求、读取或提交报告
- **THEN** UI 区分停止请求与真实终态，历史会话和报告可回看，分析入口提示再次分析；后端拒绝历史会话的新模型步骤与旧绑定的读取或提交

### Requirement: 私有报告、可靠保存和来源回看

系统 MUST 按本机资料实例保存分析报告。报告 MUST 展示范围、覆盖、读取凭证、事实、推断、建议及验证依据，且报告正文与私有会话引用不得进入公开资料。一个分析至多对应一个终稿，同一保存请求重试 MUST 核对载荷并返回已有结果或明确诊断。来源导航 MUST 按当前映射、内容凭证及原行范围复核目标。系统 MUST 为分析提供同实例的限定入口，读取已捕获索引中的 `verification` 正文。引用这类记录时 MUST 核对实际交付的记录 ID、`contentHash`、验证主体与 `subjectVersion`，并保留受检版本和原验证状态。

#### Scenario: A08 历史报告准确表达读取覆盖

- **WHEN** Agent 实际检查了完整文件和截断片段，另有未读、不可读或只枚举的路径
- **THEN** 只有真实读取证据计入查阅覆盖，报告区分其余缺口及范围是否完整，不以自述补齐

#### Scenario: A09 事实、推断与验证依据

- **WHEN** Agent 读取同实例的验证记录正文并引用，或提交无效记录、正文哈希／受检版本不符及无法证实的验证结论
- **THEN** 覆盖只计入实交付的正文。报告核对来源凭证后分别展示事实、推断与建议。原验证状态随历史证据保留，受检版本缺失时显示未核对，历史验证不产生本轮实测结论

#### Scenario: A10 保存重试、重启与实例隔离

- **WHEN** 保存响应丢失并重试，随后重启宿主并切到同项目的另一资料实例
- **THEN** 同号同载荷返回已存终稿，同号异载荷返回冲突，原实例重启后可查，另一实例和公开资料不含私有报告或会话引用

#### Scenario: A15 打开报告依据前重新核查

- **WHEN** 用户打开报告来源，当前路径和内容可核对、路径失效／越界，或同路径内容、原行范围或验证记录凭证已变化
- **THEN** 一致时定位原文；失效时显示原因；凭证不一致时显示历史来源已变化并保留旧凭证，若仍有安全可读的现文件，须另行选择才能查看当前内容

### Requirement: 核对报告依据并生成独立复盘

系统 MUST 在保存和回看时核对报告的来源代际、工作副本映射、规划及范围内代码内容。范围内的未提交修改、增加和删除 MUST 纳入核对。确认变化和无法核对 MUST 各有明确状态。用户 MUST 能重新确认范围、使用当前基线再次分析，并保留独立历史报告。该路径只记录分析与建议。

#### Scenario: A11 同一 Git HEAD 的范围内变化

- **WHEN** 分析期间或报告完成后，范围内文件未提交修改、新增或删除
- **THEN** 依据状态显示变化，已有报告仍可查，如有建议则提示重新核对

#### Scenario: A12 规划或映射变化

- **WHEN** 规划内容修订、源代际或工作副本映射改变
- **THEN** 历史报告显示相应依据已变并保留原依据，原分析绑定不能转移到新来源

#### Scenario: A13 范围外或无关变化

- **WHEN** 仅更改范围外文件，或追加本轮未引用且保持 `planVersion` 与既有已引用凭证不变的记录
- **THEN** 范围内可核对的内容与规划一致时保持依据当前

#### Scenario: A14 内容观察不可核对

- **WHEN** 没有已确认的相关变化，但工作副本失联、读取失败或观察被截断而不能完成比较
- **THEN** 显示无法核对及原因；存在部分读取凭证时该历史报告仍可回看

#### Scenario: A16 使用同一入口复盘

- **WHEN** 用户从原报告选择再次分析并确认当前范围和基线
- **THEN** 创建新的实际 Session 和分析 ID，保留两轮报告及各自依据，规划不因建议自动修改

### Requirement: 分析界面的中英资源与未知状态

分析入口、报告覆盖、运行及依据状态、诊断与空态 MUST 提供简体中文及英文，其他宿主语言回退英文。用户报告及来源原文保持其存储语言。

#### Scenario: A17 切换宿主语言

- **WHEN** 用户在简体中文、英文及第三种宿主语言下打开分析界面
- **THEN** 固定文案按既定语言和回退显示，报告原文与覆盖数据保持一致

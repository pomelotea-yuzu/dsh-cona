## 方法

用桌面安装包自带的 Electron Node（`ELECTRON_RUN_AS_NODE`）直接 import `@deepseek-ai/dsh/lib/profile-boot.js` 的 `runProfile()`，在隔离 profile 内启动**真实 web 组合**（真实 base/web-app 插件树、`agentPresets`、`sessionController`、`tools`），拿到 root `ctx` 后：

- `sessionController.create({ cwd, agentPreset })` 创建真实 Session 与 Agent；
- `tools.execute()` 走真实工具分派（含 guard/approval/执行器选择）；
- `agent.followup(createUserMessage({ source:{kind:'user', rpcId} }))` 触发真实 turn 与 `agent/pre-step`。

分析能力工具（`cona_analysis_*`）属 3.x/5.x，尚未实现。为让 `restrict()` 有可允许的全局工具，profile 在插件 bundle 之前安装测试夹具 `cona-r3-fixture`：只注册四个允许名、不实现读取语义。**夹具不是产品代码**，它使 2.x 的接点可被单独验证。

## 已实测

### preset 注册、实际会话与有效作用域（2.1 / A03、A05）

- `agentPresets` roster：`standard, ptc, minimal, cordis, cona-project-analysis`；重启与重装后可重复。
- `sessionController.create({ cwd: '/tmp/dsh-2x-probe/fixture', agentPreset: 'cona-project-analysis' })` 返回 `{ sessionId, agentPreset: 'cona-project-analysis' }`，`presetForSession` 与实际 Agent 一致；会话 cwd 记录为夹具目录（工作区挂载）。
- 可见工具只剩 `cona_analysis_background／cona_analysis_scope_files／cona_analysis_verification／cona_analysis_save_report`（`restrict` 生效）。
- 注册表缺失：headless profile 不组合 `sessionController` 与 `agentPresets`，preset 行停在 `pending (waiting for service: agentPresets)`，`cona-project` 停在 `pending (waiting for service: sessionController)`——不可用诊断可见。
- ID 冲突：`--patch` 追加第二个 `config.id: cona-project-analysis` 的声明，启动警告 `preset-duplicate-probe: Duplicate agent preset: cona-project-analysis`；原有的 roster 条目保留、可继续创建会话。

### 守卫、执行器与工具分派（2.2 / A04、A05）

- 未登记绑定：`checkGuards` 对任意工具返回 `analysis-binding-missing`；`persisted:false` 返回 `analysis-binding-not-persisted`。
- 登记绑定后：允许集内工具 `ALLOW`；`bash`／`write`／`run_code` 返回 `analysis-tool-not-allowed:<name>`。
- `tools.execute()` 实测：分析 Session 的 `bash`、`write`、`run_code` 均在**执行前**被守卫拒绝（`isError:true`，正文未进入）；夹具三个文件 sha256 前后一致，未产生 `analysis-bash.txt`／`analysis-write.txt`／`analysis-ptc.txt`。
- 执行器选择：分析 Session → `NativeToolExecutor`；同一宿主的 `standard` Session → `NativeToolExecutor`；`ptc` Session → `PtcExecutor`。PTC 对照里普通会话的 `run_code` **到达 code-run 层**（因本实测进程自身在沙箱内，返回 `CODE_RUN_FAILED sandbox-unavailable`，不是守卫拒绝）；分析 Session 的 `run_code` 停在守卫层。两者拒绝层不同，符合「工具拒绝与沙箱副作用拒绝分别取证」。
- 沙箱模式：会话事件记录 `permission/preset: workspace-write`、`sandbox/mode: workspace-write`、`approval/policy: ask`。

### 首消息认领与历史输入（2.3 / A07 部分）

在分析 Session 登记绑定 `requestId: rpc-ok` 后，用 `agent.followup` 发真实用户消息：

- `rpcId: rpc-wrong` → `turn/end {kind:'blocked'}`，会话事件只有 `turn/start`、`inbox/spliced`、`turn/end`，**没有** `step/start`／`request/header`／`assistant/attempt`：步骤未进入模型。

## 真宿主暴露并已修复的问题

1. **`ctx.effect` 语义用反，保护装好即释放。** `analysis-scope.ts` 原写 `ctx.effect?.(() => install.dispose())`；cordis 的 `effect` 会立即执行工厂并收集其返回的释放函数，因此安装完成时 `dispose()` 立即执行：真宿主里 `tools.guards.scoped` 与限制层均为空，守卫完全不生效（keyless 安装测试的 stub 不执行回调，未暴露）。修为 `effect(() => () => install.dispose())`，并新增 `2.x-r` 测试（安装后保护仍在、卸载时才释放）。修复后复测：可见工具只剩四个允许名、守卫拒绝／允许符合预期。
2. **随包 `cordis.patch.yml` 的 `cona-project` 行缺 `config` 时无法激活。** 插件 `Config` 是 `z.object`（字段全可选），loader 对未配置行传 `undefined`，`resolveConfig` 抛 `ValidationError: invalid config`。R2 记录里由 profile 手补 `config` 绕过；本次在隔离 profile 复现后，随包 patch 显式写 `config: {}`（profile 仍可按 id 覆盖以提供 `projectRoot` 等），重装后面板插件正常激活。

两处修复后的门禁：插件测试 **547/547**（原 546 + 新增 `2.x-r`）；仓库门禁 `node scripts/check-repo.mjs --all` 放行。

## 未测与边界（保持不勾选）

- **真实模型回合**：隔离 home 没有 `DEEPSEEK_API_KEY`；复制桌面 `llm-deepseek` 凭证存储后启用 account provider，仍返回 `ACCOUNT_SIGN_IN_REQUIRED`（桌面登录不可移植）。因此「分析 Session 用真实模型完成一次分析」没有发生；A04／A05 的「真实 Agent」分句仍缺。
- **范围语义**：范围预览、越界拒绝、部分读取、真实 `cona_analysis_*` 工具行为属 3.x／5.x；夹具只证明接点，不证明 A06／A08。
- **启动响应丢失、重启后历史会话**：Host 侧 4.x／6.x 未实现；当前绑定表在进程内，重启即空，pre-step 在无绑定时放行。A07 的完成／中断／重启分句未测。
- **入口不可用诊断**：scope 安装失败（如允许工具缺失）时 `ready=false` 只打印警告，未安装任何守卫；若 Host（3.x／7.x）仍派发分析消息，该会话将没有保护。入口必须在派发前核对 `ready`，此点为后续实现的硬要求。
- **允许工具的注册位置待定**：rc.2 的 `restrict({allow})` 只校验**全局**工具名，作用域本地注册不参与 allow 校验。本次夹具因此把四个 `cona_analysis_*` 注册在全局；若 3.x／5.x 按 design「在专用作用域注册」把工具放进分析 scope，当前 `restrict` 会报 `unknown global tools` 而 fail-closed；若继续注册全局，普通 Session 也会看到这些能力（守卫只装在分析 scope）。落地前必须二选一并补测：允许集校验改为「存在即可」，或分析工具保持 scope 内注册、由守卫兜底。

## Purpose

让项目节点与 DSH 聊天保持可查询的多对多关系，同时为每次实际执行提供独立可信的目标、规划基线和动作范围，避免浏览行为、模型参数或导入历史静默改变正在执行的工作及其权限。

## ADDED Requirements

### Requirement: 多对多聊天关联与实际会话身份

系统 MUST 支持一个节点关联多个聊天、一个聊天关联多个节点，保存用途和来源，并使用 DSH 实际返回的 Session 身份。创建／复用／打开聊天 MUST 核查实际关联，失效或属于另一资料实例的会话不得被静默认领。

#### Scenario: 多对多关联

- **WHEN** 节点 A 关联需求和实现聊天，实现聊天同时关联 A 与 B
- **THEN** 从节点和聊天均能查询这些关系，不用唯一 Session 字段替代全部关联

#### Scenario: 创建请求复用空白会话

- **WHEN** 宿主返回了可复用的空白 Session
- **THEN** 插件记录实际返回身份并核对关联，不把预期新 id 或其他执行聊天写入关系

### Requirement: 关联与活动写绑定分离

聊天关联 MUST 只表达背景关系；活动 WorkRun MUST 单独记录目标集合、意图、动作范围、资料实例／源代际及输入基线。浏览节点或增添聊天关联 MUST NOT 自动修改活动执行目标、开始工作或扩大权限。

#### Scenario: 执行 A 时浏览 B

- **WHEN** Agent 正在为 A 工作，而用户在面板选中 B
- **THEN** 浏览切换到 B，运行仍绑定 A；未获得新绑定的 B 写请求被拒绝

#### Scenario: 聊天已关联多个节点

- **WHEN** 当前运行只允许修改 A，而同一聊天还关联 B
- **THEN** 可以按访问范围读取背景，但关联本身不授予修改 B 的资格

### Requirement: 可信调用上下文与有限规划授权

Agent 写入 MUST 从 DSH 实际工具上下文和匹配的活动 WorkRun 取得身份，核对目标、动作、绑定版本和执行基线。Remote owner 与 Agent 工具 MUST 分别准入，不得仅凭 principalOf 为空授权。R1 MUST 能在允许目标内新增或拆分并记录原因；模型自报身份不得扩大范围。

#### Scenario: 授权内根据新信息拆分

- **WHEN** 用户允许围绕 A 调整规划，真实活动运行据新信息提出有原因的新增或拆分
- **THEN** 经统一提交检查后保存结构和原因，UI 回读到实际提交结果

#### Scenario: 伪造身份或越权目标

- **WHEN** 工具参数伪造其他 Session／WorkRun／角色，或请求修改绑定外的目标
- **THEN** 拒绝写入，不因参数声称已授权而创建新绑定，也不泄露无权读取的资料

#### Scenario: 无可信执行身份

- **WHEN** 某入口无法取得足够可信的 Agent、活动执行边界或取消状态
- **THEN** 该入口写入受阻并记录原因，不回退信任模型自报；R1 完整闭环不能因此标为通过

#### Scenario: 工具没有 Remote invocation 但具备真实绑定

- **WHEN** 实际工具调用没有 Remote invocation，却有可信 Agent 和匹配的活动 WorkRun／捕获绑定版本
- **THEN** 按工具主体检查其有限范围，不因缺 invocation 自动拒绝，也不取得 Remote owner 权限

#### Scenario: principalOf 为空或伪造 Remote 主体

- **WHEN** 无绑定的进程内工具调用令 principalOf 返回空，或业务参数伪造 owner invocation
- **THEN** 不凭空值或自报主体取得任何写资格，Remote 与工具各自的准入检查仍须成立

#### Scenario: 工具 Agent 字段缺失

- **WHEN** 实际 ToolRunContext.agent 缺失或无法唯一对应活动执行
- **THEN** 拒绝建立新绑定并记录 blocked，不从模型字段、owner 判据或旧记录推导执行身份

### Requirement: 排队、续接与旧调用隔离

每个活动执行上下文 MUST 仅有一个有效写绑定；排队消息不得覆盖当前绑定。范围变更 MUST 创建新绑定版本并保存接续来源，旧调用不得动态取得新范围；已授权规划提交后的后续命令也 MUST 重新核对明确的最新基线。

#### Scenario: 同会话排队请求不同目标

- **WHEN** A 仍在执行时，为 B 的请求进入同一会话队列
- **THEN** B 保留为待执行意图，A 的工具调用仍只对应 A，直到可信边界显式建立 B 的新绑定

#### Scenario: 旧工具调用迟到

- **WHEN** 绑定已更新或撤销，而旧调用进入提交序列
- **THEN** 按捕获的旧绑定和当前资格核对并拒绝失效写入，不把新版本权限借给旧调用

### Requirement: 结束、取消与重启不恢复权限

系统 MUST 依真实宿主生命周期使绑定失效，区分停止请求与已确认终态；Host 重启后 WorkRun 历史不得自动激活。UI 断线不自动取消宿主工作；明确取消后不得准入新的写操作，已进入发布的操作按提交恢复协议处理。

#### Scenario: 轮次结束或取消后调用

- **WHEN** 原执行已结束或取消，而工具尝试以旧绑定提交新命令
- **THEN** 拒绝新写入，保留实际历史；未确认停止的工作显示未知或待核对

#### Scenario: Host 重启与 Client 断线

- **WHEN** Host 从历史恢复 WorkRun，或 Client 断线后重连
- **THEN** 重启不恢复旧运行写资格；仅 Client 断线不撤销仍在宿主活动的绑定，重连回读真实状态

### Requirement: 有来源的运行上下文

运行上下文 MUST 按实际绑定提供目标、约束、规划基线、相关公开记录和本机聊天入口，区分用户决定、Agent 建议与未核查项。刷新在可信执行边界生效，不能把整棵树或所有聊天无差别注入，也不能通过提示文本替代程序授权。

#### Scenario: 获取目标上下文并继续工作

- **WHEN** 关联聊天在可信边界开始为 A 工作
- **THEN** Agent 得到 A 的目标、约束、当前规划版本和可追溯资料入口，所见背景与绑定一致

#### Scenario: 运行期间收到新材料

- **WHEN** 新资料到达但当前执行尚未经过新的接续边界
- **THEN** 标记待核对信息，不静默改写已启动目标；需要扩展范围时更新绑定并保留接续原因

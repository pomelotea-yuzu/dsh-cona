## Purpose

在 DSH 内提供可演示的小树编辑与聊天入口，并使界面始终区分本地编辑、已提交状态和未同步缓存，通过完整快照及版本边界处理首次加载、重连、迟到响应和恢复状态。

## ADDED Requirements

### Requirement: 最小面板与提交事实

项目面板 MUST 支持创建／接入项目、显示小树与详情、编辑及新增节点、打开关联聊天，并展示变更原因和存储位置。编辑预览与已保存状态 MUST 分开，只有应用服务确认提交并回读后才显示对应权威结果。

#### Scenario: 用户修改与 Agent 更新

- **WHEN** 用户保存一次节点编辑，随后关联聊天中的 Agent 合法拆分该节点
- **THEN** 面板显示同一项目的持久结果与原因，重启后恢复同一节点身份和规划

#### Scenario: 保存失败

- **WHEN** 提交因冲突、权限或持久化失败而未完成
- **THEN** 保留本地编辑并显示具体状态，不将本地预览标为已保存

### Requirement: 一致的完整查询快照

权威快照 MUST 携带项目／资料实例、源代际、格式版本、规划指纹和本机双修订，并基于同一已校验资料基线及本机状态构建。读取期间资料变化 MUST 重新读取，不拼接混合版本；树与其他规划投影 MUST 消费同份快照。

#### Scenario: 快照读取期间资料改变

- **WHEN** 构建快照时发现资料头或被引用正文变化
- **THEN** 丢弃不一致读取并重新核对，不发布混合树与记录

#### Scenario: 多投影一致

- **WHEN** 同一快照被树与用于校验的规划摘要投影读取
- **THEN** 节点身份、状态和规划指纹一致；该验证不要求 R1 交付路线图界面

### Requirement: 先订阅再回读并覆盖已知变化

Client MUST 在读取初始快照前建立变更通知，并在读取期间获知更新时继续回读，直到覆盖已知状态。通知只提示失效，不替代权威数据；资料还 MUST 在打开、工作准备、提交和显式刷新边界重新核查。

#### Scenario: 首次加载遭遇新提交

- **WHEN** 初始快照尚未返回，通知已报告较新的状态修订
- **THEN** Client 继续回读直到覆盖该修订，不停留在初次旧结果

#### Scenario: 文件变化没有通知

- **WHEN** 外部顺序编辑没有产生插件通知，用户显式刷新或准备提交
- **THEN** Host 重新读取并校验文件，不将内存缓存当作磁盘最新事实

### Requirement: 连接和资料代际的乱序保护

Client MUST 按连接代际、资料实例／源代际与本机 `stateRevision` 接受响应；旧连接、旧源及较旧状态不得覆盖新状态。历史回执 MUST 与当前快照分开处理，不回滚界面或跨资料实例比较计数器。

#### Scenario: 旧连接及旧资料源响应迟到

- **WHEN** Client 已重连或切换资料实例，而旧查询才返回
- **THEN** 忽略其对当前界面的覆盖，当前源与本地编辑保持不变

#### Scenario: 较旧快照或历史回执到达

- **WHEN** 已显示较新状态后收到较旧快照或旧操作回执
- **THEN** 可展示历史结果，但当前树不回退到历史版本

### Requirement: 重连和未知状态可恢复

断线重连 MUST 重建通知并回读完整状态，保留未提交编辑及其基线。源冲突、发布待核对或本机存储隔离 MUST 明确可见；旧缓存只能标注未同步，不能显示为当前权威状态或悄悄换 id 重试。

#### Scenario: 断线期间宿主已提交

- **WHEN** 命令在 Host 完成而通知丢失，Client 随后重连
- **THEN** 完整回读显示已提交事实，未提交编辑保留并按各自基线提示核对

#### Scenario: 后端状态未知

- **WHEN** 文件发布未知或本机领域进入隔离
- **THEN** 面板显示待核对／存储不可用，禁止对应写入，保留诊断及可用的本地编辑

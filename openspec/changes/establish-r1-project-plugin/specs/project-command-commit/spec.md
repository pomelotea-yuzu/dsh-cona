## Purpose

为用户和 Agent 的项目操作提供共同的校验、版本核对、持久回执和恢复语义，使文件发布与本机运行记录分离后仍能区分已提交、明确失败和待核对，避免重复创建、陈旧覆盖及对原子性的错误承诺。

## ADDED Requirements

### Requirement: 共用命令与双修订

用户和 Agent 的项目变更 MUST 经同一应用提交序列检查；规划命令 MUST 核对资料实例／源代际、`planVersion` 与本机 `planRevision`。规划变化推进规划和状态修订，单独过程记录／关联／新回执只推进 `stateRevision`；本机修订 MUST 持久延续。

#### Scenario: 保存过程记录后应用规划

- **WHEN** 分析或执行结果已保存，但规划内容和源代际未改变，再提交原规划基线的合法修改
- **THEN** 不因单独状态修订增加而拒绝该规划；提交保留最新过程记录

#### Scenario: 实际规划已变化

- **WHEN** 用户已改变目标后，Agent 按旧规划指纹或规划修订提交
- **THEN** 返回冲突与当前基线，不覆盖手工修改；Client 保留待处理编辑

#### Scenario: 无业务变化及重复查询

- **WHEN** 新命令业务结果不变而首次保存回执，随后查询或重试该命令
- **THEN** 首次仅推进状态修订，纯查询和已完成命令重试均不推进任一修订

### Requirement: 持久幂等与原操作归属

系统 MUST 按原资料实例和操作 id 保留意图／回执，并在新命令的规划冲突判断前查询原记录。相同请求摘要与归属返回原结果；不同参数或归属 MUST 拒绝，且无读取权限者不得取得原结果。回执不得自动淘汰后将旧 id 当新命令执行。

#### Scenario: 已提交但响应丢失

- **WHEN** 命令已完成持久回执但响应丢失，调用者原样重试或重启后查询
- **THEN** 返回原生成 id 和原提交版本，不重复创建，不因原命令推进版本而误报冲突

#### Scenario: 同 id 不同请求或无权查询

- **WHEN** 操作 id 被用于不同业务参数、输入基线或原调用归属，或当前主体无权读取原结果
- **THEN** 拒绝请求，不执行第二次，不泄露原回执正文

#### Scenario: 重连与执行资格分离

- **WHEN** 有读取权限的原主体通过新连接查询已完成回执，但原运行已结束
- **THEN** 可以返回原历史结果，不能据此执行新命令或重新激活旧授权

### Requirement: 意图先于公开发布

系统 MUST 先持久保存原基线、候选指纹、稳定生成 id 及请求归属，再发布公开资料，最后完成私有回执和版本。独立正文 MUST 先写入，再发布资料头引用；未引用正文不算已发布成果。不得将此协议描述为跨介质原子事务。

#### Scenario: 意图保存失败

- **WHEN** 本机意图无法明确持久化
- **THEN** 不开始公开文件发布；无法确定本机状态时进入待核对并停止受影响领域读写

#### Scenario: 正文已写而资料头未发布

- **WHEN** 正文保存后在资料头发布前中断
- **THEN** 权威查询不返回该孤立正文为已发布记录，恢复检查保留原意图和诊断

#### Scenario: 发布后回执前中断

- **WHEN** 候选资料可能已发布但完成回执尚未保存即中断
- **THEN** 不返回明确未提交或重新执行，恢复按意图与实际资料进行核对

### Requirement: 恢复核对与未知状态

恢复 MUST 区分明确完成、可证明未发布、候选内容达成及无法判断。候选内容达成可补齐带恢复来源的回执，但不得伪造作者或外部动作证据。资料分叉、回退或结果不明 MUST 保留待核对并停止该源的新写入；本机 `unknown-state` MUST 停止受影响存储领域读写。

#### Scenario: 当前内容精确对应候选

- **WHEN** 持久意图完整且全部候选发布内容经重新读取和领域校验匹配
- **THEN** 可补齐原 id 的恢复回执及本机版本一次，标记内容经恢复核对，不声称证明了文件外动作或实际作者

#### Scenario: 当前内容再次等于旧基线

- **WHEN** 中断后资料等于原基线，但不能排除曾发布后被 Git 回退
- **THEN** 保持待核对，不断言从未提交，不自动重放或换操作 id

#### Scenario: 文件发布未知或存储隔离

- **WHEN** 文件发布结果不可确定，或本机后端返回 `unknown-state`
- **THEN** 分别停止受影响资料源的新写入或受影响领域的读写，UI 显示待核对，旧缓存仅作未同步展示

### Requirement: 提交前重读与外部变化保护

系统 MUST 在提交中重读资料并核对完整资料基线，保留规划之外的新记录；非法外部内容不得被旧内存覆盖。明确成功的旧回执只代表历史，不得重放到已回退的分支。首版仅承诺一个本地插件写者，外部编辑与插件保存按明确同步边界顺序进行。

#### Scenario: 新增公开记录而规划不变

- **WHEN** 外部顺序编辑新增资料索引，而待提交命令只修改规划
- **THEN** 重新读取并在最新索引上应用合法规划，不用旧整包快照删除新增记录

#### Scenario: Git 回退后重试历史命令

- **WHEN** 已有完成回执的命令被重试，而资料已顺序切换到旧规划
- **THEN** 仅返回可访问的历史回执，不重新应用修改，不把回执版本当当前快照

#### Scenario: 外部资料不合法

- **WHEN** 刷新或提交前发现冲突标记、未知格式、非法树或失效引用
- **THEN** 保留诊断和未提交编辑并停止该源写入，不以缓存覆盖磁盘

### Requirement: 发布结果与通知分离

命令 MUST 仅在资料及私有回执完成后报告明确已提交；通知失败不得撤回或重复执行已提交事实。取消在发布前可明确拒绝，进入可能发布阶段后 MUST 核对真实结果，不能把取消信号直接当作未提交证明。

#### Scenario: 已提交但通知失败

- **WHEN** 文件和回执已完成，但 Client 变更通知发送失败
- **THEN** 命令仍是已提交，可经查询和重连回读取得，不回滚资料或重复操作

#### Scenario: 发布期间取消

- **WHEN** 工具取消信号在文件替换开始后到达
- **THEN** 完成必要核对或返回待核对，保留原操作 id，不无条件报告未提交

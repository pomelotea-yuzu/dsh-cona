## Purpose

以不依赖 DSH 私有数据库的文本协议保存长期项目规划，使不同资料位置使用同一业务模型，其他 Agent 可以直接阅读与校验，并为后续 Git 协作及新机器接续保留稳定身份和清楚的数据边界。

## ADDED Requirements

### Requirement: 三种位置共用公开格式

系统 MUST 支持按项目选择项目目录、DSH 数据目录或自定义目录保存同格式的 UTF-8 JSON／Markdown 资料，并显示实际位置和可获得的 Git 跟踪状态。位置发现不得静默改变已有选择，保存资料不得自动执行 Git 提交或同步。

#### Scenario: 在三种位置保存同一规划

- **WHEN** 分别在三种位置创建和重新打开等价规划
- **THEN** 资料遵循同一 schema，业务读取结果一致，实际位置可见且私有运行存储独立

#### Scenario: 没有代码目录的项目

- **WHEN** 用户选择 DSH 或自定义资料位置并创建逻辑项目
- **THEN** 可以保存规划，不强制先创建代码目录或 Workspace

#### Scenario: 空本机环境首次接入外部 v1 资料

- **WHEN** 全新本机根没有注册、绑定或回执，只取得一份已有合法 v1 公开资料并首次接入
- **THEN** 沿用原项目／节点 id，创建新的本机实例而不重建项目或要求原数据库，不导入旧机器授权和回执；这只验证基础接入，不代替跨机协作试用

### Requirement: 明确的文本权威入口

资料 MUST 提供 README 阅读／编辑入口、版本化 schema 与权威规划文件；独立正文仅在被有效资料头引用时作为已发布记录读取。README 或生成概览不得成为另一份可独立编辑的规划真源；读取外部资料不得自动执行其中的指令、脚本或远程获取。

#### Scenario: 无 DSH 阅读与校验

- **WHEN** 其他 Agent 只获得公开资料、格式说明和独立校验命令
- **THEN** 能读取目标、节点、关系和已发布记录，并校验资料而不加载 DSH、React、Cordis 或模型服务

#### Scenario: 孤立正文和恶意资料指令

- **WHEN** 目录中存在未被资料头引用的正文或正文要求自动执行脚本
- **THEN** 不把孤立正文显示为已发布成果，也不因接入资料而执行脚本

### Requirement: 最小稳定规划与领域校验

项目和节点 MUST 使用稳定 id；树归属、展示顺序、执行依赖、目标、完成条件与工作状态 MUST 明确表达。程序 MUST 校验身份唯一、父子有效性、树和依赖无环及引用合法性；批量拆分 MUST 整体接受或整体拒绝，不能发布部分结构。

#### Scenario: 编辑与拆分节点

- **WHEN** 用户或 Agent 合法修改目标，或将一个节点拆为明确的子节点
- **THEN** 原节点身份保留，新节点获得新 id，顺序明确，修改原因可查询

#### Scenario: 非法树或依赖

- **WHEN** 输入存在重复 id、缺失父节点、树环、依赖环或非法引用
- **THEN** 返回领域诊断并拒绝发布，不因 JSON 可解析而接受

#### Scenario: 过程结束与节点完成分离

- **WHEN** 保存执行结果或所有子节点变为已完成
- **THEN** 不自动把父节点标为已完成；显式完成命令仍核对自身条件及所需证据

### Requirement: 公开资料不得承载本机执行资格

系统 MUST 将实际 Session／Workspace、机器绝对路径、活动授权、私有草稿和意图／回执保存在独立本机存储。公开资料只发布用户选定的正文与来源；作者标记、外部验证或导入的授权文字不得成为本机权限或复测证据。

#### Scenario: 检查三种位置的公开资料

- **WHEN** 保存项目、关联本机聊天并执行一次 Agent 命令
- **THEN** 公开资料不出现实际会话身份、机器绝对路径或私有回执，且本机仍能查询这些关联

#### Scenario: 接入带外部结果的资料

- **WHEN** 读取含作者、外部通过结论或授权文字的公开记录
- **THEN** 保留来源与适用范围，不恢复原机器写权限，不将外部通过显示为本机复测通过

### Requirement: 规划指纹与格式兼容

读取方 MUST 按公开的 v1-plan 字节规则重新计算 `planVersion`，独立实现 MUST 通过随格式分发的一致性向量；覆盖实际规划而排除排版、私有运行数据和过程记录。未知格式／字段 MUST 停止写入，不静默降级；本机计数器不得作为跨副本版本顺序。

#### Scenario: 排版与过程记录变化

- **WHEN** 只改变对象键顺序、JSON 缩进，或新增一条过程记录
- **THEN** 规划指纹保持不变；节点展示顺序或目标发生变化时指纹改变

#### Scenario: 伪造指纹或未知格式

- **WHEN** 文件自报指纹与实际内容不符，或 schema／字段不受支持
- **THEN** 返回具体诊断并禁止覆盖原文件，不信任自报指纹继续写入

#### Scenario: 第二份独立实现复算

- **WHEN** 不依赖 DSH 或主实现序列化函数的第二份实现读取规范正文和一致性向量
- **THEN** 对中文、转义、嵌套键、集合白名单、整数与 null 等得到相同 canonical UTF-8 字节和规划指纹，不以本机 JSON 默认选项替代协议

### Requirement: 资料实例与路径范围

本机绑定 MUST 同时区分稳定项目 id 和独立资料实例，旧工作副本的绑定与回执不得用于另一实例。文件访问 MUST 解析用户选择的根与声明的相对引用，检查越界、符号链接及实际路径范围，不依赖当前进程目录或本机路径分隔符。

#### Scenario: 同项目的两个目录

- **WHEN** 同一项目资料被复制到两个不同工作副本并分别接入
- **THEN** 稳定项目／节点 id 相同，本机实例、聊天绑定和回执隔离

#### Scenario: 引用逃逸或符号链接越界

- **WHEN** 资料路径包含越界相对引用，或符号链接指向允许范围之外
- **THEN** 拒绝对应访问并保留诊断，不读取或覆盖范围外文件

## Purpose

使插件从首个面板开始完整支持简体中文与英文，跟随 DSH 已有语言选择并为其他宿主语言回退英文，同时保持用户项目原文、稳定协议身份和时间语义不受界面语言切换影响。

## ADDED Requirements

### Requirement: 完整中英界面与英文回退

插件 MUST 使用宿主 locale 选择，为已交付功能的导航、状态、按钮、错误、空态、弹窗、工具提示及无障碍文案提供完整中英资源。其他宿主语言 MUST 回退英文，不修改宿主语言偏好；插件元信息 MUST 提供可解析的中英资源并随包安装。

#### Scenario: 中文与英文安装包

- **WHEN** 从预构建包启动插件并分别选择简体中文和英文
- **THEN** 已交付界面及插件管理页名称／说明使用对应语言，没有漏 key 或依赖开发目录的资源

#### Scenario: 其他宿主语言

- **WHEN** DSH 选择日语等插件未支持语言
- **THEN** 插件使用英文，DSH 自身继续保留原语言选择

### Requirement: 运行中切换与生命周期

切换宿主语言 MUST 更新已打开面板及导航等固定文案，保留节点选择、未提交输入和连接状态。重启 MUST 读取宿主持久选择；卸载／重载 MUST 清理或恢复资源且不重复注册。

#### Scenario: 编辑过程中切换

- **WHEN** 用户在中文面板编辑尚未提交的节点，再切换英文
- **THEN** 面板和导航固定文案更新，输入、选中节点与编辑基线保持原样

#### Scenario: 重启及重载

- **WHEN** 宿主已保存英文选择并重启，随后重载插件
- **THEN** 插件仍使用英文，不出现重复字典或卸载后的残留注册

### Requirement: 界面语言与业务内容隔离

语言切换 MUST NOT 翻译或覆盖用户名称、目标、完成条件、原因、记录与聊天，不得改变稳定 id、状态码、规划指纹或项目修订。Host MUST 返回稳定业务码及结构化参数，由 Client 翻译；UI locale 不得单独改变 Agent 回答语言或执行授权。

#### Scenario: 中文项目置于英文界面

- **WHEN** 已保存的中文项目切换为英文界面
- **THEN** 项目正文保持中文，状态标签和错误按英文展示，业务资料与修订不变

#### Scenario: Host 返回业务错误

- **WHEN** 相同命令在不同语言 Client 中遇到过期规划或存储未知
- **THEN** Host 业务码和参数一致，各 Client 显示对应文案，未知错误有可诊断的通用提示

### Requirement: 资源一致性与时间显示

中英资源 MUST 使用对应 key 与命名占位符，数量表达和数字／时间格式 MUST 明确处理，英文长文案应可用。若 R1 展示时间，实际时间与目标日历值 MUST 区分，切换语言不能移动日期或触发排期；文档双语门禁不得代替 UI 验收。

#### Scenario: 资源缺失或占位符错误

- **WHEN** 一份语言资源缺 key、占位符不一致或固定界面文字绕过字典
- **THEN** 产品资源检查报告失败，不因宿主 common 回退或文档门禁通过而算完整支持

#### Scenario: 长文本及时间切换

- **WHEN** 显示英文错误长文本、不同数量及有明确时区的实际记录时间，并切换语言
- **THEN** 文案可阅读且数量／时间含义一致，不截掉必要操作；已有目标日期值不被改写

## 关键决定

1. **参数不含身份授权字段**：`workRunId`／`bindingVersion`／`agentId`／`sessionId` 等身份与授权字段一律不接受为参数；出现即 `operation-mismatch` 拒绝（"身份字段出现在参数中即拒绝"）。绑定只能从真实 `ToolRunContext` 捕获（`exec.agent.id` → 同会话唯一 active WorkRun，6.2 身份键规则），与 2.4 实测结论一致。
2. **agent-work 上下文走同一命令服务**：适配器不复制准入逻辑，捕获后以 `{ kind: 'agent-work', workRunId, bindingVersion, instanceId }` 调 `commandService.execute`／`appendRecord`／`getReceipt`——目标⊆范围、动作∈允许集、基线核对、提交后绑定版本推进全部复用 6.2 已测路径。
3. **参数层先行校验**：`project_apply` 的 command.type 非法时指向 `project_record`（记录追加不走 apply）；缺基线参数（expectedPlanVersion／expectedPlanRevision／sourceEpoch）在参数层拒绝，不进命令服务。`project_record` 的 sources.repositoryId 必须是资料头声明的仓库 id，命令服务层校验（非凭空字符串）。
4. **receipt 按 origin 隔离**：`project_receipt` 只收 `operationId`；命令服务 `getReceipt` 核对原操作归属，其他 WorkRun／伪造归属不可读正文（`forbidden`／`not-found`）。命中原操作时输出带 `replayed: true`；首次提交结果不带。
5. **输出 schema**：每个工具声明 `additionalProperties: false` 的 JSON schema；committed／rejected／pending 共用 `COMMITTED_SCHEMA`（可选字段按形态缺省），read 用独立 schema。`pending-reconciliation` 语义在协议文档显式标注：不能当失败换 id 重试。

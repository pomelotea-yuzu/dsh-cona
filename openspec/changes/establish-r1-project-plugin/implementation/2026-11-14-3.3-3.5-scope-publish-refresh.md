## 3.3 平台结果（实际观察，不推断）

| 场景 | macOS（本机 APFS，大小写不敏感） | Linux／Windows |
|---|---|---|
| 越界（`../`、绝对、盘符、反斜杠、NUL、空段、`.`／`..`、`%2e%2e`） | 全部以 `scope-path-*` 拒绝 | untested |
| 文件 symlink／中间段 symlink | `scope-symlink`，不跟随 | untested |
| 多硬链接写目标 | `scope-hardlink`（目录不计，只有常规文件触发） | untested |
| 非常规文件（FIFO） | `scope-not-regular-file` | untested |
| 权限（`chmod 000` 目录） | `scope-permission-denied`；以 root 运行时跳过（该结果不具代表性） | untested |
| 同目录仅大小写不同的两个文件 | **无法并存**（写入第二个会命中同一文件），`findCaseConflicts` 返回 0 组 | untested；大小写敏感平台应报 1 组 |

测试对大小写场景按实际平台分支断言：能并存则要求报告冲突，不能并存则要求 0 组，不假定文件系统敏感度。

## 3.4 三态与注入矩阵

| 注入点 | 资料头结果 | 观察 |
|---|---|---|
| `beforeTempWrite`（写入前） | `not-published`（stage=temp） | 原文件字节不变，无临时文件残留 |
| `beforeRename`（rename 前） | `not-published`（stage=rename） | 原文件不变，临时文件被清理 |
| `afterRename`（rename 后） | `unknown`（stage=rename） | 文件**已**替换为新内容——unknown 不代表未提交 |
| `beforeReread`（回读前） | `unknown`（stage=reread） | 同上，无法确认持久结果 |
| 回读前外部改写 | `unknown`（stage=reread） | 回读字节与写入不一致 |
| 正常 | `published`（stage=done） | 序列化内容一致，无临时文件残留 |

正文与聚合：

| 操作 | 结果 |
|---|---|
| 首次写正文 | `written`，路径 `records/<recordId>/<contentHash-hex>.md` |
| 重复写同字节 | `already-present`（幂等，不重写） |
| 同路径已有不同字节 | `conflict`，原正文保留 |
| 传入字节与 `contentHash` 不符 | `conflict`（不写入） |
| 正文已写、头未引用 | `validate.js check` 报 `orphan-body`；发布引用后通过 |
| 聚合替换注入写入前／rename 后 | `not-saved`／`unknown-state` |

**断电保证限制**（已写入 README 与 BOUNDARIES）：只有同目录临时文件 + rename + 回读，没有目录 fsync，也不跨目录成事务；进程被强杀或突然断电时的持久性未验证，不宣称断电安全。

## 3.5 刷新语义

- 基线 = 头字节 SHA-256 + `planVersion` + 每条引用正文的实际哈希；`planVersion` 不含排版与记录，头字节哈希补上这两块。
- `changes`：`initial`、`headChanged`、`planVersionChanged`、`recordsAdded／Removed／Changed`。
- 始终重读磁盘，不复用旧缓存；外部顺序追加记录后刷新能接纳新记录，再次刷新不重复算作新增。
- 失败一律不推进源代际、不改既有基线：未知 schema（`invalid-schema-version`）、冲突标记（`source-conflict-markers`）、非法树（`parent-not-found`）、正文哈希不符（`body-hash-mismatch`）、同路径身份变化（`source-identity-changed`）。
- 外部编辑流程：暂停写入 → `validate.js check` → `local refresh` → 继续；不自动合并、不自动重放。

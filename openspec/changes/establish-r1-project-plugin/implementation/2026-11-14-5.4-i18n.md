## 检查规则（`check-locale.mjs`）

| 规则 | 失败示例 |
|---|---|
| 中英 key 集合一致 | en 缺 `saveStatusSaved` → `缺少 key "saveStatusSaved"`（实测 exit 1） |
| 同名占位符一致 | zh `共 {n} 条` vs en `Total items` → `占位符不一致` |
| 文案非空 | `"  "` → `文案为空` |
| 不装业务值 | 含 `sha256:`、UUID、绝对路径 → 拒绝（稳定码与项目原文不入字典） |
| 包元信息齐全 | `locale/*.json` 缺 `meta.description` → 拒绝 |
| 自测反例 | `--selftest`：6 个反例必须被拒、1 个正例必须通过 |

## 关键决定

1. **字典用 JSON 而不写 TS 对象**：检查脚本可直接读取，不需要解析 TS；`resolveJsonModule` + import attributes 让类型与运行都成立。
2. **中文为 key 源**：`LocaleKey = keyof typeof zh`，en 用 `Record<LocaleKey,string>`，缺 key 在编译期就报错。
3. **文案与稳定码分开**：控制器只产出 `status` + `code` + 宿主原文，界面文案全部在字典里——「固定文案检查」才可能成立（字典里不出现指纹、UUID、路径）。
4. **元信息与界面字典分开**：`locale/*.json` 是包元信息（市场展示），不参与 `t`，避免两套 key 混用。

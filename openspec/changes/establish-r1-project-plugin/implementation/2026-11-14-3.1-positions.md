## 关键决定（与 design 的偏差）

1. **创建即生成一个根节点**。design §5 的「空规划哨兵」是命令层概念（无权威头），不是空树文件；1.2 落地的 v1 校验有 `root-count`（至少一个 `parentId: null` 的根），空 `nodes` 不是合法资料。因此 `create` 写入一个承载项目标题／目标的根节点，`rootNodeId` 可由命令层注入以保持 4.1 的幂等。
2. **接入是纯读取**。`attach` 只校验并返回原 `project.id`、节点 id、`planVersion` 与记录数，返回 `instance.registry: "pending-3.2"` 明示本机实例尚未持久化；不在资料根写任何本机文件。
3. **位置语义与应用语义分离**。种类与相对分段在 application，绝对路径与分隔符在 adapters；不做「发现 Git 仓库就换位置」，也不把相对路径按当前进程目录补全。
4. **Git 只读**。只调用 `rev-parse`／`ls-files`／`check-ignore`／`status --porcelain`，不 add／commit／checkout／config；探测失败一律 `unknown`，超时与 `git` 不可用分别标 `probe-failed`／`git-unavailable`。
5. **写入先临时文件再 rename，并回读字节**。3.1 只有 `ok/failed`；`not-published／published／unknown` 三态与中断注入留 3.4。

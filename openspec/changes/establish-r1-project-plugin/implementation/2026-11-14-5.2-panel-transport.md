## Remote 契约（已实现部分）

| 方法 | 请求（gateway `args` 按参数名） | 结果 |
|---|---|---|
| `conaProject.status` | `{}` | `ConaProjectStatus`：`configured／instanceId／projectId／sourceKind／sourceDisplay／localRootDisplay／created／error` |
| `conaProject.snapshot` | `{request: {connectionGeneration, minStateRevision?}}` | `SnapshotResult`（与 5.1 应用层同形） |
| `conaProject.execute` | `{request: {operationId, command, expectedPlanVersion, expectedPlanRevision, sourceEpoch?, instanceId?, projectId?}}` | `CommandResult`（committed／rejected／pending-reconciliation） |

准入：`ctx.invocation` 必须存在、`invocation.peer.principal.kind === 'owner'`、`principalOf(invocation) === undefined`；其余返回 `rejected(forbidden)`，不降级、不按业务参数授权。`instanceId／projectId` 若给出必须与已配置实例一致。

未实现：`follow`（需要宿主 mux 流与 Client 订阅配套，随面板一起接）。

## 配置（用户显式选择）

profile 的 `cordis.patch.yml`：

```yaml
- id: cona-project
  config:
    projectRoot: /abs/path/to/project-root
    localDataRoot: /abs/path/to/local-root
```

`projectRoot` 缺省即“未配置”：宿主正常启动，`status` 返回 `configured:false` + `binding-expired` 说明，面板据此显示引导。`localDataRoot` 缺省为 `<DSH_HOME>/data/dsh-cona/local`（design §2 默认）。

启动期打开顺序：读头 + 全部正文复核（`readSourceBaseline`）→ 按资料 `projectId` 登记或复用实例 → 读本机最近观察；**只有缺失或与磁盘不一致时才刷新**，避免每次启动都推进源代际（代际是订阅侧替换边界）。任一步失败返回稳定码，不建立半可用实例、不改资料头。

## 关键决定

1. **配置即选择**：R1 面板不做位置选择 UI，资料根由 profile 配置显式给出；插件不猜目录、不扫描磁盘。
2. **启动期不无条件刷新**：每次启动都 refresh 会让源代际无限增长，而代际是订阅侧的替换边界；改为“磁盘变化才刷新”。
3. **边界类型走公开子路径**：Typert 生成器要求 Remote 边界类型从 `./types` 导出；同时 `ProjectSnapshot.local` 从 `unknown[]` 改为计数，避免“unconstrained unknown data”。
4. **失败不阻塞宿主**：配置错误或资料不合法只让 `status` 带错，宿主与诊断服务照常启动——面板可显示原因，而不是整插件不加载。
5. **网关 args 形状**：HTTP 载体要求 `payload.args` 是“一个plain-object 字段”，且字段名与参数名一致（`request`）；这是 5.3 客户端调用必须遵守的线格式。

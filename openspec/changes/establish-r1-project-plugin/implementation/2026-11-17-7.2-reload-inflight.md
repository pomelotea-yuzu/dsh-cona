## H 层：无重复注册 + 资料/回执一致

驱动 `reload-driver.mjs` 一次运行内：启动宿主→probe→文件基线→`dsh plugin remove`→文件基线比对→`dsh plugin add <同一 tarball>`→再启动→probe→文件基线比对→Client 重连复核。宿主用 `spawn` 管理、端口 0 动态分配。

- **重复注册**：安装态与重装态的 apply 日志均只有一条 `host apply`、一条 `work event observers attached`、一条 `project tools registered`；`__DSH_BOOT__` 中 `dsh-cona-project` 恰 1 entry；侧栏「项目/Project」入口中英各恰 1 个；两 locale 面板无原始字典 key，pageerror 0。证据 `probe-before.json`／`probe-after.json`（各 11/11）。
- **资料/回执不删**：卸载后与重装前，`project.json`／`registry.json`／`state.json` 的 SHA-256 与基线逐字节一致（例：`project.json` = `68423d1f…eeec15a`）。证据 `baseline-before/afterremove/after.json`、`reload-result.json`。
- **Client 重连**：重装后 owner 经 `conaProject/follow` 建订阅（ready + connectionGeneration）→带代际读 `snapshot`（避免 stale-connection）→`followClose`→重新 `follow`（新句柄、代际递增）→回读；planVersion/planRevision/节点数/记录数与文件基线一致。证据 `reconnect-result.json`（8/8，代际 3→4）。
- **CLI 行为**：`dsh plugin remove` 因依赖先被移除，pnpm 报 `ERR_PNPM_CANNOT_REMOVE_MISSING_DEPS`（exit 非 0），但实际卸载已生效；`add` 重装恢复完整配置。沿用 7.1 记录的同一 CLI 行为，不作为产品失败。

| 场景 | 注入点 | 观察 |

## 关键决定与边界

1. **分层取证**：真实宿主进程无法精确注入 rename 前后崩溃点，第三节只在文件后端 F 层注入；前两节在真实宿主 H 层 + 文件字节取证，不把 F 层结论冒充 H 层。
2. **字典英文判定**：英文 context 的登录引导弹窗遮罩在部分 boot 下拦截点击，面板未必点开；字典英文回退以 boot 页已渲染的英文导航 + 无原始 key + pageerror 0 证明（运行中切换与重启选择由 5.5/V35/V36 覆盖，不在此重复）。此为本轮探针的观察口径，不是能力缺口。
3. **代际权威**：snapshot 必须带 `follow` 返回的 `connectionGeneration`，否则被 `stale-connection` 拒绝——这正是 5.3/V32 代际保护，不是缺陷。
4. **未做（不标 pass）**：断电安全（无目录 fsync）、真实 Liveshare non-owner 多身份、R2 Git 跨副本协作、R6 跨环境试用；沿用完成判据的既定边界。

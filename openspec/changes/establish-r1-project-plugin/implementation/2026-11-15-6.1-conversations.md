## 关键决定

1. **意图-结果持久化**：createChat／claimChat 先把意图落盘（pending），再调宿主，以宿主**实际返回** sessionId 落链接并标 linked；宿主异常＝结果未知→意图标 `unknown` 并保留，`reconcileChats` 只列候选（cwd 一致的空白会话且晚于意图登记时间），**绝不自动再建第二个聊天**，认领必须显式 `claimChat`。
2. **复用语义是「命名复用」**：实测发现宿主 `session.create` 不带 sessionId 时**总是新建**（`createMinted`），文档里的 "reusing the named blank Session" 指显式命名。适配器因此实现：list → 找 cwd 一致的空白会话 → `create({ sessionId: blank, cwd })` → 以返回 id 为准（复用失败宿主会 mint 新 id，插件照实记录）。
3. **cwd 绑定资料根**：新建会话带 `cwd = sourceRoot`——既是复用匹配键，也让冷会话在宿主重启后仍出现在 `session/list`（无 cwd 的冷会话会被宿主 list 跳过，导致 visible 误报失效——首轮实测发现）。
4. **linkChat 也核查可见性**（首轮实测抓出的缺陷）：不在宿主列表的会话一律 `session-not-visible` 拒绝，不写入链接——对齐 spec「失效或属于另一资料实例的会话不得被静默认领」。
5. **死锁修复**：settleSession 在队列任务内嵌套 `queue.run` 标记意图→永久阻塞；改为就地标记。
6. 链接只表达背景关系，不构成写授权（写绑定属 6.2）；单纯打开不激活绑定。
7. unknown-state：聚合替换结果未知时与命令层一致进隔离，聊天读写停止。

## 规则与取舍

- **逻辑仓库只来自本机登记映射**：`repositoryId → absolutePath`。插件配置的 `workCopyRoots` 仍只服务 R2 的代码观察，不合成分析仓库名；未登记映射时分析入口应显示不可用（第 7 组 UI）。
- **冻结身份**：`mappingHash = sha256([instanceId, repositoryId, realpath])`。仓库根或映射目标变化、映射被移除、资料源代际变化都拒绝旧选择；`updatedAt` 只展示，不参与身份，重登记同一路径不会误伤。
- **观察**：按 UTF-16 码元排序路径；`.git` 内部、符号链接、非普通文件记为排除项；只有「未跟踪且被 Git 忽略」的路径排除，已跟踪文件即使命中 ignore 规则仍纳入。非 Git 目录仍可观察，Git 状态记为 unavailable。指纹按 `path\0kind\0hash` 的有序条目计算，输入次序无关；同一 HEAD 下内容增删改会改变指纹。
- **限额**：扫描项数、单文件字节、单轮读取字节、单次读取行数集中定义并可注入更小值。扫描截断、单文件超限、不可读、非文本、特殊文件都返回稳定原因；部分结果保留，`complete=false` 表示覆盖不完整。
- **读取**：只按整行交付；凭证含相对路径、整份文件哈希、交付片段哈希、起止行、交付字节与截断标志。截断只覆盖实际交付片段；首行放不进预算则拒绝而不是交付半行。读取前后做两次读取、重新解析路径并比较 `ino/size/mtime`，任一变化都拒绝且不发凭证。
- **引用复核**：先核对映射身份与范围归属，再读当前整份哈希；内容变化返回 `content-changed` 与当前哈希，删除返回 `missing`，换成链接／不可读返回 `inaccessible`，映射变化返回 `mapping-changed`。不把当前正文自动当作历史引用。

## 证据

`packages/project-plugin/test/analysis-scope.test.ts`（8 项，全部通过）：

1. 3.1 双工作副本：两个映射各自可选、根不串；映射移动、资料代际变化、映射移除均拒绝旧选择；同一服务内映射更新也立即失效。
2. 3.2 预览：仓库根／目录／文件三种范围；同前缀兄弟目录不混入；`..`、绝对路径、最终与中间段符号链接、失效映射、目录当文件均拒绝。
3. 3.3 枚举：`.git` 与忽略未跟踪排除、已跟踪的忽略文件仍纳入；同一 HEAD 下修改、增、删改变指纹；两棵同布局不同创建顺序的树指纹相同。
4. 3.4 限额：扫描截断保留部分条目；单文件超限记 `hash:null` 和原因；读取预算跨调用累计并截断；首行超预算拒绝；非文本拒绝；FIFO 记特殊文件排除；无权限文件记缺口（root 跳过）。
5. 3.5 读取：目录预览无凭证；整文件与行范围凭证；预算截断只计交付片段；目录／范围外读取拒绝。
6. 3.5 读取期间内容变化（注入两次不同字节）→ `analysis-file-changed`，不发凭证。
7. 3.5 读取期间路径换成符号链接 → `analysis-file-changed`，不发凭证。
8. 3.5 引用复核：当前、内容变化、删除、替换为链接、映射变化、范围外。

# R3 项目分析与复盘

作者为 Codex（本 change 的编写会话）。2026-11-25，GLM 复核通过，DSH 技术复核通过并列出提交前修订项。作者已逐条处理，实施待安排。 [外部审阅](review.md) · [作者回应](review-response.md)

本 change 属于 R3 首切片，涵盖项目分析与复盘，同时修复 R2 归档后两条远程 CI 的共同测试故障。交付按 [实施任务](tasks.md) 的 8 组、32 项推进，分别对应 17 条产品场景和 3 条 CI 验收。

## Why

接入已有代码项目和开发中复盘需要同一个分析入口。用户需要知道 Agent 实际看了什么、结论依据是什么，以及工作副本或规划改变后哪些建议需要重新核对。R2 已提供项目概览和实例聊天，可在这两个入口上完成首次分析到复盘的闭环。 [产品设计](../../../../docs/product/2026-11-11-project-management-design.md#接入已有项目与再次分析) · [R3 路线图](../../../../docs/engineering/2026-11-12-plugin-development-roadmap.md#r3项目分析与自主规划)

2026-11-24，GitHub Actions #19 和 Gitee Go 都在 `pnpm check:ci` 的同一条真实 Git 合并冲突测试失败。测试初始化临时库时继承默认分支名，随后写死 `checkout main`，导致两边均在进入冲突断言前退出。本 change 先修复夹具，再分别核对两个远程门禁。 [日志与复现](design.md#先修复双远程-ci)

## What Changes

- 从项目概览发起专门的分析聊天，确认本机实例、工作副本与分析范围，并记录开始时的代码和规划基线。一轮选择一个已映射仓库和一个文件或目录。首次分析和复盘共用入口，各轮有独立 Session。
- 使用固定宿主的专用原生工具执行路径，允许读取已捕获的规划背景和同实例已校验的验证记录索引及正文、列举和读取选定范围内的文件，以及保存本轮私有报告。分析完成或中断后，原 Session 供历史回看。报告展示实际已读的文件或文本片段、未读及无法读取的范围，区分含依据的事实、推断及建议。
- 比较报告依据与当前规划、受检内容及资料来源。相关代码的未提交变化也纳入检查。依据变更或无法核对时，保留历史报告并显示对应状态。
- 在共享测试夹具中明确初始分支，保留真实 Git 冲突与 `git-unmerged` 诊断断言。以 `master` 和 `main` 两种默认配置回归，并以 GitHub Actions 和 Gitee Go 的完整门禁结果确认修复。

## Capabilities

### New Capabilities

- `project-analysis` 提供有明确范围的项目分析、私有报告、来源回看和复盘。

### Modified Capabilities

本机分析沿用现有会话、实例隔离与可信调用约束。独立分析绑定与本机报告由 `project-analysis` 定义。CI 修复属于测试夹具维护。

## Impact

- 项目概览新增分析入口、历史报告与依据状态，中英界面随固定宿主 DSH `0.2.2-rc.2` 验证。
- 本切片的报告保存在本机数据域。可移植摘要发布、从分析建议应用规划以及 OpenSpec 工件专用关联留给后续 change。
- 先修复 CI 夹具并验证固定宿主的 Session／工具接点，再依次交付分析闭环和复盘。用一个已有代码项目贯通发起、范围内阅读、证据报告、重启回看和变更后复盘。双远程各自记录真实门禁结果。 [技术设计](design.md) · [验证矩阵](validation-matrix.md)

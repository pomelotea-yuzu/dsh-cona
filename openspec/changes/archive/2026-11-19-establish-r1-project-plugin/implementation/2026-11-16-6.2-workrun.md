## 关键决定

1. **消息准入映射按 2.4 实测结论建模**：排队（`agent/inbox/spliced target=next-turn`）只登记 `queuedAt`，不改状态不建绑定；消费（`removed`＋user/message 或 pre-step）首次唯一匹配才启动 WorkRun。匹配条件＝意图 `awaiting-message` ＋ `expectedRpcId` 相等 ＋（若意图声明 sessionId 则必须一致）＋ turn 为有效整数 ＋ `agentPresent`。rpcId 不是授权令牌：工具提交时还核对真实 ToolRunContext 的 `agent.id`＝会话（2.4：agentId＝SessionId）。
2. **同会话最多一个生效绑定**：ToolRunContext 没有 turn 字段（2.4 实测），绑定身份键中的 turn 取自消费事件并在运行中记录；归属唯一性以「会话级单活跃运行」保证——同会话已有生效绑定时另一消息消费返回 `deferred`（意图保留待执行），对齐 spec「B 保留为待执行意图，直到可信边界显式建立 B 的新绑定」（重新 startWork 换新 rpcId）。
3. **归属不唯一两类拒绝**：同一 rpcId 匹配多个待执行意图 → 全部 `blocked`（ambiguous-intent）；`agentPresent=false` → `blocked`（agent-missing）。均不建立绑定并留 blockedReason（2.4b(i)）。
4. **绑定版本推进**：仅本运行规划命令（impact=plan）成功后 `bindingVersion+1` 且只更新 acceptedBaseline；targets／allowedActions 永不自动扩大。bump 失败不撤回提交，旧版本捕获随后被拒绝（安全失败）。新增根级节点（parentId=null）不在任何节点目标集合内，工具准入直接拒绝。
5. **重启失效**：授权要求 `run.bootGeneration === 当前代际`；重启后旧代际 active 运行 `effective=false`（历史保留），`startWork` 不复活已 active 意图，需新的真实请求边界。
6. **私有授权只在本地聚合**：`workIntents`／`workRuns` 是本机聚合字段；公开资料头（协议 schema）无任何工作状态；外部 v1 导入的新实例聚合为空授权——测试断言导入后 captureBinding 一律 binding-expired。
7. **两条入口判据独立**：remote-owner 不走 WorkAdmissionPort；agent-work 不看 invocation（集成测试断言 owner 直改范围外节点仍按 owner 规则提交，agent-work 同一目标被拒）。

## 已知边界

- **真实宿主复测余项**：workObserve 目前由 owner Remote 转发事件（诊断 harness 可驱动）；插件自动订阅宿主 inbox／pre-step 事件面在 rc.2 无静态类型可依，随 6.3 真实工具入口与 6.5 生命周期段落地后用真实 Agent 复测（消费事件 + 工具捕获端到端）。V25b(i) 的准入规则已实现并单测证明，但真实宿主复测不计入本次 pass。

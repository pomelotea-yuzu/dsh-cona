## 前置：接线依据（真实探路确认，非类型猜测）

依赖里的 `dsh-agent`／`dsh-session` 事件类型是 merge-extensible，静态 grep 取不到 `rpcId`。用真实宿主发一条带自定义 requestId 的 prompt，dump `session/page` 事件确认：

- `agent/inbox/spliced` 的 `data.inserted[].source.rpcId` = prompt 的 `requestId`；`source.kind === 'user'` 才带 rpcId。
- 消费点：`removedCount ≥ 1` 的 spliced 随后跟 `user/message`，其 `data.source.rpcId` 同源；`turn/start`／`turn/end` 的 `data.turn` 对应 turn 号。
- `agent/inbox/claimed`（cordis 事件）payload 带 `agent`（`agent.id`＝SessionId）、`message`、`turn`，可直接映射 consumed 且 `agentPresent=true`。
- `turn/end` 的 `data.reason.kind` 有 `completed`／`aborted`／`error` 等；仅 `completed` 记完成，其余按 aborted（保守）。

## 关键决定

1. **不引入 dsh-agent/session 静态类型**：`ctx.on` 按 cordis 运行时签名 `on(string, listener)` 窄化使用，事件 payload 用最小结构读取。沿用 `index.ts`／`project-tools.ts` 的既定做法——这些 `.d.ts` 与 vendored protocol 在同一 face program 会触发 `merged interface contains a declaration outside this face`。事件名取固定宿主 `0.2.2-rc.2` 已确认词表。
2. **预告不作终态、取消与终态分离**（design §7、6.5 决定 1）：`agent/turn-stopping` 只有 `signal.aborted===true` 才转 `observeCancel`（停止新写准入、run 仍 active 等真实终态）；真正结束只由 `turn/end` 确认。工具侧 `project-tools.maybeObserveAbort` 的 abort 观测保留。
3. **观察是后台副作用**：`getRuntime()` 未配置／隔离、或 `observe*` 失败都吞掉，不影响宿主事件流；WorkService 内部对无匹配意图返回 `unmatched`、对 agent 缺失／归属不唯一记 `blocked`。不把观察失败当产品成功，也不传播未处理拒绝。
4. **单实例装配**：事件转到当前装配实例的 WorkService，由其按 rpcId／sessionId／turn 匹配意图。R1 单实例；多实例事件路由属 R2。
5. **演示不伪造身份**：owner Remote 只做 `workPrepare`／`workStart`（登记范围与期望 rpcId，等同 UI"开始工作"确认）；写入全部由真实模型在 session 中调 `project_read`／`project_apply`／`project_record` 完成。没有用 owner `execute` 或手工工具调用替代。

## 向量与期望值

- v2 正向向量：`plan-v2-milestones`（两个里程碑、三项交付）、`plan-v2-milestones-permuted`（里程碑与交付顺序整体反转，canonical 与指纹必须相同）、`plan-v2-record-added`（仅追加未引用过程记录，指纹不变）、`plan-v2-empty-roadmap`（空里程碑集合，版本变化后指纹不同于 v1）。
- 拒绝向量：缺里程碑节点、重复里程碑、自交付、重复交付、交付哈希失配、交付记录缺失、里程碑未知字段、不支持版本、v1 带 roadmap、v2 缺 roadmap。
- 期望值由一次性工具在主实现上生成、随后冻结；测试同时用独立第二实现复算 canonical 字节与散列，并核对两条实现的输出完全一致（不是“各自和自己的期望比”）。

## 测试（`test/roadmap-format.test.ts`，27 项，全绿）

1. v2 样例自校验：`schemaVersion 2`、roadmap 结构有效、自报指纹等于重算值。
2. v1 指纹保持原值（`sha256:10001308…`），并断言 v1 文档不带 `roadmap`。
3. v2 向量协议标识与正/负向量数量。
4. 每条正向向量：主实现 canonical/散列命中；独立实现复算并字节一致。
5. 每条拒绝向量：两实现都必须拒绝。
6. 集合重排：permuted 与 base 的 canonical 文本逐字节相同，而原始 JSON 确实不同。
7. 过程记录追加不改变规划指纹。
8. 诊断：缺节点／重复里程碑／重复交付／哈希失配／未知字段／v2 缺 roadmap／不支持版本／v1 带 roadmap。
9. 伪造指纹：`plan-version-mismatch`。
10. 普通变换（update-node／set-node-status／move-node）保留 roadmap、变换后仍通过完整校验、指纹按实际变化推进；原位无变化保持指纹与 roadmap。
11. 独立校验 CLI：`check-file` 对 v2 样例通过；篡改 `planVersion` 后退出码非零且输出 `plan-version-mismatch`。

## 已知边界

- 既有资料根不会自动补发 v2 工件（`COPYFILE_EXCL` 不覆盖）；新根会同时落 v1／v2。启用 v2 时是否补发协议文件随 4.2 的转换流程决定。
- `roadmap` 的“待核对”语义（来源失效但保留引用）属 4.3；本批只做形状与引用存在性校验，悬空交付直接拒绝。
- 里程碑与完成证据、`complete-milestone`、`set-milestone` 等命令属 4.3；本批不做里程碑编辑入口。
- v2 与 v1 的普通编辑共用同一命令路径；4.5 会逐命令（含模板插入、分组／合并／复制、撤销重做）补 v2 保留的穷举比对。

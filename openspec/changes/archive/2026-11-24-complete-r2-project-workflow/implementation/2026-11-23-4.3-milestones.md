# 4.3 管理里程碑及交付引用（2026-11-23）

## 范围与结论

里程碑以稳定节点为身份，交付引用（节点或哈希精确的成果记录）可跨分支、可共享；只有显式
`complete-milestone` 能在一次发布里把节点置 `done`、追加完成记录并推进指纹。普通状态命令
不能完成里程碑，已完成里程碑改条件或交付要先重新打开。已保存交付的来源后来失效时保留引用
与稳定 ID，只给诊断；**新增或改变**的引用必须可核对。

为此把「交付来源失效」从致命问题降级为**非致命诊断**（`ValidationResult.diagnostics`），
并同步更新 v2 向量（2 条 reject → `diagnose`）、协议说明与 CLI 输出。

## 实现

- **领域**
  - `validate.ts`：`milestone-delivery-node-missing` / `-node-canceled` / `-record-missing` /
    `-hash-mismatch` 进 `diagnostics`；里程碑节点缺失、重复里程碑、自引用、重复交付、非法 `kind`
    仍是致命问题。成功结果新增 `diagnostics` 字段。
  - `roadmap.ts`：`setMilestone`（整体替换、排序归一、形状与自引用/重复拒绝、v1 拒绝）、
    `removeMilestone`、`milestoneOf`、`resolveDelivery`、`sameDelivery`。
  - `commands.ts`：`PlanCommand` 增 `set-milestone` / `remove-milestone`；里程碑命令结果自带的
    `roadmap` 不被“原值保留”覆盖；完成守卫：里程碑节点 `set-node-status: done` →
    `milestone-evidence-required`，已完成里程碑 `update-node` 改条件或 `set-milestone` →
    `milestone-reopen-required`。
  - `milestone-completion.ts`：完成正文构造/解析（版本标记 + `json` 围栏严格解析 + 形状/连续索引），
    以及不依赖宿主的 `verifyMilestoneCompletions`（记录身份、正文哈希、主题、证据位置与受检版本）。
- **应用层**
  - 新命令：`set-milestone` / `remove-milestone` / `complete-milestone`，全部 owner-only。
  - `set-milestone` 提交前：v2 校验、节点存在、已完成拒绝、逐项 `resolveDelivery`；
    仅当交付是既有项（`sameDelivery`）时允许保留失效来源。
  - `complete-milestone` 提交前：里程碑存在、未完成、条件非空、证据逐项覆盖（索引与原文）、
    每条证据为索引中更早的 `verification`、`pass`、主题为该节点、`subjectVersion` 等于当前规划、
    有 `scope`；候选构造把节点置 `done`、追加完成记录（`verification` + 摘要前缀 + 完成正文）、
    重算指纹并完整校验，一次修订一次发布。
  - `roadmapState` 增标题、状态、条件数、逐项交付诊断、最近完成记录与受检版本（供目标视图与诊断）。
  - 里程碑域诊断码对普通命令也原样上抛（`update-node` / `set-node-status` 的守卫）。
- **工件**：`formats/v2/milestone-completion-v1.schema.json`、`milestone-completion-protocol.md`
  （语义、正反例、独立核对命令），随新资料根发布到 `schema/` 与 `protocol/`。
- **CLI**：`validate.js check-completion <资料根>` 独立核对；`check` / `check-file` 输出 `diagnostics`
  （不影响退出码）。
- **UI**：概览路线图区显示里程碑标题、状态、交付/条件数、逐项诊断与完成记录（受检版本）。

## 边界与后续

- 里程碑编辑与完成未接入 Agent 工具或 WorkRun（owner-only）；面板编辑入口与目标视图在 4.4。
- `set-milestone` / `complete-milestone` 暂不写入逆向信息（撤销/重做）——4.5 负责 `set-milestone`
  的撤销/重做与原回执；`complete-milestone` 按设计不回退（历史记录保留）。
- 普通重做（`redo-plan-edit`）绕过 `applyPlanCommand` 的完成守卫，4.5 需在逆向候选处补同一判据。
- “被替代”当前以 `milestone-delivery-node-canceled` 诊断表达（合并保留来源为 canceled）；
  借助替代记录判断“替代目标可查”属目标视图（4.4）。
- 历史完成记录不与当前条件比较（按原记录保留），当前性由 `subjectVersion` 与指纹变化判断。

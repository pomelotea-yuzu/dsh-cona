# 4.5 覆盖 v2 的现有和新增规划变换（2026-11-23）

## 范围与结论

所有规划变换都从原 `Plan` 构造输出，未编辑的 `plan.roadmap` 原样保留；只有 `set-milestone` /
`remove-milestone` 改动目标条目，并且这两类现在会保存**条目级逆向信息**，因此撤销只回滚该条里程碑、
其余条目不受影响。普通状态命令（含重做路径）都不能把里程碑节点置为 `done`。v1 夹具跑同样的命令
仍保持 v1 字段与字节协议。

## 实现

- **领域**（`src/domain/inverse.ts`）
  - `PlanInverse.roadmapChanges?: { nodeId, before, after }[]`：只记录被编辑节点条目的前后值
    （`null` 表示当时没有条目），`validatePlanInverse` 接受并校验形状（UUID、`kind`）。
  - `buildPlanInverse`：对前后快照的里程碑集合按 `nodeId` 求差，未变化的条目不进入逆向信息。
  - `checkInverseState`：按方向核对当前条目是否仍是操作后／操作前状态，冲突码
    `inverse-roadmap-changed`（避免覆盖后续编辑）。
  - `applyPlanInverse`：在保留其余条目的前提下替换目标条目并按 `nodeId` 排序；v1 计划没有 `roadmap`
    时不补字段。
- **应用层**（`src/application/command-service.ts`）
  - `INVERTIBLE_COMMANDS` 增 `set-milestone` / `remove-milestone`。
  - `buildInverseCandidate` 用 `applied.value.roadmap ?? doc.plan.roadmap`，让条目级逆向生效、其他
    结构命令仍保留原扩展。
  - 重做守卫：方向为 `redo` 且逆向字段里 `status: done` 命中的节点带里程碑 → `milestone-evidence-required`
    （与直接提交同一判据）。
- **文档**：README 补「变换保留与撤销（4.5）」。

## 证据（A／F）

`test/v2-transforms.test.ts`（9，夹具含跨分支依赖 C→A、两个里程碑共享交付 A、一条记录交付）：

1. 九类结构命令（update／move／status／split／add／dependencies／insert-preset／group／copy）后
   `plan.roadmap` 逐字段等于操作前，里程碑身份与顺序不变，指纹按实际变化推进。
2. `save-user-template` 只追加记录、规划指纹不变；`insert-user-template` 保留里程碑。
3. 合并把交付节点 A 取消：两个里程碑都保留原 `refId`，`validateProjectDocument` 给两条
   `milestone-delivery-node-canceled` 诊断，资料仍可读。
4. 字段编辑撤销回原指纹、重做回编辑后指纹，里程碑始终不动。
5. `set-milestone` 增加交付后撤销恢复原集合与原指纹，重做回到编辑后集合与指纹（只回滚该条）。
6. `remove-milestone` 撤销恢复原条目与原交付。
7. 里程碑节点的普通 `done` 被拒；完成后再删标记，重新标记返回 `milestone-reopen-required`；
   非里程碑节点的状态命令撤销/重做照常。
8. `complete-milestone` 同 `operationId` 回放：`replayed`、资料字节不变、修订不推进。
9. v1 夹具跑 update／move／insert-preset／set-node-status：仍 `schemaVersion: 1`、字节无 `roadmap`、
   独立 `planVersionFromJsonText` 复算与自报一致。

全量：串行 `node --test --test-concurrency=1` **521 pass / 0 fail**；`build`、`typecheck`、
`check:plugin`（边界／协议／字典）、`check-repo --all` 全绿。

## 边界与后续

- `complete-milestone` 不可撤销（历史记录与状态保留），撤销完成需求按“重新打开 + 补验”处理。
- 里程碑条目的逆向信息随回执保存在本机聚合；导出／迁移不会带出，符合“私有授权不入公开资料”。
- 合并产生的替代记录与 `roadmap` 的关系仍是“保留原 ID + 诊断”，不做自动改指（与 4.3 一致）。
- H 层（真实宿主下改目标、移动、模板插入后的快照与持久回读，以及里程碑关联撤销/重做）随 5.3／5.5。

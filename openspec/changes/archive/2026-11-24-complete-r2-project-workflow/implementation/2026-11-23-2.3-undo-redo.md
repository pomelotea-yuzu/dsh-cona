## 实现

| 模块 | 变更 |
|---|---|
| `domain/inverse.ts`（新） | 规划编辑的字段级逆向信息。`buildPlanInverse` 从操作前/后 `Plan` 生成 `PlanInverse`：变化字段的 `before`/`after`、生成/移除节点（原身份与快照）、依赖边 added/removed 差集、受影响节点范围、可选 `replacement`（merge 的替代记录身份证）。`validatePlanInverse` 严格校验反序列化形状（旧回执缺字段即无逆向信息）。`checkInverseState` 核对当前是否处于所选方向的输入侧（undo 要求仍为操作后、redo 要求已回到操作前），并列出冲突对象。`applyPlanInverse` 按方向应用前后值、增删生成/移除节点、增删依赖，最后按父级分组稳定重排同级 order 保证从 0 连续，`validatePlanStructure` 兜底；输入 Plan 不可变。只记录变化字段使无关编辑天然保留。 |
| `domain/index.ts` | 统一出口导出 inverse 的构造/校验/核对/应用与全部类型。 |
| `application/local-state.ts` | `OperationRecord` 新增可选 `inverse?: PlanInverse`，随原回执保存在 `instances/<id>/state.json`；旧记录缺字段按无逆向信息处理。 |
| `application/command-service.ts` | `Command` 新增 `undo-plan-edit`／`redo-plan-edit`（`targetOperationId` + `previewDigest`），加入 `OWNER_ONLY_COMMANDS`；`INVERTIBLE_COMMANDS` 限定哪些编辑写入逆向信息（记录追加与逆向命令自身不写 replacement 标记）。新增只读 `previewInverse`（确认指纹、影响摘要、冲突对象、当前基线）与 `undoHistory`（逐操作 canUndo/canRedo 与原因）。私有方法 `inversePreviewDigest` 覆盖方向/目标/逆向信息/当前基线；`inverseOfRecord` 核对归属与提交态；`inverseSafety` 核对换源、字段/依赖变化、生成节点被公开记录/聊天/新增依赖占用、活动 WorkRun（原操作自身 added 的依赖不误报）。`commit` 在基线核对后解析逆向命令：先按摘要核对确认预览，再安全核对，全部通过才进入发布。`allocateIds` 为合并的逆向分配新记录 id（不重分配生成节点身份）。`buildCandidate` 的 `inverseContext` 分支生成逆向候选并重算指纹；合并撤销追加 `clear` 记录、重做追加新 `replace` 记录，同一权威头发布。普通 owner 规划编辑在提交时由 `buildPlanInverse` 写 `inverse` 到记录，随 prepared→publishing→committed 一起落盘；`materialize` 对逆向命令显式拒绝物化为普通 `PlanCommand`。 |
| `application/work.ts` | `commandAction`／`commandTargets` 补 undo/redo 穷尽分支（owner-only，agent 直达在命令服务入口拒绝）。 |
| `src/cli/command.ts` | 新增只读子命令 `preview-undo --target-operation <uuid> --direction undo|redo` 与 `undo-history`，使 F 层可经独立进程读取确认指纹、冲突原因与历史可用性。 |

## 测试（`test/undo-redo.test.ts`，7 用例）

1. 领域层：字段级前后值与无关字段保留、undo/redo 往返、触碰字段拒绝、`validatePlanInverse` 反序列化。
2. 字段撤销/重做：无关字段（title）编辑在 goal 的撤销/重做后保留；各只增一次规划修订；公开 `project.json` 不含 `inverse`；新建服务实例（模拟重启）仍可从聚合读取历史与逆向并重新预览。
3. 模板插入撤销：整批 `generatedNodes` 身份被记录，撤销移除后节点数与依赖回原、v1 校验器回读通过。
4. 结构往返：固定分配身份下 add-nodes + move-node，撤销恢复原同级顺序、重做恢复新顺序。
5. 冲突：旧操作无逆向信息 `unavailable`、字段已改 `inverse-field-changed`、生成节点被公开记录引用 `inverse-node-in-use`、活动 WorkRun `inverse-work-active`、换源 `source-changed`。
6. 预览过期与幂等：预览后基线变化再提交被拒；成功撤销后同号原样重放返回 `replayed:true` 且不重复变换。
7. 合并（补 E02）：撤销追加 `clear` 记录（正文 kind=clear、摘要前缀、来源恢复 todo），重做产生**新** `replace` 记录（旧记录保留、来源再次 canceled），候选可回读。

实现期间修复一处逻辑错误：`applyPlanInverse` 的依赖差集方向一度把原操作 added 边在 undo 时保留，导致模板撤销后生成节点被删而内部依赖悬空（`dependency-node-not-found`）；改为 undo 移除 added 边、恢复 removed 边，redo 相反。

回归：`undo-redo.test.ts` 7/7；全量测试在 `pnpm build` 后 381/382（唯一失败为沙箱删除守卫 `SAFE_DELETE_BULK_GUARD_ERROR state lock timeout`，属 2.1 已记录的环境抖动，非逻辑回归）；`pnpm check:plugin`（边界/协议/locale）与 `check-repo.mjs --all`（失败 0/警告 0）通过。`pnpm typecheck`（主/领域/测试三份 tsconfig）通过。

## 已知边界

- 里程碑关联（`set-milestone`）尚未实现，其撤销/重做按任务在 4.5 补测；逆向契约已通用，届时复用同一机制。
- 生成节点被记录/聊天/依赖占用、活动 WorkRun、换源时只拒绝并保留现状与原因，不自动改写或清理引用。
- 面板 UI 接入（版本选择、撤销冲突提示）随 2.6；真实宿主证据随 5.3 补 H。
- 逆向命令自身保存前后值但不带 replacement 标记，避免干扰以原操作为 target 的 clear/replace 语义。

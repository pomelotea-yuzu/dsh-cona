# 2.7 统一命令摘要与原子回执实施记录

日期：2026-11-23。执行范围：tasks 2.7 完成并勾选。矩阵 E12 记 A/F 层 `pass`；4.x 的路线图格式与里程碑命令按 4.1／4.3／4.5 复用同一契约复测。

## 结论

2.1–2.6 的新增树命令（`group-nodes`／`merge-nodes`／`copy-subtree`／`insert-preset`／`insert-user-template`／`save-user-template`／`undo-plan-edit`／`redo-plan-edit`／`move-node`）已全部经 `ProjectCommandService` 的同一路径执行：信封形态校验 → 请求摘要 → owner／绑定准入 → 实例串行队列 → 持久候选（`prepared`）→ 正文 → 权威头 → 回执与双修订。本次未改产品代码，用一组 A/F 用例把该契约逐分句固定下来；实现本身不需要新的接入点。

| 契约要点 | 落点 |
|---|---|
| 信封与形态校验 | `checkEnvelope`（UUID v4、规划指纹形态、非负修订、正整数源代际） |
| 请求摘要覆盖业务载荷与基线 | `requestDigest` 对 `projectId/instanceId/sourceEpoch/expectedPlanVersion/expectedPlanRevision/command` 做递归键排序后哈希；`operationId` 与重连标识不入摘要 |
| 生成 ID 发布前冻结 | `allocateIds` 在 `prepared` 落盘前生成并写入意图 `generated`；`materialize` 只用这一批 ID，重试与恢复不重新分配 |
| 持久候选 | `prepared.candidateHead/candidateHeadHash/originalHeadHash/bodies/result/writeHead` 随意图保存 |
| 单一权威头 | 一条命令一次 `writeDocument`；含衍生正文的动作用同一次头发布，正文先写、内容寻址 |
| 原回执 | 同号同摘要同归属 → `replay` 返回原 `OperationRecord.result`；摘要或归属不同 → `operation-mismatch`／`forbidden`；未决 → `pending-reconciliation` |
| owner 准入 | `OWNER_ONLY_COMMANDS` 覆盖结构、模板与逆向命令，agent-work 直达一律 `forbidden`；`authorizeTrustedContext` 与 `WorkAdmissionPort` 两条入口分别判据 |

## 测试（`test/unified-command-receipt.test.ts`，10 用例，全绿）

1. **摘要覆盖面**：位置（锚点）、模板版本、用户模板三元组、组成内容、合并处置、复制目标、模板子树根、逆向目标、验证结论逐项改参均产生不同摘要；字面量键序不同摘要相同；`expectedPlanVersion`／`expectedPlanRevision`／`sourceEpoch` 任一变化即变摘要。
2. **合并原子发布**：`publish`／`body` hooks 计数各 1（一个权威头、一份正文）；回执 `recordId`＝意图 `generated.recordId`＝索引条目 id；正文实际哈希＝索引 `contentHash`；`prepared.candidateHead` 与磁盘字节一致；双修订 `2/2`。
3. **证据正文**：带 `verification` 的 `append-record` 同样单头单正文，`impact=state`、规划修订 0、状态修订 1，规划指纹不变，索引内 `verification` 原样保留。
4. **生成 ID 冻结**：`insert-preset` 的意图 `nodeIds` 数量＝预设节点数、无重复、全部出现在磁盘；同号重发返回同一修订且不新增节点。
5. **非法子步骤**：合并未处置来源依赖 → `unresolved-dependency`；头字节、`records/`、修订与操作数全部保持（不落意图）。
6. **头发布前中断**：`publish.beforeRename` 注入异常 → `persistence-failed`；头与记录索引不变、修订不推进；先落的正文留在磁盘但不在索引中，不作为已发布记录暴露。
7. **回执丢失**：第三次聚合替换注入失败 → `pending-reconciliation`／stage `receipt`；资料已含替代记录且本机停在 `publishing`；`recover` 按候选匹配返回原 `operationId`、同一规划指纹、双修订 `2/2`、原记录 id，`getReceipt` 与原样重发同源，正文不重复发布。
8. **同号更参**：位置（锚点）、模板版本、验证结论、逆向目标（`targetOperationId`）分别 `operation-mismatch`，且字节与修订不变。
9. **原位无变化**：原位移动 `impact=state`，头字节与指纹保持，修订 `0/1`。
10. **批量无正文**：分组 1 头 0 正文、不追加记录、单次规划修订，同号重发返回原回执。

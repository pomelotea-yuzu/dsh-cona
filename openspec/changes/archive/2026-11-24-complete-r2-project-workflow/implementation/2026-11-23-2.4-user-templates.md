## 实现

| 模块 | 变更 |
|---|---|
| `domain/user-template.ts`（新） | 用户模板可移植正文。`UserTemplateBody` = `{version:1, templateId, title, bodyLanguage, nodes, dependencies}`；节点为局部 `{key, parentKey, order, title, goal, completionCriteria}`，依赖为模板键二元组。`extractSubtreeTemplate` 从所选子树按稳定 DFS 生成局部键（`n0…`）、同级 order 连续、原节点 UUID 不进正文；`internalDependencies` 只保留两端都在子树内的边，对外依赖省略。`buildUserTemplateText`／`parseUserTemplateText`（首行 `<!-- cona:template v1 -->` + json 围栏严格解析）与 `validateUserTemplateBody`（单根、唯一键、父键存在、父子无环、同级连续、依赖存在/不自依赖/不重复/无环，以及标题/目标/条件/节点/正文规模上限）；`bodyLanguage` 为明确语言标签或 `und`。 |
| `domain/index.ts` | 统一出口导出用户模板构造/校验/抽取与类型。 |
| `application/command-service.ts` | 新增 owner-only `save-user-template`（`templateId/title/bodyLanguage/rootNodeId`）；`buildTemplateBody` 从当前公开资料抽取子树构造正文，避免调用方伪造内容。`buildCandidate` 把保存转成 `plan-change` 的 `append-record` 候选（摘要前缀 `[cona:template] `、`subjectNodeIds: []`），复用同一发布/幂等/恢复链路。新增只读 `previewUserTemplate`（正文与摘要预览，不落盘）、`listUserTemplates`（逐条核对摘要前缀、正文哈希、严格解析后组装目录项）、`getUserTemplate`（`templateId`+`versionRecordId`+`contentHash` 三元组精确读取；哈希不符返回 `template-version-mismatch`，不存在返回 `template-version-unavailable`）。损坏正文、孤立记录与不支持版本在目录阶段被过滤。 |
| `application/work.ts` | `commandAction`／`commandTargets` 补 save-user-template 穷尽分支（保守 `record`，目标为子树根；owner-only，不经绑定准入）。 |
| `src/cli/command.ts` | 新增只读子命令 `list-user-templates`、`get-user-template`（`--template-id/--version-record/--content-hash`），保存经现有 `run --command` 提交。 |
| `formats/v1/` | 新增 `user-template-v1.schema.json`、`user-template-protocol.md`（形状、正例、11 类反例、读取接口），两者加入 `FORMAT_ASSET_FILES` 随包复制到资料根 `schema/` 与 `protocol/`。 |

## 测试（`test/user-template.test.ts`，5 用例）

1. 正文协议：构造/解析往返保留原文；未知版本、额外字段、非法语言 `zh_CN`、重复键、非单根、父键无效、依赖成环均拒绝；缺版本标记或 json 围栏拒绝。
2. 子树抽取：只含局部键、原节点 UUID 不进正文、内部依赖按局部键映射、对外依赖被省略、未知根返回空。
3. 保存两版：`plan-change` 摘要前缀、`subjectNodeIds` 为空、各只推进一次状态修订、`planVersion` 与规划修订不变、公开正文不含节点身份、v1 校验器回读、两版各自保留单语言原文。
4. 目录与三元组读取：`source:"user"` 目录项按 `templateId`/`versionRecordId`/`contentHash` 精确匹配；三元组不符不回退近似版本；注入损坏正文与孤立记录后目录只返回有效版本。
5. owner 可保存、agent 直达 `forbidden`、错误子树根 `node-not-found`、空标题 `template-invalid`，拒绝不推进修订。

实现期间修复一处 bug：`save-user-template` 初版被 `commit` 当作规划命令，因正文发布不改变 `planVersion` 而命中 `noBusinessChange` → `writeHead:false`，导致正文写入公开资料但 `project.json` 的记录索引未落盘；改为把模板保存归入记录追加类命令（`planning=false`），恢复写头，索引才随正文一起发布。

回归：`user-template.test.ts` 5/5、`undo-redo.test.ts` 7/7（单独运行）；`pnpm typecheck`、`pnpm check:plugin`（边界/协议/locale）、`check-repo.mjs --all`（洁净度失败 0／警告 0、链接问题 0、双语问题 0）通过。全量 `pnpm test:run` 在沙箱删除守卫无干扰时为 385/387（2 例 refresh 抖动）；守卫锁爆发时大量用例在 setup 阶段以 `SAFE_DELETE_BULK_GUARD_ERROR state lock timeout` 失败，属 2.1 已记录的环境抖动，非逻辑回归。

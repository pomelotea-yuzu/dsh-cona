## 实现

| 模块 | 变更 |
|---|---|
| `domain/replacement.ts`（新） | 替代记录正文构造与严格解析。两个互斥形状：`replace {version:1, kind, sourceNodeIds, replacementNodeId}`、`clear {version:1, kind, clearsRecordId}`——拒绝额外字段、未知版本、未知 kind、来源重复/为空、自引用、非法 UUID。格式：首行 `<!-- cona:replacement v1 -->` + `json` 围栏（`strictParse` 拒重复键）+ 可读 Markdown；索引摘要前缀 `[cona:replacement] ` |
| `domain/transforms.ts` | 新增 `mergeNodes`（来源以原 ID 保留为 canceled、原位置不变；后代移入保留节点末尾保持相对顺序；每条触及来源的依赖边必须显式处置 keep/reattach/drop——未处置 `unresolved-dependency`、处置不存在的边 `dependency-not-found`，重接自依赖/成环由结构校验拒绝；保留节点可同时应用字段补丁）与 `copySubtree`（目标父必须存在、锚点属目标同级组、新 ID 数量=源子树 DFS 节点数、新节点 todo、内部依赖按新 ID 映射、外部依赖按确认接入且必须恰好触及子树一端、原树不动） |
| `domain/commands.ts` | `PlanCommand` 新增 `merge-nodes`／`copy-subtree` 并分派 |
| `application/command-service.ts` | `Command` 新增两命令；`OWNER_ONLY_COMMANDS` 加 `merge-nodes`/`copy-subtree`；`allocateIds` 增加 `doc` 参数（copy-subtree 按源子树大小分配 ID 批次、merge-nodes 分配替代记录 ID）；**合并的规划候选与替代记录在同一权威头发布**——buildCandidate 中变换通过后追加 plan-change 记录索引条目（subjectNodeIds 覆盖保留+来源）与正文 bodies，随后全量领域校验；结构码上抛列表补 `unresolved-dependency`/`dependency-not-found`/`copy-id-count-mismatch`/`invalid-merge-source`/`duplicate-merge-source` |
| `application/work.ts` | `commandAction`（保守 update）与 `commandTargets`（merge=保留+来源集合、copy=目标父）补分支 |
| `formats/v1/` | 新增 `replacement-v1.schema.json`（两形状 oneOf、additionalProperties:false）与 `replacement-protocol.md`（版本说明、正反例表、独立校验命令说明）；两者加入 `FORMAT_ASSET_FILES`，接入时复制到资料根 `schema/` 与 `protocol/` |
| `src/cli/validate-replacement.ts`（新） | 独立校验器：从 project.json 出发读取 plan-change + 摘要前缀记录 → 复算正文哈希 → `parseReplacementText` → 按索引顺序投影（clear 指向更早 replace、逐项核对来源当前指向、`resolvedRecords` 集合拒绝重复解除、活跃来源重复拒绝、替代链成环拒绝）。任一步失败输出记录 ID、字段与原因，非零退出 |

## 测试（`test/merge-copy.test.ts`，8 用例）

合并：来源 canceled 原 ID 原位、后代移入保留节点（相对顺序、字段不变）、补丁应用、依赖三处置（重接/删除/不触及来源的原样保留）；负例 6 种（未处置、外部处置、跨父级、来源含保留、重复、自依赖环）。复制：新子树 todo、内部依赖映射、外部依赖按确认接入/未列出不接入/两端在子树内拒绝、ID 数量与位置负例。端到端：owner 合并单次权威头发布（记录 kind/摘要前缀/subjectNodeIds/正文可解析/来源 canceled）、**同号重试必须原样重发原请求（含提交时旧基线）返回原回执且不重复发布**、agent 直达 `forbidden`。独立校验器：正例通过、clear 引用错误拒绝、解除修正后通过、重复解除拒绝。

实现期间修复两处 bug（均被测试捕获）：①`mergeNodes` 后代重挂未滤除原位置节点导致 `duplicate-node-id`；②校验器 `alreadyCleared` 误用 activeRecordOf 判断重复解除（其值本来就是建立记录 ID），改为独立 `resolvedRecords` 集合。

回归：相关七文件 73/73 全绿；构建（tsc×2 + build-client + typert + check-locale + check-boundaries）全绿。

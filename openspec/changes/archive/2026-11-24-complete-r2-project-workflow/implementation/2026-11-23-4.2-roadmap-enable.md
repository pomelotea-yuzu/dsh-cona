# 4.2 显式启用扩展规划（2026-11-23）

## 范围与结论

v1 资料继续按 v1 字节协议编辑；首次启用 v2 由 owner 预览兼容影响并显式确认，发布时只创建空里程碑集合。
旧项目、节点、依赖、记录身份与验证受检版本全部原样保留。启用后的重新预览／再发布给
`roadmap-already-enabled`，预览后资料字节变化则给 `preview-mismatch`，不写盘。

同时修复 4.1 遗留的一处**写回丢失**：`serializeProjectDocument` 未序列化 `plan.roadmap`，
导致启用后资料头被写成 `schemaVersion: 2` 而无 `roadmap`，随后读取按缺字段拒绝。
新增回归用例覆盖「v2 写回后重读等价、v1 不补字段」。

## 实现

- **领域**（`src/domain/roadmap.ts`）
  - `convertToRoadmap(doc, sha256)`：v1 → v2，`roadmap.milestones = []`，节点／依赖／记录原样引用，
    重算指纹并完整领域校验；`roadmap-already-enabled`、`unsupported-format`、`invalid-project` 稳定码。
  - `roadmapEnableDigest({schemaVersion, planVersion, headHash}, sha256)`：确认摘要绑定预览时的资料字节。
- **命令服务**（`src/application/command-service.ts`）
  - 新命令 `{ type: 'enable-roadmap', previewDigest }`；列入 `OWNER_ONLY_COMMANDS`（agent-work 与无可信上下文都 `forbidden`）。
  - 提交前核对：已启用 → `roadmap-already-enabled`；摘要与当前头字节不符 → `preview-mismatch`（附 `current`）。
  - 候选在 `buildCandidate` 中直接由 `convertToRoadmap` 构造，不经过 `PlanCommand`；`impact = plan`、只推进一次规划修订。
  - 只读面：`roadmapState()`（v1 为 `enabled:false` + 空里程碑）、`previewRoadmapEnable()`（目标版本、
    身份计数、验证记录影响、确认摘要），共用 `readInstanceSource()` 的隔离／注册表／聚合／基线核对。
- **宿主**（`src/host/overview-service.ts`）：`conaOverview` 增 `roadmap`、`roadmapPreview`；发布仍走既有
  `conaOverview/execute`，因此幂等、回执、三态发布与队列全部复用。
- **客户端**（`project-overview-controller.ts`、`ProjectTopBar.tsx`）
  - 状态 `roadmap`：读状态、预览（含 `operationId`）、确认、取消；`load()` 自动选中实例时一并读取。
  - 确认前先用新快照核对预览基线（本地 `preview-mismatch`，不发命令）；提交复用预览的 `operationId`；
    待核对保留预览与 id（重试只核对，不产生第二次发布）；拒绝清预览要求重新预览。
  - UI `RoadmapSection`：v1 空态 + 「启用扩展规划」→ 影响面板（版本、身份、验证记录当前／历史计数、前 3 条）
    → 确认／取消；v2 显示已启用与里程碑节点。中英 16 个 key。
- **文档**：README 增启用流程与旧读者行为；`formats/v1` README 模板补「启用后可读 v2」提示。

## 证据（A／F）

`test/roadmap-enable.test.ts`（8）：
1. 预览给出目标版本、身份计数、验证记录 `currentlyCurrent`，且资料字节、修订、本机聚合都不变。
2. 确认后 `schemaVersion: 2`、`roadmap.milestones: []`；项目／节点／依赖／记录 id 与 `subjectVersion` 全等；
   指纹等于预览值；只推进一次规划修订；独立复算通过；`roadmapState` 报已启用。
3. 同 `operationId` 重发返回原回执（`replayed: true`），不改资料、不推进修订、只有一条回执。
4. 已启用后再预览与再发布都是 `roadmap-already-enabled`，资料不变。
5. 预览后仅改排版（指纹不变）→ `preview-mismatch`，资料仍 v1；重新预览后可发布。
6. 取消（只预览不提交）→ 资料字节与修订不变。
7. `agent-work` 与缺可信上下文都 `forbidden`；摘要形态非法 `operation-mismatch`。
8. v1 普通编辑保持 v1（无 `roadmap` 字段、字节不含该键、独立复算通过）；旧 v1 schema `const 1` + 禁止未知字段。

`test/roadmap-format.test.ts`（+1）：v2 资料头序列化保留 `roadmap` 且重读指纹一致；v1 不补字段。

## 边界与后续

- 启用后无法退回 v1（未提供降级动作）；需要回退时按 Git 历史处理，不在产品内做格式降级。
- 现有资料根不会自动补发 `formats/v2` 工件（`COPYFILE_EXCL`），随 5.x 的接入流程处理。
- 预览影响里的验证记录只按索引 `subjectVersion` 比较；里程碑证据与目标视图属 4.3／4.4。
- `conaProject`（配置实例树面板）暂未暴露路线图入口，启用入口在概览；4.4 视图落地时统一。
- 矩阵 E10 需要 v2 里程碑原值（依赖 4.3），本步只覆盖 v1 侧，故仍记 `untested`。

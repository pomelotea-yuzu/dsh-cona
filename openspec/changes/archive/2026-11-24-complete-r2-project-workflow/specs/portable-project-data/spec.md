## ADDED Requirements

### Requirement: 显式接入与隔离的工作副本

项目概览 MUST 支持预览并显式接入外部公开资料，展示规范位置、格式、项目身份、Git 跟踪状态和可配置的本机仓库映射。Host MUST 校验权威资料头、正文、相对路径和实际根范围。同项目的两个资料根 MUST 使用各自独立的本机实例、配置和执行数据。接入 MUST 保留项目、节点和公开记录身份，区分历史验证和本机证据。

#### Scenario: 干净环境接入合并后的资料

- **WHEN** 非 DSH Agent 根据公开说明在工作副本 A 修改 JSON 与 Markdown、用独立校验器校验，两个工作副本完成 Git 合并，干净 DSH 环境显式接入 B
- **THEN** 原项目、节点和记录 ID 保留，工作副本 B 的映射解析相对引用，历史接续和成果可读，B 有独立实例、本机聊天与回执状态，接入只使用公开资料和当前环境

### Requirement: 外部资料刷新与回退隔离

Host MUST 在实例队列内重新读取当前源、内容指纹、记录索引与正文，校验候选后显式接纳，发布同源完整快照。冲突标记、依赖成环、没有可核对的历史提交依据的索引缺失或同 ID 正文改写、无效正文和未知格式 MUST 给出诊断并禁止覆盖，保留最后有效快照与草稿。分支回退、源变化和旧回执 MUST 按各自来源核对。Git 观察 MUST 只读。

#### Scenario: 外部编辑与并发草稿核对

- **WHEN** A 与 B 的本机计数相同但规划不同，B 又发生未提交编辑和索引追加，同时界面保有旧草稿和在途候选
- **THEN** 以实际内容指纹区分规划，只追加索引时规划指纹保持不变，旧草稿保留且提示复查，旧候选不得覆盖外部规划或追加记录，工作区状态可见

#### Scenario: Git 语义冲突和历史回退

- **WHEN** Git 文本无冲突但合并结果形成依赖环，另用合法资料切换到历史分支并以实际 commit 树核对后确认刷新，再发来旧响应及原操作号
- **THEN** 成环资料可诊断并保持待修复，显式接纳合法回退后的完整快照，旧响应和回执只可用于原操作核对，当前源没有旧命令重放或隐式 Git 写入

### Requirement: 可恢复的资料位置迁移

owner MUST 能在三种已支持的资料位置之间预览并确认同一实例的迁移。迁移 MUST 先核对实例状态、源、目标和在途工作，持久化意图，验证复制候选，再更新有效定位与源代际。重启 MUST 能核对原操作及所处阶段。新位置只有在已验证的切换和本机状态一致后接收写入。旧位置保留。

#### Scenario: 三种位置迁移保持身份

- **WHEN** owner 将有效项目从项目目录迁至 DSH，再迁至自定义目录，再迁回项目目录的可用位置，随后使用保留原定位的启动配置重启
- **THEN** 每次切换仅有一个有效写入位置，实例、项目、节点、有效本机聊天和公开记录 ID 保留，源代际按操作推进，旧位置内容保留，启动解析到有效定位

#### Scenario: 迁移中断和目标冲突

- **WHEN** 目标已占用、与源重叠或校验范围越界，另在意图、复制、定位切换及回执各边界注入中断
- **THEN** 冲突目标原样保留，重启后根据登记和精确候选核对可继续、可取消或待核对状态，已有切换只补齐原操作，未知状态禁止继续写入，原资料可诊断

## MODIFIED Requirements

### Requirement: 规划指纹与格式兼容

读取方 MUST 按明确的 schema 版本分派指纹协议并独立复算 `planVersion`，保留 v1-plan 的字节规则与向量。v2-plan MUST 覆盖共享路线图的里程碑与交付关联，并提供随格式分发的独立一致性向量。指纹 MUST 排除排版、私有运行数据和过程记录。用户 MUST 显式预览并确认从 v1 启用 v2，普通 v1 操作保持原格式。未知格式／字段 MUST 停止写入，本机计数器不得作为跨副本版本顺序。

#### Scenario: 排版与过程记录变化

- **WHEN** 只改变对象键顺序、JSON 缩进，或新增一条过程记录
- **THEN** 规划指纹保持不变。节点展示顺序、目标或 v2 规划中的里程碑与交付引用发生变化时指纹改变

#### Scenario: 伪造指纹或未知格式

- **WHEN** 文件自报指纹与实际内容不符，或 schema／字段不受支持
- **THEN** 返回具体诊断并禁止覆盖原文件，不信任自报指纹继续写入

#### Scenario: 第二份独立实现复算

- **WHEN** 不依赖 DSH 或主实现序列化函数的第二份实现读取两个版本的规范正文和一致性向量
- **THEN** 对中文、转义、嵌套键、集合白名单、整数、null 和路线图字段得到各版本一致的 canonical UTF-8 字节和规划指纹，不以本机 JSON 默认选项替代协议

#### Scenario: v1 继续编辑并显式启用扩展

- **WHEN** 打开真实 v1 资料并做普通树编辑，随后预览 v2 转换，分别取消、处理预览期间的外部修改并在新基线上确认
- **THEN** 普通编辑可由旧 v1 读者读取，取消或冲突时不改格式，确认只发布一次 v2，项目、节点、记录 ID 及正文引用保留，旧读者遇到 v2 时停止写入

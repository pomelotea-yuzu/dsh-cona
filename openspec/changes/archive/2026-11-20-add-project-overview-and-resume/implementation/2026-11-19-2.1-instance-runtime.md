## 二、真实宿主实测（隔离 profile + 预构建包，宿主 Node v24.21.0）

从当前源码 `pnpm pack` 得 tarball，装入全新独立 `DSH_HOME=artifacts/r2-probe/home-multi` 的 `cona-r2-test` profile（base + web-app + 插件）。配置实例 A 指向 `proj-a`；用插件 CLI `local register` 把同 projectId 不同目录的 `proj-b` 登记为实例 B。经 Playwright 浏览器同源 HTTP Remote 调用（cookie=owner）实测：

| 检查 | 结果 |
|---|---|
| `conaOverview/instances` 列出实例 | pass：列出 A、B 两条，均 `readable:true`，含 projectId/sourceKind/sourceDisplay/sourceEpoch |
| 同 projectId 两目录是独立实例 | pass：A=`cc6cf8ba…`、B=`afc459da…`，projectId 相同、instanceId 不同 |
| `conaOverview/snapshot` 按实例读 | pass：A、B 均返回 snapshot（各 11 节点，planVersion 一致），B 为按需装配（此前未打开） |

| 缺 instanceId | gateway 边界校验拒（`gateway/input-invalid`，instanceId 在 wire schema 为必填），符合「定向访问必须明确实例」 |
| 既有 `conaProject` Remote 未受影响 | pass：仍返回配置实例 A 的 snapshot；入口/工具/事件未改 |

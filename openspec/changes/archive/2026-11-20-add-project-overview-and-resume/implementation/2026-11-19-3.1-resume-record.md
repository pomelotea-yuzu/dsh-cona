# 3.1 接续记录写入：格式、保存与回读（2026-11-19）

状态：tasks 3.1 的**领域与保存闭环完成**并经真实文件后端集成测试。交付带版本正文格式、摘要前缀、必填校验、候选选取与不可读诊断，复用 R1 的 `append-record` 与回执三态保存。卡片 UI、聊天指针、工作副本代码观察属 3.2/3.3，不在本轮。

## 一、交付

| 文件 | 内容 |
|---|---|
| `src/domain/resume.ts`（新） | 纯领域模块：`RESUME_SUMMARY_PREFIX`／`RESUME_BODY_MARKER`／版本 1／64 KiB 上限；`buildResume`（payload→带前缀 summary + marker+fenced-JSON+可读 MD 正文）、`buildPayload`／`validateResumePayload`（停点/下一步 trim 非空、nextStepKind、savedAt、可选字段、验证引用状态）、`parseResumeBody`（marker+严格 JSON+载荷校验，各类不可读码）、`selectResumeCandidate`（索引尾部向前、kind+前缀匹配、跳过普通、首个即停）、`hasResumePrefix` |
| `formats/v1/resume-v1.md`（新） | 随包发布的格式说明 + 可读样例；说明索引层/正文层/边界与不可读语义 |
| `test/resume.test.ts`（新） | 6 项：构造/解析往返、必填校验、前缀识别、候选选取（跳普通/回退）、不可读诊断（marker/JSON/版本/超限）、严格 JSON 重复键 |
| `test/resume-save.test.ts`（新） | 3 项真实文件后端集成：`append-record` 保存→索引候选→正文哈希核对→解析往返（impact=state、planRevision 不变、历史验证状态原样）、同 operationId 幂等只一条、普通 execution-note 不误选 |

**复用 R1 而非重造**：接续记录就是 `kind=execution-note` + summary 前缀 + 版本化正文。不改 R1 索引字段、`schemaVersion`（严格校验会拒未知字段）、正文寻址与内容哈希。`append-record` 的幂等（operationId）、三态回执（saved/not-saved/unknown-state）、部分成功/隔离全部走 R1 现有 `command-service`（已有测试覆盖）。

### 2.1 活动 WorkRun 与重启前隔离（probe-41-work / main）

- `workPrepare`（committed）→ `workStart`（awaiting-message）→ `workObserve(kind=consumed, agentPresent=true)` 启动生效运行 `f2b92a06…`：`targets=[根 0000…0002]`、`bindingVersion=1`、`sessionId=session-3b925a3a…`、`turn=1`、`effective=true`。owner 转发 consumed 事件建立的是本机运行/绑定记录；工具侧 `agent.id` 核对仍由 `project-tools.captureBinding` 独立成立（O11 工具拒绝分句的边界见末节）。
- **浏览 B**（`conaOverview/snapshot(B)` 返回 B 的 11 节点）：A 的 WorkRun id/targets/bindingVersion/effective 逐字节不变，两条 Client `follow` 订阅均存活。
- **保存 B**（owner `conaOverview/execute` 走 `append-record`，impact=state，卡片投影出停点「4.1 B 保存隔离探针停点」）：A 的 WorkRun 再次核对不变；A 的公开记录数组未出现 B 的停点（实例资料隔离）；A 的两条 `follow` 订阅仍存活。
- 期间构造两条 A 的 Client `follow`（gen 9/10），`followEvents` 在浏览/保存前后均可拉取。

## 三、诚实口径与未测项

1. **O11 的 B 会话工具拒绝 / B 开始动作禁用**：当前切片 design §2 明确「切换插件运行实例和为 B 自动建立项目 WorkRun 由后续 change 定义」，`conaOverview` 未提供 `createChat/linkChat`，B 无本机聊天链接，无法在 H 层构造「B 的真实会话调用项目工具」。该项**未测**，不以 owner RPC 模拟冒充。工具侧 `captureBinding` 的绑定版本/范围准入已由 R1 6.2/6.3 单测与真实 Agent E2E 覆盖。
2. **O11 的「B 节点关联两个真实会话、打开确切 Session」**：受同一边界限制，B 无建聊天入口。3.3（probe-36）已在配置实例 A 上实证「多聊天选择→指针→打开确切 Session→解绑回读」，4.1 的重启/干净环境闭环以 A/B 接续记录回读覆盖，未在 B 重造会话。
3. **O13 的「运行中草稿原文保留」**：真实 UI 切换在设置浮层内进行，切回概览需关闭浮层；草稿为 Client 内存态，重载页面会丢（符合 design §1「草稿可停留在当前 Client 进程」）。4.1 验证「切换无需重开面板、文案即变、无 key 泄漏」；草稿跨语言保留的交互分句由 R1 V35 覆盖。
4. **resumeCandidate 的连接代际**：`overview-service.ts:245` 内部 `connectionGeneration: 0`，配置实例 A 一旦被 `conaProject/follow` 推进代际，其概览卡片投影会短暂显示 `stale-connection` 诊断（探针副作用；正常产品路径中概览用独立实例或 fresh page 读）。B 实例独立 follow 状态不受影响。此现象已观察，未改产品代码，留给 R6 试用确认是否需修正。
5. **宿主内进程 vs 编写环境**：所有 WorkRun/订阅/保存/回读/切换均在真实宿主进程内经 `/api` 发生；`proj-a`、`proj-b`、`home-multi`、`home-clean41` 的文件改动是探针产生的测试产物（不入库）；重启前后 PID、bootGeneration 已记录。干净 profile 的公开资料来自 proj-b 的既有文件，未从 A 的私有聚合复制任何授权。

## 四、对 change 的影响

4.1 的 H 层闭环成立：活动 WorkRun 下浏览/保存 B 不扰动 A、重启不复活旧授权、干净环境只读公开资料、运行中语言切换生效。O11 可验分句有实测证据；B 会话工具拒绝与 B 建会话受 design §2 边界限制未测，不影响本切片其余结论，也不放宽验收标准。建议 tasks 4.1 勾选、矩阵 O11/O12/O13 记入 H 层证据并保留未测分句标注。O10（引用查阅/越界）不在 4.1 场景内，维持 `untested`。

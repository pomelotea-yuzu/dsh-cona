## 三、调用时机约束（须带入 design §1 / 任务 2.2）

`ctx.layout.selectPanel(id)` 在调用前检查**实时** `main` 注册表，未注册的 key 抛错并保留当前选中态（rc.2 `ui-layout/src/client/service.ts:72-78`、`README.zh.md:63`）。R1 面板经 `ctx.slots.inject('main', () => ctx.slots.register({name:'main', key:'cona-project', …}))` 异步注册。因此设计里「打开树编辑器时先确认实例/代际，再让面板绑定控制器并导航」的实现，必须：

1. 等 `cona-project` 的 `main` keyed slot 完成注册后再 `selectPanel`；概览入口在插件 apply 早期不可直接调用。
2. 复用 R1 已注册的同一个 `main` keyed slot（panel id `cona-project`），不新开面板；否则命中 hasMainPanel 拒绝。
3. 因 `selectPanel` 与导航共用 layout 的 `navigation` abort 信号（`beginNavigation()`），连续导航须按代际丢弃过期请求（与 design §2 选择代际一致）。

## 四、本探针未覆盖（不得当作通过）

- **产品交互层**：顶部按钮的真实文案/图标、向下展开的概览内容、键盘展开与 Escape 焦点返回、草稿/选择保留——属 2.2 与 spec Req1，1.1 只确认宿主容器支持（overlay 为可聚焦的标准 DOM、按钮键盘可达），未实现产品组件。
- **安全会话导航的完整语义**：`openSession` 本次证明「能落到指定 Session」；「点击时复查当前实例/节点关联/宿主 Session 仍有效才导航」属 3.3/Req5，未在本探针验证。
- **多实例路由**：本探针复用 R1 单实例配置；按 `instanceId` 路由的新 owner 入口属 2.1，未测。
- **非 owner / 未登记拒绝**：属 2.1/O03，未测。

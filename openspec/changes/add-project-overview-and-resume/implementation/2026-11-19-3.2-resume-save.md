# 3.2 实施记录（第二段）：保存预览与接续编辑 UI（2026-11-19）

## 范围与结论

3.2 第二段交付**保存预览与接续编辑 UI**：概览内"写接续"入口 → 表单（停点/下一步必填 + 成果/决定/未解决可选 + 下一步性质单选）→ 共享内容预览（带前缀 summary）→ 经 `conaOverview/execute` 提交 append-record → 三态回执。已通过真实宿主浏览器实测 8/8 项。**保持未勾选**：每实例工作副本配置、只读代码观察（HEAD/dirty）与"待核对"原因呈现属第三段，尚未实现。

## 设计与实现

- **不加新 Host Remote**：conaOverview 已有 `execute`（owner 准入 + 按 instanceId 构造 envelope 转发 `command.execute`）与 `snapshot`（按实例读基线），保存链路全部复用——client 只需取快照基线、构造 append-record 命令、提交并处理回执。
- `client/project-overview-controller.ts` 新增：
  - `ResumeDraft`（全共享内容字段 + `operationId`）与 `ResumeSaveState`（idle/saving/saved/failed/conflict/pending）；
  - `editResume()` / `patchResumeDraft()` / `discardResumeDraft()`；切换实例即丢弃草稿（`select` 内清空）；
  - `resumePreview()`：用领域 `buildResume` 生成带前缀 summary + 版本化正文预览（保存与预览同一构造函数，所见即所存；不含任何本机数据）；
  - `saveResume()`：必填校验（停点/下一步 trim 非空，缺失给 `missing-required` 稳定码）→ `snapshot` 取基线 → 构造 `append-record`（kind `execution-note`、subjectNodeIds 取树首个节点、summary/body 来自 buildResume）→ `execute` 提交。回执处理与 R1 面板同口径：committed 清草稿并刷新卡片；rejected 的 plan-conflict/source-changed 归为 `conflict`；pending-reconciliation 归为 `pending`；**任何失败/冲突/未知保留草稿与原 operationId**，幂等重试不产生第二条记录（传输异常归 `transport-unknown`，结果未知不换 id）。
- `client/ProjectTopBar.tsx` 新增 `ResumeSaveSection`：入口按钮（选中实例才显示）→ 表单 → 预览块（summary + 说明"共享内容，不含本机数据"）→ 保存/取消；保存状态行内联显示（必填缺失/失败码/冲突/待核对）；保存成功表单关闭后，入口按钮旁保留"已保存"回执（`data-cona-resume-saved`）。
- i18n：中英各补 15 键（resumeEdit、resumeEditStop/Next/Outcome/Decisions/OpenIssues、resumePreviewTitle、resumeSave、resumeCancel、resumeSaved/SaveFailed/SaveConflict/SavePending/MissingRequired/Saving），`check:locale` 通过。

## 测试与实测

- 单测 4 项（`test/project-overview-controller.test.ts`）：必填缺失不触 transport；提交成功清草稿 + summary 带前缀 + kind/subjectNodeIds 正确 + 卡片刷新；冲突保留草稿与 operationId 且重试复用同 id（幂等）；传输异常保留草稿。全仓 277/277 通过。
- 真实宿主实测（探针 `artifacts/r2-probe/probe-34.mjs`，8/8 通过）：表单打开 → 只填下一步保存被 `missing-required` 拦截 → 填全后预览出现 `[cona:resume] 保存表单实测完成` → 保存成功 → 草稿清空 + "已保存"回执 + 卡片刷新显示新停点/下一步 → 取消丢弃草稿 → 无页面错误。
- 门禁：`check:ci` 全绿。

## 诚实口径

- 保存回执的 `pending-reconciliation` 与部分成功路径沿用 R1 command-service 既有行为，未针对接续命令单独注入故障（与 3.1 记录一致）。
- 保存预览目前展示带前缀 summary 一行；完整正文预览（fenced JSON + 可读 Markdown）未展示，属可改进项。
- 每实例工作副本配置、Git 只读观察与"待核对"呈现未做——卡片历史验证仍直接来自记录 payload。
- subjectNodeIds 简化取树首节点；接续语义上记录归属项目级而非特定节点，未提供节点选择。

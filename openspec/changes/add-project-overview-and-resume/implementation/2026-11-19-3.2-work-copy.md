## 范围与结论

3.2 第三段交付**每实例本机工作副本配置 + 只读代码观察 + 待核对呈现**：

- `adapters/fs/work-copy.ts`（新）：`observeWorkCopy(root, excludeRoots, options)` 只读观察——`rev-parse --show-toplevel` 确认工作副本、`rev-parse HEAD` 取提交、`status --porcelain` 计脏条目并**排除实例公开资料目录**（path.resolve 前缀匹配，rename 取源路径）。失败给稳定原因（not-a-work-copy / no-commits / status-failed），不做任何 git 写操作。
- 配置：`host/index.ts` `Config` 加 `workCopyRoots: record<instanceId, 绝对路径>.optional()`；`bootstrap.ts` `HostConfigInput/HostConfig` 透传，`resolveHostConfig` 校验每个 value 绝对路径（非绝对给 `cona-config-not-absolute`）。
- runtime：`ConaProjectRuntime` 加可选 `observeWorkCopy(instanceId)`；装配时闭包注入（resolveHostConfig 成功后暂存映射），未配置该实例返回 null。

- i18n：中英各补 5 键（codeObserved、worktreeClean、worktreeDirty、codeNotConfigured、codeUnavailable），占位符中英一致，`check:locale` 通过。

## 诚实口径

- 安全根检查的复用方式：工作副本根校验采用与资料/本机根一致的绝对路径规则（`resolveHostConfig` 拒绝非绝对路径与 `..` 语义）；`inspectPrivateRoot` 本身语义相反（私有根必须无 tracked 文件），不直接复用其函数，仅复用其只读探测模式。
- "最新候选不可读"由领域级单测（坏 marker/坏 JSON/版本未知）与 Host rejected 传递覆盖，未对真实资料注入损坏正文做浏览器级复现。
- 脏计数对含引号/转义路径做保守处理（去引号不还原转义），rename 取源路径；极端文件名下计数允许偏差，不影响"有/无未提交"的方向性结论。
- 会话插曲：本段实测期间沙箱 shell 一度被安全中心持续拦截（toybox 临时清理规则），中途由用户在真终端按命令清单执行过一轮（起始目录错误未成功）；shell 恢复后由沙箱完成实测与提交，并清理了错建的 `packages/project-plugin/artifacts/` 与陈旧 `.git/index.lock`（0 字节、无进程占用）。

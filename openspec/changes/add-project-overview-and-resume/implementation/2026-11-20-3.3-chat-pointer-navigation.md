## 设计与实现

- **指针存储**（`application/resume-chat.ts` 新增 `ResumeChatService`）：`ResumeChatPointer { recordId, contentHash, linkId, createdAt }` 存入本机实例聚合新增 `resumePointers`（旧聚合读取时归一化为空数组，不静默改写磁盘）。写路径与命令/聊天共用每实例 `InstanceCommandQueue`；隔离（quarantine）与 unknown-state 语义与 `ConversationService` 同口径。
  - `link()`：先复查链接仍存在（`resume-link-missing`）、记录在当前已接纳索引（`record-not-found`）且索引可读（`record-unknown`，不冒充不存在），再落指针；同 `(recordId, linkId, contentHash)` 重复请求幂等不推进修订；同记录换链接或记录版本经显式核对刷新变化时替换。
  - `view(recordId, contentHash)`：卡片投影三态——`linked`（含 Session 可见性，目录不可用记 `visible: null` 不冒充失效）／`unlinked`／`unavailable`（聚合缺失=干净 profile、隔离、链接已删）。本机状态不可读**不阻塞卡片**，公开摘要照常显示（design §4）。
  - `resolveTarget()`：打开前复查记录版本（请求哈希 ≠ 指针哈希 → `record-version-changed`）、指针与链接（`resume-pointer-missing`／`resume-link-missing`）、宿主列表可见（`session-not-visible`）。
- **Host 入口**（`conaOverview` 新增三个 Remote，owner 准入 + 按实例路由复用 2.1 机制）：
  - `resumeChats`：本实例链接列表（purpose + sessionId + nodeIds + 可见性）；本机聚合缺失/隔离给 `unavailable`，保存仍可不关联继续。
  - `linkResume`：幂等保存指针；失败/unknown 如实返回稳定码，公开记录数不变。
  - `resumeChatTarget`：返回确切 `sessionId` 供 client 导航；导航本身不用 Host，不带任何执行绑定。
  - `resumeCandidate` 卡片结果新增 `contentHash` 与 `chat` 三态；运行时注入 `resumeChats` 服务（记录版本复查走本实例快照的已接纳索引）。
- **Client**：
  - 保存表单新增「关联聊天」下拉（`data-cona-resume-chat`，`visible=false` 的行禁用并标注），可留空=仅保存摘要；`editResume()` 打开表单时读取选项，切换实例丢弃迟到响应。
  - 保存链路：`append-record` 提交成功后若选了聊天则调 `linkResume`；失败降级为 **部分保存**（`partial`，提示「摘要已保存；聊天未关联」+「重试关联」按钮），重试只调 `linkResume`、复用现有 `recordId`，公开记录数不变（幂等由 Host 保证）。
  - 卡片聊天行三态呈现；`linked` 且未确认失效时显示「打开原聊天」——点击后 Host 复查通过才 `openSession(sessionId)`（1.1 探针实证路径）；拒绝给 `chatNotice` 稳定码。选择代际检查：复查返回时实例已切换则丢弃，不导航。
  - 注入：`package.json` `dsh.client.inject` 加 `@deepseek-ai/dsh-client-ui-workspace`（ui-sidebar 先例），client fiber `inject` 加 `uiWorkspace`；类型按探针实证的最小结构访问（宿主不随插件分发类型包）。`callOverview` 把 `OwnerDenial` 的 null 与形状异常统一归一为 `rejected`，控制器不接触 null。
- **i18n**：中英各补 8 键（关联聊天/不关联聊天/列表不可读/打开原聊天/原聊天在此不可用/聊天未关联/部分保存/重试关联），`check:locale` 通过；稳定错误码保持原文。

# 3.3 启用受限 Agent 移动与插入实施记录

日期：2026-11-23。执行范围：tasks 3.3 完成并勾选。矩阵 W04、E08、E09 记 A／F 层 `pass`；J05 仍为 H 层待验（本批提供 A 层前置证据）。H 层真实 Agent 的获准／越界写入随 5.4 补。

## 关键边界

结构命令从“静态 owner-only”改为“可由可信 WorkRun 发起，但必须过工作绑定准入”。为不把原来的静态拒绝变成缺口，命令服务对 `agent-work` 增加了硬性守卫：`move-node`／`insert-preset`／`insert-user-template` 在宿主未装配工作端口时一律 `forbidden`，不因“没有 work 服务”而跳过准入。

## 实现

| 层 | 变更 |
|---|---|
| `application/local-state.ts` | `WorkAction` 增 `move`／`insert`；新增 `WorkTemplateAuthorization`（内置按 ID+版本、用户模板再带记录 id 与正文哈希）；`WorkIntent`／`WorkRunRecord` 增可选 `rootGroupAllowed`、`templates`（旧数据缺字段按 false／空授权读取）。 |
| `application/ports.ts`／`host/session-directory.ts` | 新增 `PlanNodeViewPort.planOutline()`：只投影当前规划的 `id/parentId/order`，供结构影响范围解析；`planNodeView` 从资料头实现。 |
| `application/work.ts` | `WorkAction` 映射：`move-node → move`、`insert-preset`／`insert-user-template → insert`（分组／合并／复制仍保守映射 `update`，且仍 owner-only）。新增 `structuralImpact(command, outline)`：移动 = 子树（含自身）+ 源父组 + 目的父组 + 锚点 + 源组中位置后移的同级 + 目的组中插入点起的同级；插入 = 父组 + 锚点 + 插入点起的同级；并给出 `touchesRootGroup`（源或目的父组为根）。`commandTargets` 增加可选轮廓参数，有轮廓时用精确影响，无轮廓时保持旧保守投影。`prepareWork` 接收并冻结 `rootGroupAllowed`／`templates`，`sameIntent` 把它们纳入幂等比较。`observeConsumed` 把两项冻结进运行。`authorizeAgentCommand` 增结构准入：缺动作 `forbidden`；插入 `parentId: null` → `parent-not-found`（早于任何候选分配）；模板精确不符 → `template-not-authorized`；缺轮廓 → `structure-scope-unavailable`；根组重排缺许可 → `root-group-not-allowed`；影响范围越出目标集合 → `structure-scope-denied`。 |
| `application/command-service.ts` | `OWNER_ONLY_COMMANDS` 移除 `move-node`／`insert-preset`／`insert-user-template`，保留分组／合并／复制／撤销重做／模板保存；新增 `WORK_RUN_STRUCTURAL_COMMANDS`：agent-work 上下文缺工作端口时直接 `forbidden`。 |
| `host/project-tools.ts` | `project_apply` 的 `PLANNING_TYPES` 增三类结构命令；工具描述写明影响范围、根组许可、`parentId: null` → `parent-not-found`、模板精确版本与“生成节点不加入目标集合”；参数说明由“五类”更新为八类。 |
| `host/project-service.ts` | `ConaWorkPrepareRequest` 增 `rootGroupAllowed`／`templates` 并原样转交（面板/宿主可显式授予；旧调用不变）。 |
| `client/*` | 工作动作选项补 `move`／`insert`（中英文案），使面板可显式授予这两项动作；根组许可与模板授权的专用勾选未做 UI，按 API 显式传参（见边界）。 |
| `README.md`／`src/types.ts` | README 增结构命令协议与授权要点；导出 `WorkTemplateAuthorization`、`PlanOutline`／`PlanOutlineNode`／`StructuralImpact`。 |

## 测试（`test/work-structure.test.ts`，9 项，全绿）

夹具：根 `[R1,R2]`、`R1` 下 `[A,B,C]`、`A` 下 `[A1,A2]`、`R2` 下 `[D]`，真实资料头 + 本机注册 + 刷新基线，命令服务与工作服务共享实例队列。

1. 影响范围：移动含子树、源组后移同级、目的组插入点起同级与锚点；源／目的为根时 `touchesRootGroup`。
2. 影响范围：插入含父组、锚点与后移同级；末尾追加不牵动既有同级；`commandTargets` 有／无轮廓两种口径。
3. 缺动作：允许集合只有 `update` 时 `move-node`／`insert-preset` 均 `forbidden`，资料字节与修订不变。
4. 源或目标越权：移入目标集合外的父组 `structure-scope-denied`；只授权 `[A1]` 时连源父组 `A` 也越权。
5. 根组：未授予时根级重排 `root-group-not-allowed` 且根序不变；授予后发布一次、根序按确认重排；非根升根仍由领域 `child-to-root` 拒绝（不新增越级通道）。
6. 模板：无 `templates` 的旧运行（空授权）、精确版本不符、用户模板哈希不符分别 `template-not-authorized`。
7. 两类根级插入：已授予 insert、根组许可与精确模板版本，`insert-preset` 与 `insert-user-template` 的 `parentId: null` 均 `parent-not-found`，修订不变、节点数不变（无候选、无生成节点）。
8. 获准插入：内置模板插到现有父节点下发布、规划修订 +1、新节点数等于预设节点数、运行目标集合不变、绑定版本 +1。
9. 旧绑定与 owner 改基线：旧捕获版本写 → `binding-expired`；owner 改基线后原运行仍可捕获与读上下文；同一运行拿新基线写 → `binding-expired`；结束旧运行并显式发起新运行后可写入。

## 已知边界

- H 层（真实 Agent 工具提交 move／insert、两类根级插入、旧绑定拒绝与新运行获准、工具读视图一致）随 5.4；W04 的 H 部分与 J05 仍待。
- 面板目前只能授予 `move`／`insert` 动作，`rootGroupAllowed` 与模板精确授权还没有专用 UI（须经 `workPrepare` 显式传参）；W04 的“持有根组重排许可、插入动作和所选模板版本的新绑定”在 A 层用直接调用覆盖。
- 移动的影响范围包含“因归一化而变序的同级”，因此目标集合需覆盖这些同级；这是有意从严——同组重排牵动邻居，要求用户确认整组。
- 根组许可只用于根内重排；把子节点升为根仍被领域拒绝，不因结构授权放开。
- 结构影响按当前资料轮廓计算；提交时重读资料后若轮廓变化，由绑定基线不一致或领域校验拒绝，不做二次扩权。

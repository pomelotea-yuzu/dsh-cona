## 真实宿主发现并修复的产品缺陷

### 缺陷八：配置实例没有回填进多实例运行时表 → 工作入口一律“不可用”

- 现象：干净 profile 启动后概览仍显示「本实例不是启动配置实例：项目工作入口不可用」，`configuredInstanceId()` 恒为 undefined，`workPreview/workPrepare/workStart` 全部拒绝。
- 根因：`InstanceRuntimeRegistry` 构造只注入了 runtime promise，`host/index.ts` 没有把异步打开成功的配置实例交给 `configured`，表内 `configured` 恒 false。
- 修复：新增 `setConfigured(instanceId, runtime)`，宿主在 `shared()` 成功后回填；`release()` 与概览行归属改用内部 `configuredId`。回归 `instance-runtime-registry.test.ts`（8/8）。

### 缺陷九：概览的一次性 owner 读被 stale-connection 误拒 → 工作预览／接续保存不可用

- 现象：面板订阅推进连接代际后，概览的工作预览固定带 `connectionGeneration: 0`，宿主按“旧代际”拒绝（`stale-connection`），预览与接续保存卡死。
- 根因：`snapshot.read` 把 0 也当作会过期的订阅代际；但 0 是概览一次性读的哨兵（不建立订阅，读到的就是当前内容）。
- 修复：只拒绝 `0 < 请求代际 < 最新代际` 的正代际请求；一次性 owner 读接受当前内容。回归 `snapshot.test.ts`（15/15，新增一次性读放行断言，旧代际仍拒绝）。

### 缺陷十：插件新建聊天没有落到宿主工作区 → 会话列表不收录、`openSession` 导航到空态

- 现象：面板「新建聊天／打开会话／打开原聊天」后页面落到「选择工作区／选择一个工作区开始」，没有输入框；宿主 `workspace.json` 里没有对应工作区或会话未被记账。
- 根因：插件只用 `sessionController.create({cwd})` 建会话；宿主 Web UI 的工作区列表与 `uiWorkspace.openSession` 导航依赖 `workspaceRegistry` 的会话记账，`create` 本身不记账。
- 修复：`sessionDirectory` 先按资料根 `resolveByPath`／`create` 工作区，再以 `workspaceId` 建会话（`create` 不接受 cwd 与 workspaceId 同时给），成功后 `workspace.attachSession(sessionId)`；宿主无工作区服务时退回旧 cwd 行为。回归 `session-directory.test.ts`（4/4，含定向复用/创建与 attach）。

### 缺陷十一：`project_receipt` 输出 schema 只声明 rejected 形状

- 现象：真实 Agent 查询命中回执时被宿主输出校验判为 schema 错误（回执带 `operationId/impact/planVersion/replayed` 等 committed 字段）。
- 修复：`project_receipt` 输出改用 `COMMITTED_SCHEMA`；`project-tools.test.ts` 断言回执 schema 覆盖 committed 字段（11/11）。该修复晚于本轮验收包，5.8 在最终包上复测回执。

### 产品缺口（未定，已记录）：面板没有模板／根组授权的 owner 入口

- `conaOverview/workPrepare` 原先不透传 `templates`／`rootGroupAllowed`，面板又只有动作勾选框、没有模板/根组选择控件；真实 Agent 的 insert 在面板流程里只能得到 `template-not-authorized`（或根级 `parent-not-found`），无法完成“获准父节点正常插入”。
- 本轮为取得 W04 H 证据，给 owner Remote 补了 `templates`／`rootGroupAllowed` 透传（UI 未加控件）；W04 的许可分句因此可在真实宿主复现。**UI 是否补控件、或改规格移除不可兑现的 insert 勾选，待用户裁决。**

**缺陷七：面板合并命令把保留节点也塞进 `sourceNodeIds`（已修）**

- 现象：UI 上任何合并都必然被域层拒绝（`invalid-merge-source`），而同一预览区已经显示「保留：A · 涉及来源：B」——预览与命令载荷不一致。
- 根因：`panel-controller.ts` 构造 `merge-nodes` 时 `sourceNodeIds: [...draft.nodeIds]`，`draft.nodeIds` 是多选全集（含 keep）；域层规则是「保留节点不得出现在来源数组」。
- 为何 A 层没抓到：`test/panel-tree-editing.test.ts` 把错误载荷写进了断言（`sourceNodeIds: [C1, C3]`，C1 就是 keep），断言跟着实现一起错。
- 修复：`sourceNodeIds` 过滤掉 `keepNodeId`，与预览口径一致；同时改断言为 `[C3]`。`panel-tree-editing` + `panel-controller` 20/20 pass。
- H 层复测（装入修复后的 client 构建、重启宿主）：同一对节点合并 → `已保存`，磁盘上保留节点 `工程实现` 存在、来源 `5.3 分组实测` 变 `canceled`，与 E02 语义一致。

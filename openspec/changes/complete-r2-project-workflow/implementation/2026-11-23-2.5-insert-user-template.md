# 2.5 统一模板插入与重试实施记录

日期：2026-11-23。执行范围：tasks 2.5 完成并勾选。矩阵 E06／E07 补充插入覆盖，E11 记 A/F `pass`（H 层随 5.3 补）。

## 实现

| 模块 | 变更 |
|---|---|
| `domain/user-template.ts` | 新增 `instantiateUserTemplate(plan, body, newIds, parentId, beforeNodeId)`：按模板节点顺序分配新项目 ID，用单语言原文创建 todo 节点，按局部键映射父子与内部依赖；对外依赖不进入模板故不注入。校验正文、ID 数量/UUID/重复、父节点存在、锚点属于目标同级组，注入后 `validatePlanStructure` 兜底；输入 Plan 与正文不变。 |
| `domain/commands.ts` | `PlanCommand` 新增 `instantiate-user-template` 并在 `applyPlanCommand` 分派；领域出口已导出实例变换。 |
| `application/command-service.ts` | `Command` 新增 owner-only `insert-user-template`（`templateId/versionRecordId/contentHash/parentId/beforeNodeId`）。提交时**重读当前发布索引与正文**：找记录并核对 `plan-change`+`[cona:template] ` 前缀 → 不存在 `template-version-unavailable`；索引哈希与请求不符 `template-version-mismatch`；正文不可读 `template-version-unavailable`；复算正文哈希不符 `template-version-mismatch`；严格解析失败 `template-invalid`；`body.templateId` 不符 `template-version-mismatch`。解析出的正文随 `resolvedUserTemplate` 传给 `allocateIds`（按模板节点数分配 ID）与 `materialize`（物化为 `instantiate-user-template`，**不在物化阶段重新解析**）；位置错误由领域变换原样上抛 `parent-not-found`／`invalid-anchor`。预检失败在分配 ID 前返回，不写文件不推进修订。同号重试走既有 `replay`、恢复走既有 `recover`，均用已持久化的候选与回执，不重新解析模板。`insert-user-template` 加入 `INVERTIBLE_COMMANDS`，插入批次身份写入逆向信息，可经 2.3 的 undo/redo 撤销。 |
| `application/work.ts` | `commandAction`／`commandTargets` 补 insert-user-template 分支（`add`，目标为父节点；owner-only，本阶段不开放 Agent）。 |
| `cli/command.ts` | 无新增子命令：插入经既有 `run --command '<json>'` 提交，模板目录与精确读取沿用 2.4 的 `list-user-templates`／`get-user-template`。 |

## 测试（`test/insert-user-template.test.ts`，7 用例）

1. 领域实例化：新 ID/todo、内部依赖按新 ID 映射、原树不动；未知父/null 父/错误锚点/ID 数量不符拒绝。
2. 两位置插入：同一模板在父 ROOT 末尾与锚点 CHILD 前各插入一批 2 节点与 1 条内部依赖，各只增一次规划修订，v1 回读，原节点与依赖保留。
3. 错误码：版本不存在 `template-version-unavailable`、哈希不符与 templateId 不符 `template-version-mismatch`、正文 version=2 `template-invalid`（索引哈希与正文一致以隔离解析层）、null/不存在父 `parent-not-found`、锚点不属于目标同级组 `invalid-anchor`；全部拒绝后规划修订不变。
4. 源变化与基线冲突：`plan-conflict` 与 `source-changed` 不改文件、不推进修订、不分配候选。
5. 同号重试与重启：断联后同 envelope 原样重放返回 `replayed:true` 且不重复生成；新服务实例指向同一本机根与 store 经 `getReceipt` 仍读到历史结果；同号改 contentHash 返回 `operation-mismatch` 且不生成节点。
6. 用户模板插入可撤销（2.3 契约）：批次生成身份写入 `inverse.generatedNodes`，preview undo 可用，撤销后节点数恢复、v1 回读通过。
7. owner 准入与映射：agent 直达 `forbidden`、`commandAction='add'`、`commandTargets=[parentId]`（null 父为空）；内置 `insert-preset` 原协议不受影响。

实现期间补一处遗漏：初版 `INVERTIBLE_COMMANDS` 未含 `insert-user-template`，导致用户模板插入不写逆向信息、无法按 2.3 契约撤销；补入后新增的撤销用例通过。

回归：`insert-user-template.test.ts` 7/7、`user-template.test.ts` 5/5、`undo-redo.test.ts` 7/7（合计 19/19）；`pnpm typecheck`、`pnpm check:plugin`（边界/协议/locale）、`check-repo.mjs --all`（洁净度自测 32 项通过、链接 157 篇问题 0、双语问题 0）通过。全量 `pnpm test:run` 历次受沙箱删除守卫 `SAFE_DELETE_BULK_GUARD_ERROR` 抖动影响，本批未重复跑，权威结果以真终端为准。

## 已知边界

- 用户模板插入本阶段为 owner-only；design 中"明确授权的 Agent"随 3.3 启用受限 `insert` 动作时统一开放。
- 跨副本 Git 交换模板后插入（5.2）与真实宿主证据（5.3）待补。
- 面板 UI 的版本选择与插入预览随 2.6；内置 `treePresets`／`insert-preset` 保持原协议，不与用户模板目录混用。

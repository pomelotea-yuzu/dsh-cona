## ADDED Requirements

### Requirement: 同一规划下的目标视图

项目树、里程碑目标视图及 Agent 规划读取 MUST 使用同源完整快照。视图 MUST 显示成果及完成条件、直接依赖、实际进展、阻塞和下一步，缺少或已过期的来源须明确标记。用户 MUST 能定位原节点、核对成果或打开已核对的关联聊天。浏览切换和重连 MUST 保持实例、连接代际和执行边界。界面 MUST 支持简体中文、英文及其他宿主语言回退英文。

#### Scenario: 目标视图同步与实例隔离

- **WHEN** 在 A 的树中移动关联交付的节点，打开目标视图查阅里程碑、依赖、近期成果、阻塞、下一步及关联聊天，再浏览 B、重连并接收迟到的 A 响应
- **THEN** 可按相同节点 ID 定位最新规划，B 保持自身快照。只呈现可追溯的来源或具体空态／待核对状态。导航不启动执行，新增固定文案按语言或英文回退显示

### Requirement: 带自有完成条件的跨分支里程碑

里程碑 MUST 使用树中一个存在的稳定节点及其完成条件，每个节点至多一个里程碑。交付关联 MUST 使用稳定标识、类型和适用的内容哈希。交付关联、执行依赖和工作状态 MUST 独立。移动 MUST 保留引用。已保存来源取消、被替代、缺失或版本不符 MUST 提示待核对。正式完成 MUST 明确映射每项自身完成条件与当前规划下的已发布通过证据，原子保存完成状态和可追溯的受检版本。完成记录正文 MUST 提供公开版本说明、schema、样例和独立校验入口，使外部读取方可按索引核对逐项证据。旧版本验证 MUST 保留为历史。

#### Scenario: 跨分支交付引用与独立达成

- **WHEN** 两个里程碑引用同一成果，相关节点先移动，再取消或被替代。其他交付均完成，当前里程碑仅有 v1 历史验证或缺部分自身条件的当前证据，之后补齐证据并显式确认
- **THEN** 移动后原引用保留，替代目标有可查 ID 但不自动改指。缺证据、旧版本或普通状态命令均不能完成里程碑。逐项证据齐备时原子发布状态及依据记录，可核对输入、受检版本和范围。执行依赖不变

#### Scenario: 核对新增与历史交付引用

- **WHEN** owner 新增自引用、跨项目、缺失来源或重复交付，另从外部移除里程碑节点、取消该节点，或使一个已发布的合法交付来源不可得或哈希失配
- **THEN** 非法新增和悬空里程碑拒绝接纳。取消节点及其里程碑保留为历史。来源失效时保留引用、稳定 ID 及诊断，合法关联仍可查询和修订

### Requirement: 既有规划变换保留里程碑扩展

所有规划变换 MUST 保留其未明确修改的 v2 里程碑和交付字段。普通 v1 编辑 MUST 保持 v1 格式和 v1 字节协议。编辑使引用发生可观察失效时 MUST 按其生命周期显示原因。

#### Scenario: v2 树编辑保留交付规划

- **WHEN** 对带里程碑及跨分支引用的 v2 实例逐次做加节点、改目标与条件、拆分、调整依赖、状态变化、移动、分组、合并、复制、两类模板插入和逆向编辑，并在 v1 夹具上重复适用操作
- **THEN** v2 的未触及扩展及稳定引用保留，受影响的历史关联给出待核对原因。普通 v1 操作保持 v1 字段和协议，独立 v1 读者仍可读取

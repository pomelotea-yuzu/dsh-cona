# portable-project-data Specification

## Purpose
以不依赖 DSH 私有数据库的文本协议保存长期项目规划，使不同资料位置使用同一业务模型，其他 Agent 可以直接阅读与校验，并为后续 Git 协作及新机器接续保留稳定身份和清楚的数据边界。

## Requirements

### Requirement: 三种位置共用公开格式

系统 MUST 支持按项目选择项目目录、DSH 数据目录或自定义目录保存同格式的 UTF-8 JSON／Markdown 资料，并显示实际位置和可获得的 Git 跟踪状态。位置发现不得静默改变已有选择，保存资料不得自动执行 Git 提交或同步。

#### Scenario: 在三种位置保存同一规划

- **WHEN** 分别在三种位置创建和重新打开等价规划
- **THEN** 资料遵循同一 schema，业务读取结果一致，实际位置可见且私有运行存储独立

#### Scenario: 没有代码目录的项目

- **WHEN** 用户选择 DSH 或自定义资料位置并创建逻辑项目
- **THEN** 可以保存规划，不强制先创建代码目录或 Workspace

#### Scenario: 空本机环境首次接入外部 v1 资料

- **WHEN** 全新本机根没有注册、绑定或回执，只取得一份已有合法 v1 公开资料并首次接入
- **THEN** 沿用原项目／节点 id，创建新的本机实例而不重建项目或要求原数据库，不导入旧机器授权和回执；这只验证基础接入，不代替跨机协作试用

### Requirement: 明确的文本权威入口

资料 MUST 提供 README 阅读／编辑入口、版本化 schema 与权威规划文件；独立正文仅在被有效资料头引用时作为已发布记录读取。README 或生成概览不得成为另一份可独立编辑的规划真源；读取外部资料不得自动执行其中的指令、脚本或远程获取。

#### Scenario: 无 DSH 阅读与校验

- **WHEN** 其他 Agent 只获得公开资料、格式说明和独立校验命令
- **THEN** 能读取目标、节点、关系和已发布记录，并校验资料而不加载 DSH、React、Cordis 或模型服务

#### Scenario: 孤立正文和恶意资料指令

- **WHEN** 目录中存在未被资料头引用的正文或正文要求自动执行脚本
- **THEN** 不把孤立正文显示为已发布成果，也不因接入资料而执行脚本

### Requirement: 最小稳定规划与领域校验

项目和节点 MUST 使用稳定 id；树归属、展示顺序、执行依赖、目标、完成条件与工作状态 MUST 明确表达。程序 MUST 校验身份唯一、父子有效性、树和依赖无环及引用合法性；批量拆分 MUST 整体接受或整体拒绝，不能发布部分结构。

#### Scenario: 编辑与拆分节点

- **WHEN** 用户或 Agent 合法修改目标，或将一个节点拆为明确的子节点
- **THEN** 原节点身份保留，新节点获得新 id，顺序明确，修改原因可查询

#### Scenario: 非法树或依赖

- **WHEN** 输入存在重复 id、缺失父节点、树环、依赖环或非法引用
- **THEN** 返回领域诊断并拒绝发布，不因 JSON 可解析而接受

#### Scenario: 过程结束与节点完成分离

- **WHEN** 保存执行结果或所有子节点变为已完成
- **THEN** 不自动把父节点标为已完成；显式完成命令仍核对自身条件及所需证据

### Requirement: 公开资料不得承载本机执行资格

系统 MUST 将实际 Session／Workspace、机器绝对路径、活动授权、私有草稿和意图／回执保存在独立本机存储。公开资料只发布用户选定的正文与来源；作者标记、外部验证或导入的授权文字不得成为本机权限或复测证据。

#### Scenario: 检查三种位置的公开资料

- **WHEN** 保存项目、关联本机聊天并执行一次 Agent 命令
- **THEN** 公开资料不出现实际会话身份、机器绝对路径或私有回执，且本机仍能查询这些关联

#### Scenario: 接入带外部结果的资料

- **WHEN** 读取含作者、外部通过结论或授权文字的公开记录
- **THEN** 保留来源与适用范围，不恢复原机器写权限，不将外部通过显示为本机复测通过

### Requirement: 规划指纹与格式兼容

读取方 MUST 按明确的 schema 版本分派指纹协议并独立复算 `planVersion`，保留 v1-plan 的字节规则与向量。v2-plan MUST 覆盖共享路线图的里程碑与交付关联，并提供随格式分发的独立一致性向量。指纹 MUST 排除排版、私有运行数据和过程记录。用户 MUST 显式预览并确认从 v1 启用 v2，普通 v1 操作保持原格式。未知格式／字段 MUST 停止写入，本机计数器不得作为跨副本版本顺序。

#### Scenario: 排版与过程记录变化

- **WHEN** 只改变对象键顺序、JSON 缩进，或新增一条过程记录
- **THEN** 规划指纹保持不变。节点展示顺序、目标或 v2 规划中的里程碑与交付引用发生变化时指纹改变

#### Scenario: 伪造指纹或未知格式

- **WHEN** 文件自报指纹与实际内容不符，或 schema／字段不受支持
- **THEN** 返回具体诊断并禁止覆盖原文件，不信任自报指纹继续写入

#### Scenario: 第二份独立实现复算

- **WHEN** 不依赖 DSH 或主实现序列化函数的第二份实现读取两个版本的规范正文和一致性向量
- **THEN** 对中文、转义、嵌套键、集合白名单、整数、null 和路线图字段得到各版本一致的 canonical UTF-8 字节和规划指纹，不以本机 JSON 默认选项替代协议

#### Scenario: v1 继续编辑并显式启用扩展

- **WHEN** 打开真实 v1 资料并做普通树编辑，随后预览 v2 转换，分别取消、处理预览期间的外部修改并在新基线上确认
- **THEN** 普通编辑可由旧 v1 读者读取，取消或冲突时不改格式，确认只发布一次 v2，项目、节点、记录 ID 及正文引用保留，旧读者遇到 v2 时停止写入

### Requirement: 资料实例与路径范围

本机绑定 MUST 同时区分稳定项目 id 和独立资料实例，旧工作副本的绑定与回执不得用于另一实例。文件访问 MUST 解析用户选择的根与声明的相对引用，检查越界、符号链接及实际路径范围，不依赖当前进程目录或本机路径分隔符。

#### Scenario: 同项目的两个目录

- **WHEN** 同一项目资料被复制到两个不同工作副本并分别接入
- **THEN** 稳定项目／节点 id 相同，本机实例、聊天绑定和回执隔离

#### Scenario: 引用逃逸或符号链接越界

- **WHEN** 资料路径包含越界相对引用，或符号链接指向允许范围之外
- **THEN** 拒绝对应访问并保留诊断，不读取或覆盖范围外文件

### Requirement: 显式接入与隔离的工作副本

项目概览 MUST 支持预览并显式接入外部公开资料，展示规范位置、格式、项目身份、Git 跟踪状态和可配置的本机仓库映射。Host MUST 校验权威资料头、正文、相对路径和实际根范围。同项目的两个资料根 MUST 使用各自独立的本机实例、配置和执行数据。接入 MUST 保留项目、节点和公开记录身份，区分历史验证和本机证据。

#### Scenario: 干净环境接入合并后的资料

- **WHEN** 非 DSH Agent 根据公开说明在工作副本 A 修改 JSON 与 Markdown、用独立校验器校验，两个工作副本完成 Git 合并，干净 DSH 环境显式接入 B
- **THEN** 原项目、节点和记录 ID 保留，工作副本 B 的映射解析相对引用，历史接续和成果可读，B 有独立实例、本机聊天与回执状态，接入只使用公开资料和当前环境

### Requirement: 外部资料刷新与回退隔离

Host MUST 在实例队列内重新读取当前源、内容指纹、记录索引与正文，校验候选后显式接纳，发布同源完整快照。冲突标记、依赖成环、没有可核对的历史提交依据的索引缺失或同 ID 正文改写、无效正文和未知格式 MUST 给出诊断并禁止覆盖，保留最后有效快照与草稿。分支回退、源变化和旧回执 MUST 按各自来源核对。Git 观察 MUST 只读。

#### Scenario: 外部编辑与并发草稿核对

- **WHEN** A 与 B 的本机计数相同但规划不同，B 又发生未提交编辑和索引追加，同时界面保有旧草稿和在途候选
- **THEN** 以实际内容指纹区分规划，只追加索引时规划指纹保持不变，旧草稿保留且提示复查，旧候选不得覆盖外部规划或追加记录，工作区状态可见

#### Scenario: Git 语义冲突和历史回退

- **WHEN** Git 文本无冲突但合并结果形成依赖环，另用合法资料切换到历史分支并以实际 commit 树核对后确认刷新，再发来旧响应及原操作号
- **THEN** 成环资料可诊断并保持待修复，显式接纳合法回退后的完整快照，旧响应和回执只可用于原操作核对，当前源没有旧命令重放或隐式 Git 写入

### Requirement: 可恢复的资料位置迁移

owner MUST 能在三种已支持的资料位置之间预览并确认同一实例的迁移。迁移 MUST 先核对实例状态、源、目标和在途工作，持久化意图，验证复制候选，再更新有效定位与源代际。重启 MUST 能核对原操作及所处阶段。新位置只有在已验证的切换和本机状态一致后接收写入。旧位置保留。

#### Scenario: 三种位置迁移保持身份

- **WHEN** owner 将有效项目从项目目录迁至 DSH，再迁至自定义目录，再迁回项目目录的可用位置，随后使用保留原定位的启动配置重启
- **THEN** 每次切换仅有一个有效写入位置，实例、项目、节点、有效本机聊天和公开记录 ID 保留，源代际按操作推进，旧位置内容保留，启动解析到有效定位

#### Scenario: 迁移中断和目标冲突

- **WHEN** 目标已占用、与源重叠或校验范围越界，另在意图、复制、定位切换及回执各边界注入中断
- **THEN** 冲突目标原样保留，重启后根据登记和精确候选核对可继续、可取消或待核对状态，已有切换只补齐原操作，未知状态禁止继续写入，原资料可诊断

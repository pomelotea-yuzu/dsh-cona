# project-tree-editing Specification

## Purpose
让用户能在 DSH 内按积木方式搭建与调整项目树：预览并确认同级重排、子树移动与内置流程插入，移动保留节点身份、后代、成果与聊天关系；结构操作遵循实例与执行边界，沿用既有规划提交、冲突、回执与恢复协议，并按宿主语言呈现界面而不改写模板正文。

## Requirements

### Requirement: 用户能够预览并保存树结构操作

插件 MUST 从项目概览打开所选已登记实例的树编辑器，并允许 owner 在根组或普通子节点组内同级重排、移动整棵子树和插入内置流程。树 MUST 按父子层级及同级顺序展示。拖放和键盘可操作的菜单 MUST 提供相同的移动位置，操作 MUST 显示预览并由用户确认保存。预览与已提交快照 MUST 可辨。取消 MUST 恢复已提交视图和可识别的焦点。

#### Scenario: 同级前移后移及回到原位置

- **WHEN** 在合法的多根 v1 项目中，用户分别在根组和普通子节点组将节点向前移、再向后移，另尝试放回原位置
- **THEN** 每次实际移动按目标位置展示并保存，受影响的同级组编号从 0 连续，根节点集合保持原值。回到原位置时显示无变化，原规划指纹和规划修订保持原值

#### Scenario: 键盘和拖放预览及取消

- **WHEN** 用户分别通过拖放和键盘菜单选择同一移动位置，并用键盘选择一个流程插入位置；分别取消预览和确认保存
- **THEN** 两种移动入口产生等价预览；预览期间公开资料和已保存版本保持原值，取消后焦点回到可识别的位置；键盘可确认所有结构操作

#### Scenario: 切换实例或宿主页面保留各自草稿

- **WHEN** 用户从 A 进入树并建立结构草稿，再切到 B 或宿主其他页面，随后回到 A；另在有节点内容草稿时尝试发起结构编辑
- **THEN** 草稿与选中节点归属原实例，B 只显示本实例数据，返回 A 恢复原草稿；该实例只保留一份草稿，用户须先保存并完成核对或明确放弃原草稿，才能开始另一编辑

### Requirement: 移动保留子树身份与已有关系

结构移动 MUST 接受一个现有节点、目标父节点和可选同级锚点。`parentId: null` 定义根组，根节点 MUST 只在根组内重排，非根节点 MUST 以现有节点为目标父节点。锚点 MUST 属于目标同级组，无锚点时 MUST 追加到该组末尾。发布结果 MUST 保持 v1 的至少一个根、各同级组顺序从 0 连续、父子无环及依赖端点有效且无环。移动 MUST 保留已有节点 ID、子树内部结构、目标、完成条件、状态、显式依赖、公开记录及本机聊天关联。

#### Scenario: 移动有后代、成果和聊天的子树

- **WHEN** 用户把已有聊天、记录与跨分支依赖的子树从一个阶段移到另一个阶段的指定兄弟节点之前，再移动至另一个根分支中的空阶段下
- **THEN** 整棵子树出现在新位置，原与目标同级顺序连续，节点 ID、后代顺序、依赖端点和公开记录保持原值，原聊天仍归属相同节点，已记录验证及节点状态原样保留

#### Scenario: 拒绝无效的根、父节点或位置

- **WHEN** 请求把根降为子节点、把非根升为根、把节点放在自身或任一后代下、锚定自身、引用缺失节点，或为根组、普通子节点组指定属于其他组的锚点
- **THEN** Host 返回对应原因，公开文件、规划修订和聊天关联保持原值，有效目标位置仍可重新选择

### Requirement: 内置流程作为完整子树实例化

插件 MUST 提供至少一个可预览且有明确版本的开发流程预设，展示其来源、准确版本、层级、完成条件和内部依赖。经 owner 与实例核对的树入口 MUST 提供当前随包预设及其可用正文语言。Host MUST 精确匹配请求中的预设 ID、版本和可用正文语言，并验证目标为现有父节点。Host MUST 为模板中的每个节点分配新项目节点 ID，一次发布全部节点和内部依赖，保留旧节点及旧依赖。新节点 MUST 从 `todo` 开始，发布只使用普通 v1 节点与依赖。无效预设、语言或位置 MUST 给出原因。

#### Scenario: 插入预设并独立再次插入

- **WHEN** 用户预览一个有内部依赖的预设，插到现有同级节点之前，再以新操作在一个空父节点下插入相同版本
- **THEN** 两次均得到完整子树，位置和内容符合预览，所有新 ID 唯一，两批内部依赖分别指向各自的新节点，既有节点及依赖保留，新节点无聊天、结论、历史成果或授权，原 v1 读者可读取发布结果

#### Scenario: 拒绝不可用或无效的模板输入

- **WHEN** 请求未知预设、已不可用版本、不支持的正文语言、无效目标位置，或包内预设存在重复键、无效父级、缺失依赖端点或成环
- **THEN** Host 解释拒绝原因，公开头、记录与规划修订保持原值；其他有效树操作仍按既有准入可使用

### Requirement: 结构操作遵循实例和执行边界

Host MUST 用既有 owner 和本机登记实例核对保护预设读取与结构操作。移动和插入 MUST 由受信 owner 发起。Agent 工具 MUST 继续遵循既有动作、节点范围、绑定和基线规则。浏览、预览及结构提交 MUST 保持已启动 WorkRun 的执行目标、范围和运行状态。对实际推进规划基线的结构操作，面板 MUST 提示如果有活动工作，规划写入需在原运行结束后从当前规划显式发起新运行。

#### Scenario: 多实例和可信身份校验

- **WHEN** owner 通过项目概览在可写的已登记实例 B 操作，另提交实例不匹配、未登记、不可读或非 owner 的请求，并用可信 Agent 上下文直接提交新增结构命令
- **THEN** 有效写入只出现在 B，其余请求返回原因；旧配置实例入口、原有 Agent 工具准入与现有实例隔离仍可用

#### Scenario: 工作运行中修改同实例的树

- **WHEN** 配置实例存在活动 WorkRun，owner 先做原位预览，再实际移动其目标的祖先或插入预设；Agent 使用原基线写入，再读取最新规划并尝试在同一运行中写入。随后旧运行确认结束，用户从当前规划显式发起新工作
- **THEN** 实际变更前的基线有效性与原位预览前相同。实际变更后原运行继续执行并可读取，目标、允许动作及历史保留，新节点未纳入其范围，两次当前运行的写请求均被拒绝。新运行通过原可信宿主边界取得基于当前规划的绑定，获准范围内的写入可提交

### Requirement: 提交、冲突与回执遵循既有规划协议

结构操作 MUST 捕获实例、项目、源代际和规划基线，经同一实例的持久意图、发布、回执和完整快照回读流程完成。实际成功的结构变更 MUST 推进一次规划修订。结构操作与既有节点规划编辑的普通已保存状态 MUST 基于已确认回执及同源有效回读。已确认提交但快照无法核对时，面板 MUST 显示「已提交，待同步」并提供读取重试。换源后的回执 MUST 保留为历史，当前树以当前源有效快照为准。遇到基线冲突 MUST 保留请求草稿并提示在新快照上确认；遇到未知结果 MUST 使用原请求和 `operationId` 核对，保留既有隔离及恢复行为。可选变更原因 MUST 在结构变更确认且完成同源回读后单独保存，移动以移动节点为记录主体，插入以目标父节点为主体。原因保存状态 MUST 与结构变更结果可辨。

#### Scenario: 用户确认前已发生其他规划或源变化

- **WHEN** 在结构预览建立后，另一有效写入调整了规划、外部顺序编辑改变了内容指纹，或实例切换了源代际
- **THEN** 旧请求按原基线被拒绝，草稿保留并标注冲突，最新树可打开核对；用户在新位置重新确认后使用新的操作号

#### Scenario: 确认后断线并重试模板插入

- **WHEN** 模板已发布但回执响应丢失，Client 重连后核对或重发原请求；另用相同操作号修改位置或版本。分别验证结构提交及既有节点编辑的回执已确认但完整回读失败，以及结构变更已同步但可选原因保存失败
- **THEN** 原插入只生成一套节点 ID，规划修订只推进一次，改动参数的同号请求被拒绝。回读失败时提示「已提交，待同步」，读取重试成功后才显示普通已保存。原因失败单独提示，重试原因时保留原结构提交回执

#### Scenario: 发布途中中断或旧响应迟到

- **WHEN** 在已持久化候选时中断发布并重启，或已切到 B 时 A 的回执和快照迟到
- **THEN** 候选按既有恢复规则核对，完整发布后显示结果，无法确认时保留待核对状态；A 的响应仅作用于 A 的原请求，B 的可见树与草稿只由 B 的有效回读更新

#### Scenario: 更新后重启并读取已有接续资料

- **WHEN** 在已有接续记录的 v1 项目上完成结构变更，关闭和重开插件后读取项目树、原聊天及接续卡片
- **THEN** 可回读新结构及既有记录，聊天仍解析到原会话，接续卡片保留记录中的历史验证状态，并继续显示当前代码观察结果或可见的未核对原因

### Requirement: 界面语言与模板正文独立

结构控件、预览、错误、状态和无障碍标签 MUST 支持简体中文与英文，其他宿主语言的控件及新预设预览 MUST 回退英文。预设正文 MUST 使用创建草稿时选定的可用语言实例化，语言切换 MUST 保留原有节点正文、待提交请求和已保存正文。

#### Scenario: 编辑期间切换宿主语言

- **WHEN** 用户在中文下打开预设预览，切换到英文和第三种语言，保持原草稿并完成保存后，在第三种宿主语言下新开一个预设预览
- **THEN** 固定文案切换并按需回退英文，原草稿显示并保存选定的中文正文，原项目内容原样保留，新预览使用英文正文

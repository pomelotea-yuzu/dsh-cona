# project-tree-editing Specification

## Purpose
让用户能在 DSH 内按积木方式搭建与调整项目树：预览并确认同级重排、子树移动与内置流程插入，移动保留节点身份、后代、成果与聊天关系；结构操作遵循实例与执行边界，沿用既有规划提交、冲突、回执与恢复协议，并按宿主语言呈现界面而不改写模板正文。

## Requirements

### Requirement: 用户能够预览并保存树结构操作

插件 MUST 从项目概览打开所选已登记实例的树编辑器，并允许 owner 在根组或普通子节点组内同级重排、移动整棵子树和插入内置流程。树 MUST 按父子层级及同级顺序展示。拖放和键盘可操作的菜单 MUST 提供相同的移动位置，操作 MUST 显示预览并由用户确认保存。预览与已提交快照 MUST 可辨。取消 MUST 恢复已提交视图和可识别的焦点。

#### Scenario: 同级前移后移及回到原位置

- **WHEN** 在合法的多根 v1 项目中，用户分别在根组和普通子节点组将节点向前移、再向后移，另尝试放回原位置
- **THEN** 每次实际移动按目标位置展示并保存，受影响的同级组编号从 0 连续，根节点集合保持原值。回到原位置时显示无变化，原规划指纹和规划修订保持原值

#### Scenario: 键盘和拖放预览及取消

- **WHEN** 用户分别通过拖放和键盘菜单选择同一移动位置，并用键盘选择一个流程插入位置；分别取消预览和确认保存
- **THEN** 两种移动入口产生等价预览；预览期间公开资料和已保存版本保持原值，取消后焦点回到可识别的位置；键盘可确认所有结构操作

#### Scenario: 切换实例或宿主页面保留各自草稿

- **WHEN** 用户从 A 进入树并建立结构草稿，再切到 B 或宿主其他页面，随后回到 A；另在有节点内容草稿时尝试发起结构编辑
- **THEN** 草稿与选中节点归属原实例，B 只显示本实例数据，返回 A 恢复原草稿；该实例只保留一份草稿，用户须先保存并完成核对或明确放弃原草稿，才能开始另一编辑

### Requirement: 移动保留子树身份与已有关系

结构移动 MUST 接受一个现有节点、目标父节点和可选同级锚点。`parentId: null` 定义根组，根节点 MUST 只在根组内重排，非根节点 MUST 以现有节点为目标父节点。锚点 MUST 属于目标同级组，无锚点时 MUST 追加到该组末尾。发布结果 MUST 保持 v1 的至少一个根、各同级组顺序从 0 连续、父子无环及依赖端点有效且无环。移动 MUST 保留已有节点 ID、子树内部结构、目标、完成条件、状态、显式依赖、公开记录及本机聊天关联。

#### Scenario: 移动有后代、成果和聊天的子树

- **WHEN** 用户把已有聊天、记录与跨分支依赖的子树从一个阶段移到另一个阶段的指定兄弟节点之前，再移动至另一个根分支中的空阶段下
- **THEN** 整棵子树出现在新位置，原与目标同级顺序连续，节点 ID、后代顺序、依赖端点和公开记录保持原值，原聊天仍归属相同节点，已记录验证及节点状态原样保留

#### Scenario: 拒绝无效的根、父节点或位置

- **WHEN** 请求把根降为子节点、把非根升为根、把节点放在自身或任一后代下、锚定自身、引用缺失节点，或为根组、普通子节点组指定属于其他组的锚点
- **THEN** Host 返回对应原因，公开文件、规划修订和聊天关联保持原值，有效目标位置仍可重新选择

### Requirement: 内置流程作为完整子树实例化

插件 MUST 提供至少一个可预览且有明确版本的开发流程预设，展示其来源、准确版本、层级、完成条件和内部依赖。经 owner 与实例核对的树入口 MUST 提供当前随包预设及其可用正文语言。Host MUST 精确匹配请求中的预设 ID、版本和可用正文语言，并验证目标为现有父节点。Host MUST 为模板中的每个节点分配新项目节点 ID，一次发布全部节点和内部依赖，保留旧节点及旧依赖。新节点 MUST 从 `todo` 开始，新节点和依赖沿用普通节点形状。v1 资料 MUST 保持 v1，v2 资料 MUST 保留已有路线图字段和引用。无效预设、语言或位置 MUST 给出原因。

#### Scenario: 插入预设并独立再次插入

- **WHEN** 用户预览一个有内部依赖的预设，插到现有同级节点之前，再以新操作在一个空父节点下插入相同版本。分别使用 v1 和已设置路线图的 v2 资料
- **THEN** 两次均得到完整子树，位置和内容符合预览，所有新 ID 唯一，两批内部依赖分别指向各自的新节点，既有节点及依赖保留，新节点无聊天、结论、历史成果或授权，旧 v1 读者可读取 v1 结果，v2 结果中的原里程碑和交付引用保持

#### Scenario: 拒绝不可用或无效的模板输入

- **WHEN** 请求未知预设、已不可用版本、不支持的正文语言、无效目标位置，或包内预设存在重复键、无效父级、缺失依赖端点或成环
- **THEN** Host 解释拒绝原因，公开头、记录与规划修订保持原值。其他有效树操作仍按既有准入可使用

### Requirement: 结构操作遵循实例和执行边界

Host MUST 以可信 owner 身份及本机登记核对保护树入口。Agent 的移动与插入 MUST 遵循明确动作、实际节点及位置范围、活动绑定与基线规则，越范围请求 MUST 拒绝。浏览、预览及 owner 结构提交 MUST 保持已启动 WorkRun 的目标、范围和运行状态。对实际推进规划基线的结构操作，面板 MUST 提示后续规划写入须在原运行结束后从当前规划显式发起新运行。

#### Scenario: 多实例和可信身份校验

- **WHEN** owner 通过项目概览在可写的已登记实例 B 操作，另提交实例不匹配、未登记、不可读或非 owner 的请求，并让可信 Agent 在缺少相应动作或位置授权时提交结构命令
- **THEN** 有效写入只出现在 B，其余请求返回原因。旧入口、原有 Agent 工具准入与现有实例隔离仍可用

#### Scenario: 工作运行中修改同实例的树

- **WHEN** 实例存在活动 WorkRun，owner 先做原位预览，再实际移动其目标的祖先或插入预设。Agent 使用原基线写入，再读取最新规划并尝试在同一运行中写入。随后旧运行确认结束，用户从当前规划显式发起新工作
- **THEN** 原位预览后基线保持，实际变更后原运行继续执行并可读取，目标、允许动作及历史保留，新节点未纳入其范围，两次当前运行的写请求均被拒绝。新运行以当前规划建立可信绑定，可在获准范围内写入

### Requirement: 提交、冲突与回执遵循既有规划协议

结构操作 MUST 捕获实例、项目、源代际和规划基线，经同一实例的持久意图、发布、回执和完整快照回读流程完成。实际成功的结构变更 MUST 推进一次规划修订。结构操作与既有节点规划编辑的普通已保存状态 MUST 基于已确认回执及同源有效回读。已确认提交但快照无法核对时，面板 MUST 显示「已提交，待同步」并提供读取重试。换源后的回执 MUST 保留为历史，当前树以当前源有效快照为准。遇到基线冲突 MUST 保留请求草稿并提示在新快照上确认；遇到未知结果 MUST 使用原请求和 `operationId` 核对，保留既有隔离及恢复行为。可选变更原因 MUST 在结构变更确认且完成同源回读后单独保存，移动以移动节点为记录主体，插入以目标父节点为主体。原因保存状态 MUST 与结构变更结果可辨。

#### Scenario: 用户确认前已发生其他规划或源变化

- **WHEN** 在结构预览建立后，另一有效写入调整了规划、外部顺序编辑改变了内容指纹，或实例切换了源代际
- **THEN** 旧请求按原基线被拒绝，草稿保留并标注冲突，最新树可打开核对；用户在新位置重新确认后使用新的操作号

#### Scenario: 确认后断线并重试模板插入

- **WHEN** 模板已发布但回执响应丢失，Client 重连后核对或重发原请求；另用相同操作号修改位置或版本。分别验证结构提交及既有节点编辑的回执已确认但完整回读失败，以及结构变更已同步但可选原因保存失败
- **THEN** 原插入只生成一套节点 ID，规划修订只推进一次，改动参数的同号请求被拒绝。回读失败时提示「已提交，待同步」，读取重试成功后才显示普通已保存。原因失败单独提示，重试原因时保留原结构提交回执

#### Scenario: 发布途中中断或旧响应迟到

- **WHEN** 在已持久化候选时中断发布并重启，或已切到 B 时 A 的回执和快照迟到
- **THEN** 候选按既有恢复规则核对，完整发布后显示结果，无法确认时保留待核对状态；A 的响应仅作用于 A 的原请求，B 的可见树与草稿只由 B 的有效回读更新

#### Scenario: 更新后重启并读取已有接续资料

- **WHEN** 在已有接续记录的 v1 项目上完成结构变更，关闭和重开插件后读取项目树、原聊天及接续卡片
- **THEN** 可回读新结构及既有记录，聊天仍解析到原会话，接续卡片保留记录中的历史验证状态，并继续显示当前代码观察结果或可见的未核对原因

### Requirement: 界面语言与模板正文独立

结构控件、预览、错误、状态和无障碍标签 MUST 支持简体中文与英文，其他宿主语言的控件及新预设预览 MUST 回退英文。预设正文 MUST 使用创建草稿时选定的可用语言实例化，语言切换 MUST 保留原有节点正文、待提交请求和已保存正文。

#### Scenario: 编辑期间切换宿主语言

- **WHEN** 用户在中文下打开预设预览，切换到英文和第三种语言，保持原草稿并完成保存后，在第三种宿主语言下新开一个预设预览
- **THEN** 固定文案切换并按需回退英文，原草稿显示并保存选定的中文正文，原项目内容原样保留，新预览使用英文正文

### Requirement: 手工编辑与批量结构变换

owner MUST 能编辑节点的目标和完成条件，预览同父级普通节点的分组及合并、为现有节点拆出子项、复制子树。预览 MUST 明确目标位置、身份、依赖、引用和受影响范围。变换 MUST 复用合法树校验、基线、持久意图及回执，在同一规划提交中整体接受或拒绝。对含规划和衍生记录的动作 MUST 通过一次权威头发布两者，重试 MUST 使用原回执和原生成身份。结构化替代正文 MUST 有公开的版本说明、schema、样例和独立校验入口。

#### Scenario: 编辑条件并分组拆分

- **WHEN** owner 修改完成条件，将同父级节点分组，并对其中一个已有节点拆出多个子项
- **THEN** 完成条件可保存和回读，所选节点及关系保留，分组保持相对次序，拆分保留原节点并生成有序新 ID，非法同级位置或依赖整批拒绝

#### Scenario: 合并保留来源和替代关系

- **WHEN** owner 合并多个有效同级节点，明确保留节点、后代位置及外部依赖的处理
- **THEN** 后代和获准的有效依赖按预览转移，原节点以原 ID 保留为已取消与被替代，聊天及成果仍能按来源查阅，新发布的结构化替代记录可用原 ID 定位保留节点，路线图保留原引用并提示待核对。成环或源变化时不发布局部结果

#### Scenario: 复制只有模板化的规划内容

- **WHEN** owner 复制已有完成状态、外部依赖、聊天和验证的子树，另在回执丢失后用原操作号重试
- **THEN** 新子树使用唯一 ID、`todo` 状态与重映射的内部依赖，外部依赖按确认结果处理，原聊天、成果、历史及权限原样保留，重试只产生一棵副本

### Requirement: 经核对的规划撤销和重做

系统 MUST 能为同源且已有逆向信息的 owner 内容、树结构、模板插入及里程碑关联编辑提供可预览的撤销与重做。原回执及公开历史 MUST 保留，缺少逆向信息的旧操作 MUST 显示原因。撤销／重做 MUST 以新操作核对受影响字段和当前关系。涉及后续更改、在用引用、活动工作或换源时 MUST 解释冲突并保留草稿与当前内容。

#### Scenario: 保留无关编辑的撤销和重做

- **WHEN** owner 提交一次规划编辑，重启后另一合法编辑改变无关字段，随后 owner 选择撤销并重做原编辑
- **THEN** 只处理原操作影响范围，无关编辑保留，每次成功产生单次新修订和对应回执，原操作及历史仍可查

#### Scenario: 后续修改或引用使逆向不安全

- **WHEN** 选定操作的字段已被修改、其新节点已有记录／聊天／依赖，或源代际已经切换
- **THEN** 系统在提交前显示冲突对象，保留现场。重试和重启不会绕过当前基线或重复应用逆向变换

### Requirement: 用户流程模板的保存和实例化

owner MUST 能预览并保存所选子树的可复用模板，按不可变版本列出项目内模板，基于同实例已发布版本预览和插入到现有父节点之下。对 `parentId: null` 或不存在的父节点 MUST 返回 `parent-not-found`。模板 MUST 仅保存显式确认的标题、目标、完成条件、层级及内部依赖。Host MUST 校验模板描述、版本、内容与位置。每次实例化 MUST 生成新 ID 与独立内部依赖，复用候选和回执恢复。用户模板 MUST 按模板 ID、版本记录 ID 和内容哈希精确读取，以作者保存的单语言正文实例化。模板列表与预览 MUST 支持简体中文、英文和英文回退。

#### Scenario: 保存用户模板并从另一副本复用

- **WHEN** owner 预览并保存子树为模板，再保存另一版本，从独立副本读取所选旧版本并在两个位置插入，期间切换宿主语言
- **THEN** 模板版本可区分，原文和规划指纹保持，内外依赖边界可见，插入只使用所选版本，两批 ID、位置和初始状态正确，私有数据没有进入模板

#### Scenario: 模板版本变化、无效正文或重试

- **WHEN** 在预览后目标处发生外部变更、所选模板版本失效或正文校验失败，另模拟成功发布后回执迟到
- **THEN** 失败有具体原因且不提交子树，仍可显式选有效版本和位置。成功操作原样重试仅回读一批已生成节点

### Requirement: 新规划命令的原子发布及回执

批量树操作、用户模板插入、里程碑、格式启用及逆向编辑 MUST 经过统一命令服务。请求摘要 MUST 覆盖业务载荷和基线，衍生正文及生成 ID MUST 在发布前冻结。版本只按实际业务变化推进，失败 MUST 保持最后有效头。同号同请求 MUST 返回原回执，同号更参 MUST 拒绝。

#### Scenario: 原子候选与原操作回执

- **WHEN** 提交含结构化记录的批量规划动作，分别注入非法子步骤、头发布前中断、发布后回执丢失、同号更参以及原位无变化
- **THEN** 非法操作与中断不暴露部分规划或记录。成功规划只推进一次规划修订，候选 ID 和关联正文可从原回执核对。无变化保持头、指纹和规划修订

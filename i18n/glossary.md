# 术语表

| 术语 | 含义 |
|---|---|
| DSH | DeepSeek Harness，插件宿主 |
| 项目树 | 以归属关系组织项目、阶段和具体工作的层次结构，可随新信息调整 |
| 可移植项目资料 | 不依赖 DSH 运行时即可读取的版本化项目文件；位置可选项目／DSH／自定义目录，包含规划与选定发布的记录 |
| 本机资料实例 | 同一项目在当前机器某个资料源／工作副本中的独立绑定，用于隔离聊天、执行、回执和同步状态；不代替跨机器稳定项目 id |
| 规划指纹 | 按公开规范化规则计算的规划内容标识，用于跨环境核对基线；本机自增修订号不作为团队全局版本 |
| 路线图 | 与项目树共用规划，通过目标与时间视角呈现里程碑、交付、依赖和进展，具体界面与排期能力待细化 |
| 界面语言 | UI 固定文案的展示语言；首版简体中文与英文完整支持，其他宿主语言回退英文，不直接决定项目内容或 Agent 回答语言 |
| locale | DSH 的语言选择、字典注册与翻译服务所用标识；中文基础 id 为 `zh`，英文为 `en`，日期显示还需区分时区与日历值 |
| 流程块 | 可插入、移动或复用的一段阶段子树；展示顺序与执行依赖分别管理，具体交互待验证 |
| 节点／阶段 | 项目树中的工作单元，可继续拆分，并关联目标、材料、成果和聊天；具体字段待设计 |
| 流程模板 | 可复用的节点层次、目标、输入与成果要求，不等同于 DSH 的一次 Workflow 执行 |
| 骨架模板 | 可在项目创建或后续阶段应用的目录、初始文件与参数 |
| 项目预设 | 流程模板与骨架模板的场景组合，具体形式仍是设计建议 |
| 聊天关联 | 节点与 DSH 会话的多对多联系，不自动表示持续同步或执行授权 |
| 成果 | 工作产生的文件、内容或结论；具体记录与完成判定规则待讨论 |
| 项目分析 | 在专门的 DSH 聊天中结合目标、代码、文档和验证记录形成现状、缺口与调整建议；可用于首次接入和开发途中 |
| Host 项目服务 | 运行在 DSH 宿主进程中的插件业务逻辑，供内部 UI 和 Agent 工具共同调用，不是用户另行部署的后端 |
| 项目面板 | 集成在 DSH 界面内的项目入口及概览、树和详情视图，关联 DSH 原有聊天 |
| SDD | Specification-Driven Development，以规范、实现任务和验证证据推进开发的工程方法；在本项目中按变更影响选择是否采用 |
| spec | 对功能行为、约束和可验收场景的规范；可以关联一个或多个项目节点 |
| change | 一次有边界的工程变更及其设计、规范、任务和验证记录；OpenSpec 是首个候选适配器 |
| SDD 提醒 | 用户可通过开关启用或关闭的开发提示；启用时按变更影响提示检查或建立规范，简单任务可跳过；关闭后不主动催促，不影响用户主动使用 SDD |
| Super-agent | 官方研究原型及未来协调能力的参考称呼，不代表已发布稳定的 DSH 集成协议 |
| 检查点（历史文件恢复语境） | 可恢复的文件版本快照；不同于 DSH 会话持久化检查点 |
| 交付（历史文件恢复语境） | 把受管理工作副本的改动受控写入原项目，不据此限定项目管理中的成果提交方式 |
| 回退（历史文件恢复语境） | 依据已保存版本恢复文件，不覆盖后续人工改动 |
| F01–F08 | Cona 的文件版本／交付／回退用例组，仅作专题参考，不是当前首版范围 |

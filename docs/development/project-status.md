## 已知的路线级事实（会影响结论）

1. **受控出口采用“窄通道优先”**：宿主侧命名管道 broker（管道 DACL 按容器身份 SID 授予）以“客户端令牌容器 SID 匹配 + 别名白名单 + taskId 绑定”提供访问，**不授予任何网络能力**；模型资料发送测试网关亦经该通道。
2. **依赖安装的出网受限**：经宿主 loopback 策略代理不可行（loopback 不可达 + 异步 fs EPERM），依赖安装工作流在安全边界内未完成——这是当前判定为“调整”而非“采用”的直接原因。
3. **Git 走容器外可信服务**：容器内 Git 无法解析自身工作目录，已确认降级路线——宿主侧代执行、经窄通道别名提交；**Git 不在隔离进程内运行**（降级边界如实记录）。
4. **一次性提权不可回避**（卷根读属性／遍历 + 运行时只读授权），但日常运行不需要提权。
5. **产品默认可做到不主动碰 C 盘**，唯一例外是 Windows 自建的容器身份档案目录（运行结束时由驱动回收）。
6. **性能实现注意**：祖先目录“仅遍历”ACE 的授予开销随被遍历子树规模增长，正式实现应改为按 run 一次性供给。
